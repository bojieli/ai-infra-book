# 第 3 章 推理与训练负载

> 写作大纲 · 持续负载、任务依赖与训练预算 · 2026-09-09

第一章建立资源估算方法，第二章从模型结构给出一次执行与完整生成的需求。本章把执行放入时间和完整任务：同一模型被多少请求使用、多久重用一次状态、哪里产生新数据、哪些阶段必须等待。先建立负载的共同描述，再从多轮交互走向多模态与实时任务，随后补上训练与 RL，最后将任务目标转成训练和长期服务预算。

**本章判断：** 模型结构给出单次执行的需求；任务的阶段组成、到达与依赖关系，以及状态寿命，决定这些需求如何在时间上叠加。比较系统方案时，还必须保持任务质量和完成目标一致。

到达率和平均长度不足以决定配置；复用间隔、阶段关联和尾部会同时改变搬移、驻留与排队。训练预算还需结合长期服务成本。负载给出需求，实际排队与驻留还取决于服务能力和执行策略。

**前置与交付：** 依赖第 2 章的模型需求表。交付 Chat、Agent、视觉 E→P→D 与训练／RL 的阶段图和固定输入，保留到达、长度相关性、状态复用间隔、质量与完成目标，供第 4–12 章独立使用。

**阅读安排：** 3.1 建立共同口径，3.2–3.3 加入任务依赖、媒体与时限，3.4–3.5 分析训练及 RL，3.6 汇总预算。核心练习为实验 3-2、实验 3-4、实验 3-7；实验 3-7 先使用 3.4 的训练状态表。Scaling Law 的完整拟合及其余练习为延伸，正文保留预算判断。全部十项实验、九项配图及原始证据保留；完整参数、实现版本与实验变体见[扩写资料](extensions/03-%E6%8E%A8%E7%90%86%E4%B8%8E%E8%AE%AD%E7%BB%83%E8%B4%9F%E8%BD%BD.md)。章末更新[跨章设计决定](decision-record.md)。

## 3.1 从一次执行到持续负载

先定义一次请求及阶段依赖，再改变请求组成和时间关联。使用第二章已经算清的模型需求，在固定服务条件下观察工作如何叠加；这里建立后续所有任务共同使用的描述与指标。

### 3.1.1 Prefill 与 Decode

直接使用第 2 章 Qwen3-8B 与 V4-Flash 的模型需求表，把一次请求放入时间线：输入阶段产生首输出，后续逐步生成，状态随已处理位置增长。前缀命中减少新输入工作，既有状态仍可能被读取；本章开始关心这些工作何时到来、持续多久。

对比单 token decode 与批量输入的矩阵形状。低并发下，一次读取权重只服务少量 token；增加 batch 可以摊薄权重读取，随后 KV、容量、专家分布与等待又可能成为限制。prefill 常偏计算密集、decode 常偏带宽密集，是可由形状检验的起点。

> **实验 3-1 ★〔延伸〕：Prefill 与 Decode 的资源变化**
>
> 使用第 2 章已有的长度、batch 与前缀命中需求表，比较输入较多和生成较多的两个时段，分别汇总各阶段的工作与状态。保持总 token 数时，检查阶段组成是否仍会改变资源需求；不再重复逐层矩阵推导，也不提前把峰值下界写成真实服务时间。
>
> 条件：基础·手算／短脚本。

**计算结果（3-1）：** 每请求总 token 数相同（4,224），只改变阶段组成：输入较多的时段与生成较多的时段矩阵工作只差 7%（512.8 对 548.5 TFLOPs，batch=8），权重读取却相差 29 倍（1,804 对 52,329 GiB）——decode 每步都要重读整份权重，读的次数等于输出长度。batch 从 8 到 32，prefill 工作线性涨 4 倍，decode 权重读取完全不变。命中 3,072 前缀把 prefill 降 73%，decode 三项一个字节不变。[逐场景表与限制](../experiments/ch03/03-01/README.md)。

### 3.1.2 任务目标与评价指标

说明客户端 TTFT、输出间隔与设备计算时间的边界：输入准备、传入、调度、回传和发送都可能影响用户等待。3.4 补训练输入准备与传输，以及取回 loss 可能产生的等待；本章只交代负载需求，stream 与同步在第 5 章讲。

区分一次模型请求和一个完整任务：任务可以包含多次生成、工具调用、验证与重试。先声明什么算完成、什么质量才合格，再统计输入、内部生成、用户可见输出及失败尝试。

每份负载记录使用共同字段：任务与质量目标；模型和输入输出单位；各阶段的调用次数、计算与数据量；到达时间及前后依赖；状态的产生、更新、复用和回收时刻。容量、逻辑访问、实际物理读写分别记录，缺少的字段与服务假设单列。

定义首 token 时间（TTFT）、后续 token 间隔与平均每输出 token 时间（TPOT）、完整请求延迟和完整任务时间；reasoning 另区分首个内部 token 与首个对用户有用的输出。p95 标明统计对象、计时边界与分位数算法。有效吞吐只计满足所声明质量和时限的产出，成功任务成本计入失败与重试；实时首播等指标在 3.3 补上。

### 3.1.3 请求分布

从单轮问答进入多轮 Chat，比较输入、输出、重复前缀与到达突发。本节负责统计请求分布，再代入第 2 章的资源公式，观察平均长度相同而尾部不同的两组请求如何产生不同的 KV 峰值与等待。沿用[已封存的 Chat／Agent 记录](../experiments/ch02/02-08/README.md)，无需为章节分工重新采集；第 2 章只使用其中给定的长度字段。

在相同到达率和平均长度之外，保留长短请求的尾部、输入输出长度的配对、客户组成与时段变化。请求到达率、同时未完成的请求数和实际执行 batch 分别记录；工具返回后的下一次调用受前一轮完成影响，不能全部视作独立外部到达。

> **实验 3-2 ★〔核心〕：相同均值下的不同请求分布**
>
> 先手算两组平均输入与输出长度相近的请求，再重放到达和完成过程；比较 KV 峰值、等待和 p95，识别平均值遗漏的约束。
>
> 条件：基础·手算后重放。

**实测结果（3-2）：** 两组 480 请求的输入与输出长度逐条相同，只改到达位置。完整请求 p95 几乎一样（299.4 对 299.4 s），TTFT p95 却是 242.9 对 258.9 s，抢占事件 62 对 24；时段组前段长输入集中时只有约 30 条在跑，后段升到 64。两组 KV 池采样峰值都到 100%，第 120 秒仍有 359／349 个请求未完成。平均值相同不代表约束相同。[回放记录、时间线与限制](../experiments/ch03/03-02/README.md)。

**实测（部分）：** [两分钟同总量回放](../experiments/ch03/03-02/README.md)完成960个请求：均匀与时段变化组的完整请求p95都约299.4秒，但TTFT p95约242.9/258.9秒，抢占62/24次。相同均值与近似排空时间没有抹平等待和状态压力的差异。 [ServeGen窗口回放](../experiments/ch03/03-02/servegen-replay/README.md)另完成960请求：原始／配对置换的p95为0.786／0.801秒，均无抢占；该轻负载结果不推广为重负载结论。 [四客户多轮对照](../experiments/ch03/03-02/multiturn-cache/README.md)输入输出相同，开启缓存后轮转与客户内连续访问的命中比例为0.40%／66.32%，说明访问顺序还会改变前缀复用。 [相同多轮负载并发](../experiments/ch03/03-02/multiturn-concurrency/README.md)后，答案保持一致，KV池采样峰从51.27%升到100%，出现等待与抢占。

重放比较固定模型、服务能力、准入、执行与状态释放策略，再只改变一项分布或时间关联。使用教学服务时长时明确其来源；真实系统记录保留原配置。长度决定单次需求，等待和 KV 峰值由负载与这些服务条件共同产生。批处理、抢占与缓存策略的机制在第 8 章展开。

## 3.2 多轮交互与 Agent 任务

从单轮请求扩展到完整任务，依次加入历史累积、思考与验证、工具依赖和分支。Chat、reasoning 与 Agent 可以出现在同一任务中，各自改变不同的负载字段。

### 3.2.1 多轮 Chat 与前缀增长

沿 3.1 的同一份 Chat 记录逐轮展开：上一轮输入与输出成为下一轮历史，新增消息触发新的输入工作。记录重复前缀、可复用状态、轮间间隔和上下文策略；可复用长度不等于实际缓存命中，后者依赖缓存是否仍在及其恢复条件。

将每轮长度代入第 2 章公式，累计完整任务的工作和状态需求。3.1 比较请求群体的分布，本节保留同一会话内部的关联，第 8 章再选择怎样保存与复用。

### 3.2.2 Reasoning、验证与成功任务成本

沿相同任务分别统计 token 数、思考长度、正确结果与失败尝试。token 单价降低时，若调用或重试增加，成功任务成本仍需重新计算。 依据：[成本下降调研](../research/token-cost-2023-2026/report.md#economics)。

> **实验 3-3 ★★〔延伸〕：Reasoning 预算与正确结果成本**
>
> 用可验证题集或固定公开记录，比较串行、并行与按难度分配；计入验证、状态和最终输出，在相同质量要求下求代价。
>
> 条件：进阶·模型／数据分析。

**实测结果（3-3）：** 前两次实跑（输出上限 1,024／4,096）三策略均 0/8，全部在思考未结束时被截断，无法比较代价。换成八道可完成的子集计数题并把上限提到 8,192 后，48 组实跑给出可比结果：串行 12/16、并行 13/16、按规模分配 12/16，质量差异只有一道题，不构成排序。代价差别明确——并行省时间不省 token（生成更多 token 却只用串行 55% 的时间），按规模分配省 token 不省时间（请求数 −25%，每正确结果 11,253 token 最低）。难度悬崖同样清楚：4–6 元素题 36/36 全对，7 元素题只有 1/12，且 11 次失败全部是没在预算内结束思考而非答错——悬崖之外三种策略表现完全一致。[三策略实跑、难度分层与限制](../experiments/ch03/03-03/solvable-set/README.md)。

**部分实测：** [四题、44个真实候选](../experiments/ch03/03-03/README.md)在1024总输出上限下全部截断，没有最终答案。串行、并行与按题目规模分配的耗时不同，但都未达到质量门槛，不能据此比较正确结果成本。 [4096上限补测](../experiments/ch03/03-03/wide-budget/README.md)的44个候选仍全部未结束思考，增加预算未取得正确最终结果。 [关闭thinking诊断](../experiments/ch03/03-03/no-thinking/README.md)的44个候选全部自然结束，但严格JSON接口检查仍全部失败；独立后验提取后，三策略仅1/8、2/8、1/8题数值正确，不能替换主评分。运行中另一个GPU服务启动，所存耗时也不具备独占条件。

### 3.2.3 Agentic：模型、工具与检索的循环

沿代码 Agent 的一条具体轨迹，连接生成、工具执行、结果回传和下一次 prefill。每轮输入中有旧前缀、先前 reasoning 或回答、以及新增工具结果；不同上下文策略会改变可复用部分，不能用对话轮数直接代替计算量。

文档问答沿[检索与生成算例](../case-studies/retrieval-and-generation.md)补一种上游负载变化：检索策略会改变满足回答质量所需的文档数，从而改变后续输入、prefill 与 KV。此处只定义检索输出怎样成为模型负载；同质量候选的实测放在 8.5.1。

### 3.2.4 分支、工具等待与状态驻留

比较串行调用、并行工具与多候选探索。工具等待未必消耗 GPU 核时，却可能占住 KV；分支共享前缀并分别增长尾部。计算活跃生成、等待恢复和可换出状态，为内存池与缓存路由建立负载依据。

> **实验 3-4 ★〔核心〕：Agent 的模型、工具与状态**
>
> 从完整轨迹统计每轮命中 token、新输入、reasoning 输出和工具等待；计算关键路径与 KV 驻留，再替换一段模型时间，寻找真正值得优化的环节。
>
> 条件：基础·轨迹分析。

**实测结果（3-4）：** 12 轮真实代码 Agent 轨迹：累计输入 19,556 token，其中引擎报告命中 16,304（83.4%），累计输出 765；模型墙钟合计 13.156 s，工具 0.476 s，整段 13.803 s。关键路径几乎全在模型侧，但高命中并没有纠正代码错误——12 轮预算内任务失败。开启 thinking 的对照轨迹另存。真正值得优化的不是这条轨迹的工具等待。[逐轮记录、缓存与限制](../experiments/ch03/03-04/README.md)。

实测：同一Qwen3-8B代码任务，关闭thinking时12轮仍未修复；开启后4轮通过返回值与输入不变检查，模型调用时间由13.16增至76.29秒。首轮截断及额外别名检查发现的问题均保留，不能只看速度或缓存命中判断任务收益。[两条完整轨迹与验证](../experiments/ch03/03-04/README.md)。

## 3.3 多模态与实时交互

先数清非文本任务的执行阶段、数据和状态，再加入持续供给与截止时间。多模态描述工作的组成，实时性描述时间约束；两者可以与 3.2 的 Agent 循环组合。视觉与工具负载在这里提供最小完整输入，后文分别研究其执行与位置。

### 3.3.1 视觉 E→P→D 与 EC／KV

以语音、持续视频感知和截图请求定义非文本输入的阶段。图像编码记为 E，语言 prefill 为 P，decode 为 D；E 产生的编码结果 EC 与 P／D 产生的 KV 在身份、位置依赖和可复用范围上分别记录。编码、传输和生成的顺序由实际模型决定，后文单实例调度和 EPD 直接使用这里的定义。

视觉贯穿变体固定 Qwen3-VL-4B：预处理后 640×640 图片形成 400 个视觉位置，含 DeepStack 的完整 BF16 EC 为 7.8125 MiB，对应逻辑语言 KV 另为 56.25 MiB。用实际张量计数核对；原始截图采用 0.8 MB 教学输入，文件字节、编码特征和语言状态不能互相替代。来源与格式见[阶段放置笔记](../case-studies/multimodal-stage-placement.md)。第 8 章研究同卡调度，第 9 章研究数据中心内交接，第 12 章才加入端侧链路。

### 3.3.2 音频与图像生成的工作单位

生成任务再补两个工作单位的反例：音频模型一帧内部可能有多次码本预测；图像的 50 个去噪步在采用双分支 guidance 的具体路径下可能执行 100 次 DiT 前向。按实际循环计数，不能直接用文本 tokens/s 比较。正文各选一条路径，其他模型与完整算子数留在[生成模型资料](../case-studies/generative-multimodal-models.md)；执行位置和传输优化仍归第 12 章。

### 3.3.3 连续感知、首段响应与打断

加入作者 AOI 论文的短例：动作之间的瞬时弹窗可能被周期截图漏掉，观测与动作应分别调度。沿采集、筛选、持久文字与模型消费记录速率、字节和状态寿命，并保留额外图像挤占上下文导致效果退化的反例。论文入口与取材范围见[作者材料](../case-studies/author-context-and-design.md)。

语音沿采集、编码／识别、推理、语音生成与播放画依赖，分别统计首段可用时间、持续供给、打断与过期工作。RAW 精修以完整成片为截止，与连续媒体分开。第 12 章复用这些任务定义，不承担前面章节的知识前置。

> **实验 3-5 ★〔延伸〕：实时语音的响应预算**
>
> 对固定语音记录计算首次播放、块间抖动和打断响应；分别改变模型、网络与缓冲，判断哪项能改善对话。
>
> 条件：基础·时序分析。

**计算结果（3-5）：** 对话质量由三个不同的量决定，改善手段各不相同。缓冲 0→40→100 ms 使首次播放 38→78→138 ms，一比一地记在延迟上；抖动场景下加大缓冲把欠载从 1 次降到 0 次。模型从 12 ms 加速到 6 ms 只把首次播放缩短 6 ms，变慢到 25 ms 却推到 91 ms——慢会伤、快不怎么帮。打断到静音固定 10 ms，由控制通路与设备量子决定，与缓冲无关。[时序表与限制](../experiments/ch03/03-05/README.md)。

**记录分析（部分）：** [两份历史语音记录](../experiments/ch03/03-05/historical-arrivals/README.md)的首块接收延迟约400／370 ms；缺设备播放与取消链证据，不能当作首播或打断响应，也不能比较模型、网络和缓冲的收益。

## 3.4 训练的计算与状态需求

从一次更新需要什么数据出发，在第 2 章前向执行上补齐反向与更新，再比较训练阶段怎样改变工作。先建立需求，具体状态分片、重计算和执行组织在第 10 章选择。

### 3.4.1 前向、反向与更新状态

在第 2 章单层矩阵上补上反向传播，数梯度、激活与优化器状态，解释训练为何比推理需要更多计算和存储。`6ND` 放在这里作为稠密参数矩阵训练的粗估，随后加入长上下文注意力、MoE 激活、重计算、输出头与精度的影响；它不决定最佳模型大小或训练数据量。

沿前向、损失、反向和参数更新标出依赖：激活为反向保存，梯度在反向产生，优化器状态跨更新保留。单次微批的工作与一次参数更新的累计工作分别声明，数据 token 数、有效训练位置和损失掩码不能混用。

### 3.4.2 预训练、中期训练与 SFT

预训练与中期训练通常延续相同的自回归学习与梯度更新过程，区别主要来自数据质量与混合、上下文长度、训练进度和能力目标。“Mid-train” 的阶段划分随团队而异，按具体报告解释；用 Qwen3 的通用、推理数据强化与长上下文阶段，以及 V4 的预训练说明数据变化怎样改变计算形状。

SFT 沿用前向、损失和梯度更新的基本路径，按具体配方记录样本组织、序列长度、损失位置和训练参数范围。只在回答位置计损失不代表其余上下文不参与前向；全参数训练与部分参数训练的状态需求也应分别声明。

### 3.4.3 从 6ND 到分项训练预算

正文走通 Qwen3-8B 的一组例子：在 8K 输入、batch 为 1 的声明口径下，前向与两个梯度的矩阵工作约为 431.37 TFLOPs，而按全部参数套用 6ND 约为 402.59 TFLOPs。沿[分项计算](../calculations/results/training-qwen3-8b-t8192.md)找出序列交互与矩阵使用方式的差别，再说明它仍未包含非矩阵反向、优化器和重计算，不能当作完整训练投入。

V4 的压缩器、状态更新、mHC 和优化器用于说明新结构会增加哪些工作；正文只解释会改变预算的差别。各子图的前反向公式、保存对象和验证范围放在本节扩写资料，不能把部分账重复相加或当作整模型训练已经复现。第 10 章再用这些需求选择状态分片与执行方式。

> **实验 3-6 ★〔延伸〕：各训练阶段的工作量**
>
> 对固定 dense 和 V4-Flash 配置，从前向、反向与状态计数开始，比较预训练、长上下文中期训练与 SFT；逐项指出 6ND 漏掉的工作，并给出影响预算的范围。
>
> 条件：基础·手算／短脚本。

**计算结果（3-6）：** 4K 预训练上 6ND 几乎正确（矩阵/6ND = 0.998），32K 长上下文中期训练上低估 51%（比值 1.514）——差额全部来自注意力（950 of 2,438 TFLOPs），而 6ND 里没有这一项。SFT 只有输出头能省（比值 0.941），主干前反向与预训练相同。6ND 之外还漏掉优化器标量工作 114.7 GFLOPs（是前反向标量的 69 倍）与 137.3 GiB 未切分参数状态。[三阶段对照与 V4 子账](../experiments/ch03/03-06/README.md)。

## 3.5 RL：生成、反馈与更新

将前面的推理、Agent 和训练连成闭环：当前策略产生候选，反馈决定哪些样本进入学习，更新后的权重用于再次生成。先统一同一批有效样本的需求，再交给第 10 章组织学习与交接。

### 3.5.1 Rollout、奖励与环境验证

从刚讲过的推理和 Agent 轨迹出发，解释训练数据如何由当前策略生成，再由规则、模型或实际环境验证。DeepSeek-R1 用于交代 RL 训练路线，DeepSeek-V4 用作系统主例；一次训练迭代需要的不只是生成 token，还可能需要代码执行、工具环境和多个模型前向。

### 3.5.2 有效样本、策略更新与权重交接

把样本筛选与组织、策略更新、新权重同步接到 rollout 之后。计算生成、奖励／验证、反向更新、参数与状态传输的阶段时间；只有阶段需求统一为同一批有效样本，才能判断资源应给采样还是学习。具体并行、共置和调度机制留到第 10 章。

用[八个 prompt、每题四候选的教学批次](../calculations/results/rl-qwen8-base.md)数清各阶段实际处理多少样本：生成 32 条、最终接受 16 条，拒收的候选仍然消耗生成和评分工作。先改变接受比例，计算维持同一有效样本目标需要增加多少工作；第 10.5 节再加入真实阶段能力和权重依赖，决定如何配资源。这份 Qwen 计算不作为 V4 的实际部署证据。

### 3.5.3 同一有效样本目标下的阶段需求

> **实验 3-7 ★〔核心〕：RL 循环的资源供给**
>
> 按 V4 的阶段组织构造明确标注的教学输入，计算 rollout、验证、教师前向、更新和权重交接的工作与数据量；改变样本接受比例，比较同一有效样本目标下各阶段增加的需求。把这张需求表交给第 10 章，再讨论资源池配比。
>
> 条件：基础·手算／短脚本。

**计算结果（3-7）：** 固定 16 个有效样本的目标下，接受比例从 1/2 降到 1/8，有效样本产出降到 1/4（1.823→0.456 样本/秒）——被拒绝的候选照样跑完 rollout 与打分，只有更新阶段不随候选数增长。受限池也随接受率转移：低接受率时在 actor，全部接受时转到 learner。actor 池加速 2 倍后流水间隔从 8.78 降到 4.76 s，瓶颈随即转到 learner，继续加 actor 不再有收益。[阶段需求表与限制](../experiments/ch03/03-07/README.md)。

>
> 按 V4 报告自绘生成、验证、教师、学习与状态传输图；实验 3-7 提供教学数值，图注明确非本书实测。

## 3.6 从负载需求到训练与服务预算

前面各节已经给出工作与依赖，本节进一步问在质量、完成期限、模型寿命和预期调用量下应投入多少。历史投入用于说明预算选择，完整型号统计留在延伸材料。

### 3.6.1 Scaling Law：拟合、验证与适用范围

明确 scaling law 的对象是固定数据与训练条件下的统计关系。由多组模型规模 N、数据量 D、计算预算 C 和验证损失拟合关系，保留未参与拟合的实验检验预测；Llama 3 的预算到损失、再到任务表现的两步方法作为历史实例。

将更长训练和蒸馏视为用前期投入改变未来任务需求的候选。在给定质量、预期调用量与模型寿命下求收益条件，能力密度的比较保持评测范围一致。 依据：[成本下降调研](../research/token-cost-2023-2026/report.md#density)。

> **实验 3-8 ★〔延伸〕：Scaling Law 的拟合与预算选择**
>
> 用论文公开实验点拟合 N、D 与损失，留出点验证外推；比较 Kaplan／Chinchilla 假设，再加入调用次数得到训练与推理费用交叉曲线。可选小模型实验只检验局部范围。
>
> 条件：基础·Python；可选单卡。

**实测结果（3-8）：** 三个参数规模各两个 seed 的六次真实训练，留出损失全部低于初始化；但增大模型没有在两个 seed 下都更好——seed 309 的最大模型 2.548 nats/byte 反而差于中等模型的 2.480。有限训练量、固定优化器和两个 seed 不足以支持“参数更大一定更好”或向大模型外推。[训练曲线、检查点与限制](../experiments/ch03/03-08/README.md)。

> **局部实训**：固定文本、三个小模型规模各训练两个seed，六次留出损失均下降；但最大模型有一个seed仍差于中等模型。增大参数不自动保证这段有限训练中的收益，不能据此外推大模型规律。[实际训练与检查点曲线](../experiments/ch03/03-08/README.md)。

**计算结果（3-9）：** 同规模模型三代之内训练投入涨 43 倍（Llama-1 7B → Qwen3 8B），涨的几乎全是数据：参数 1.2×、token 36×。D/N 从两位数升到四位数，Chinchilla 的 ≈20 只符合 Llama-1 65B（21.5）与 Llama-2 70B（28.6），此后全部远超。MoE 必须分列：V4-Flash 按 13B 激活参数算的 6ND 只有 405B 的 1/15，但权重容量要按总参数算。[两组投入表与保留差异](../experiments/ch03/03-09/README.md)。

### 3.6.3 质量约束下的生命周期预算与交付

章末决定是在既定质量和调用量下怎样分配训练与服务投入，并指出最需要补测的量。第 4 章据此选择计算、存储与通路配比。

将候选的前期训练投入与预期调用量乘以每任务服务成本分别列出，比较在同一质量目标和请求分布下的总费用。更长训练、蒸馏或更多推理时计算可以改变未来需求；收益交叉点依赖模型寿命、成功率和调用组成。当前章节只建立条件式预算，真实设备能力与执行效率由第 4–10 章逐步校准。

章末保留一页共同字段的负载表，使用以下三组固定输入：

文本 Chat／Agent：模型与质量检查、每轮前缀和新输入、reasoning 与最终输出、到达和工具等待、分支及复用间隔。第 8 章比较批处理与状态保留，第 9 章比较跨实例交接与路由，第 11 章处理工具环境和任务恢复。

视觉与实时任务：原始文件字节、E/P/D 调用、EC 与 KV、帧或块的到达、首段与持续供给目标、打断及过期工作。第 8、9 章使用同一输入分析调度与交接，第 12 章再加入距离、链路与执行位置。

训练／RL：数据与质量目标、序列和批次口径、前向／反向／更新、候选与有效样本、模型和环境调用、权重交接及完成期限。第 4–7 章检查资源供给和协作，第 10 章比较学习与交接，第 11 章组织环境及资源池。

三组输入共用字段定义，分别保留模型、版本、实测与教学假设。每组都交付逐资源需求、阶段依赖图、状态寿命和最需要补测的量，不要求用同一模型承担全部任务。
