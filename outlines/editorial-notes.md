## 全书的写作立场与层次

以资深芯片与系统设计者回顾行业的口吻写作：先交代当时要完成什么、手中有什么资源，再让读者跟着几笔计算发现旧方案的限制，由此理解新设计。经验体现在对关键约束、代价和未知量的判断上，不用自我标榜、口号或大量术语制造权威感。作者亲历可采用第一人称，其他人的设计动机以原件为据，推断明确作为推断。

借鉴《计算机体系结构：量化研究方法》以定量原则连接真实架构与设计取舍的组织方式；具体语气与小标题延续 AI Agent book 的自然、明确、逐层解释。先让读者算出一个判断，再改变负载或硬件复算，最后回到实际采用的方案、代价及后来怎样变化。案例是推导的载体，历史不是发布年份的串联，比较表只用于方便核算。

第 1 章先以降低数据搬移代价提出设备选择，建立集群→超节点→主机与卡→芯片内部的整体认识，把各处资源化为约束：按精度区分的算力、逐卡 HBM 容量与带宽、链路带宽和延迟。容量检查、Roofline、最窄链路与关键路径在第 1 章就引入；第 2 章反复提供这些方法所需的 FLOPs、驻留字节、读取和更新量。每个模型都要算 prefill、单步 decode 与整段生成，不能用“KV 更省”替代具体计算。可编程性与系统抽象边界在 1.1.3 提供背景，在第 11 章回到任务环境。

章节先按少数完整问题组织，再在问题内展开模型或机制。一般保留 4–6 个一级节；第 3 章明确分推理与训练两块。某个案例、参数或新技术增加时，先判断它归属的分析过程，避免不断追加同层标题。本轮各章二级小节最多五个；这不是字数配额，后续需要更细推导时优先用连接清楚的段落和就地实验。每章选择三项核心练习，其余就地标为延伸；完整题目和实验变体放入逐章扩写资料。星级表示难度，核心标记表示阅读选择。

开源系统随着机制和案例出现，不新增产品介绍章。vLLM／SGLang 的请求执行、Ollama 的本地管理、TensorRT-LLM 的 LLM 推理、TensorRT 的通用网络执行、FlashInfer／DeepEP 的内核和通信，以及 Megatron／verl 的训练职责分别说明。实测型实验必须指定真实引擎、版本、模型、硬件和输入，并提供原始记录；纸笔推算先行，没有设备时分析同一记录。当前特性落点见[框架演进笔记](../case-studies/framework-evolution.md)。

优化以 profiling 反馈继续推进，但一次局部变快不能代替完整请求收益。多面体的合法性、硬件成本预测与真实测量分开，TVM／Ansor 已有实测调优；Agent 扩大候选空间，并承担额外验证成本。CUDA Graph、融合、persistent kernel 与 pipelining 按省下的工作分别解释，不能互当同义词。

模型结构必须区分数学表示、参考实现、生产后端和实测。Qwen3-8B 是 Dense 跟算基线，Qwen3-235B／V4-Flash 为 MoE 主线，V4-Pro／Kimi K3 为结构与规模迁移题；旧模型仅在需要解释历史时出现。“Transformer 是旋转 90 度的 RNN”只能用作时间与深度依赖的类比，必须画出新增的历史访问边、参数共享差异和生成依赖。

本轮对照的出版信息见 [Elsevier 第六版说明](../references/outline-checks/2026-09-07/edge-media/quantitative-architecture.html)，实际回读 AI Agent book 的章节样式；没有将出版说明当作全书逐页阅读记录。

## 草案 22 的统一要求

主张和依赖以 [structure.md](structure.md) 为准。每章明确一个可被反例修正的判断，以共同执行图和设计决定连接后文。五问用于发现可优化的搬移；计算瓶颈、必要串行、质量和正确性独立检查。更少字节或更高峰值都不能自动推出有效任务收益。

第 3 章定义 E→P→D 与 EC／KV；第 8、9 章直接使用。第 10 章的 RL 验证引出第 11 章任务环境，再由第 12 章改变物理位置。第 11 章先环境生命周期后调度，第 9.5 节先状态身份与持久化后路由及组合。

新增来源只在推进推导、提供反例或校准关键假设时进入正文。完整版本、矩阵、价格与更多实现保存到扩写资料；主大纲保留能独立复算的配置、单位和出处。首尾重写后的旧细目只作来源，不能以扩写资料的旧题目替换当前核心练习。

作者判断的修正落在 5.3（AKG）、7.4（1Pipe／UB）、12.5（Queqiao）与 13.2（OpenTallas）。亲历细节由已有原件支持，缺失过程留待作者补充；完整实测、局部实现和分析模型分开。第 13 章必须有未在正文求解的配置与能使选择翻转的新增信息。

## 第 2 章 模型架构

- 常见模型规模的硬件“甜点”按精度、设备、状态与并发推导。部署适配不等于已证实的历史设计动机；7–8B 并非只能对应 4090，235B 也不能脱离卡型泛称八卡最优。层数、宽度与专家颗粒度同时影响能力、矩阵效率、状态与通信。

- 容量、每步访问与累计流量分别核算，见[资源计算笔记](../case-studies/model-resource-accounting.md)。K3 NoPE 不表示删除了参考代码中的 64 维分支；紧凑缓存教学路径与该代码展开缓存分别计量。KDA 状态 dtype 由内核决定，不由模型 dtype 猜测。报告中的 MTP 与所固定配置 `num_nextn_predict_layers=0` 分别记录。

- 跟算基线为 Qwen3-8B，主要架构比较为 DeepSeek-V4 与 Kimi K3，配置与代码范围见[模型算子笔记](../case-studies/model-operator-examples.md)。V3 MLA、V4 CSA／HCA 和有限状态混合结构分别核算；V4 的 43 层主干与额外 MTP 分开。Chat／Agent 以实际输入输出、reasoning、复用间隔和命中取回时间比较。

- 模型结构带来的系统收益，与论文明确说明的设计动机分别举证；不能单凭资源计算解释模型质量。
- 固定配置中的层类型、状态格式与量化信息是实验输入；正文选足以解释变化的实例，完整型号资料留在参考库。

- Qwen3.5-397B-A17B 当前快照为 60 层，45 层线性注意力、15 层全注意力；按 text_config 核算，视觉编码器和 MTP 另列。
- Kimi K3 为 69 KDA＋24 MLA 层，存在末尾额外 MLA；不能只按 3:1 比例推算。主干宽度与潜空间专家宽度不同。
- V4 的 CSA／HCA 不是把 V3 MLA 换一个名字；缓存量需包含滑动窗口、压缩状态和索引相关状态。
- 结构和质量之间不预设必然关系，厂商消融结论保持原数据、训练预算与评测范围。

## 第 4 章 加速器架构

- 代际演进穿插于 4.2–4.4 与 4.6 的具体问题；不另设年代回顾节。旧负载、瓶颈、机制收益与设计代价连在一起，产品事实和因果推断分别标明。Vera CPU／Rubin GPU、SM100／SM120、GPU Neural Accelerator／独立 ANE 不混用。相关输入见[演进笔记](../case-studies/architecture-evolution.md)。

- 三种主架构贯穿计算、存储、数据通路与整芯片比较；Apple 的 GPU 与 ANE 分开，不把 ANE 峰值算入 Metal GPU 执行。
- 昇腾核内 Unified Buffer 与系统 Unified Bus 都可能缩写为 UB，首次出现写全称并保持图例不同。950 CV 采用白皮书 §4.1.4／图 4-6；NDDMA 采用 §4.1.5，公开支持不直接等于某工作负载的实测收益。
- H100／4090 是历史判断案例；M2 Max／RTX PRO 6000 是本书拟实测配对。模型、时间和精度不相同的结果不拼成统一排名。

- RTX PRO 6000 Workstation Edition 的 96 GB GDDR7、1,792 GB/s、600 W 分别是容量、标称带宽和总板卡功率规格；不能直接当作实际可用容量、吞吐和整机功率。
- 950PR／950DT 及裁剪配置分别记录；“高速片上内存”不等于核内 SRAM。UB 双向线速不能代入单向有效带宽。
- Trainium3 两份官方文档目前仍分别列 4.9／4.7 TB/s 和 16／20 CC-Core；保留冲突，不用均值或任取一值做精确比较。
- 未获得昇腾实机，跨平台开发时间、性能和能耗结论均需要对应证据；Graphcore 第一代微基准不套用到 GC200／Bow。

## 第 6 章 超节点

- 本章先完成具体模型的 TP／PP／DP／EP 推算，再讲对应硬件。Qwen3-235B 的 94 层／128 选 8 与 V4-Flash 的 43 层／256 选 6 分开；K3 的潜空间路由、首个 dense 层与 MTP 单列。分组、复制和最大逐卡占用按实际实现，不能只用总资源平均。

- 内存池区分可共享容量、访问语义与实际带宽收益。四个 64 GiB 节点承接 80／48／32／32 GiB 为教学输入；借用容量可行不代表每 token 访问远程 KV 可行。

- 先按每 rank 的通信量与实际路径建立下界，再谈集合通信算法。需要校验物理链路共享、全双工及计算—通信是否真的能重叠。
- UE、UALink、NVLink 和 UB 的正式规范／产品资料按各自证据使用，不把宣布支持的最大规模写成已经达到的应用性能。

- 环 all-reduce 的公式必须说明每 rank 原始张量大小、阶段和双工假设；NCCL algorithm bandwidth 与 bus bandwidth 不混用。
- 950 的 2016 GB/s 为双向线速汇总；UBoE 与 UB 共享的端口不能重复计入。
- UALink Evaluation Copy、UB 中文正式规范及 NVLink 产品规格的资料类型不同；正文摘录或原图使用状态单独核对。
- 超节点的协议支持上限、厂商发布规模与已测可用吞吐分别取证。

## 第 7 章 数据中心网络

- 集合通信是模型切分的一部分，不能退化为纯协议目录。第 7.1–7.2 节先推算跨超节点训练与八卡服务器间的大模型推理，后面的主机、协议、拥塞和拓扑用于解释这些方案的瓶颈。InfiniBand／RoCE 输入固定设备与路径，跨超节点协作不写成跨广域网。

- 从上一章超节点的边界、跨超节点流量与扩展效率进入。作者传统网络文章提供机制背景，不能取代 AI 任务的章节主线；强扩展与弱扩展、单访问与全系统状态规模分别计算。

- 作者博客提供叙述顺序和亲历背景；UB 的执行序、完成序、可见性及故障行为以 Base 2.0.1 正式条款为准。不要引用博客中宽泛的“AI 对数据顺序不敏感”来推导正确性。
- RDMA 连接状态可以在主存保存并由网卡片上缓存；状态规模、缓存命中与活动关系才是需要计算的量，不能假定所有状态永久驻留 SRAM。
- ECMP 通常按流选择路径；流级、事务级、包级多路径分别画图。共享内存访问不自动意味着任意设备间缓存一致性或统一访问代价。
- 协议取证入口：UB §2.1–2.2 的语义关系、§5 网络层、§6 传输层、§7 事务层、§8 功能层；页码与中文版本见 [UB 核对笔记](../references/UB-ASCEND-NOTES.md)。

- OpenURMA 的实现快照不代表 UB 全部规范已在生产硬件验证；文档中的实现范围需要随提交号核对。
- UB Reliable Transport 与实时媒体 RTP 缩写不同义，首次出现写全称。
- 拓扑预算需要补所选 NIC、交换机和链路的具体型号；不从芯片总互联带宽直接推整网能力。

## 第 8 章 单实例推理

- vLLM V1、SGLang 重叠调度与混合状态前缀缓存，Ollama 内存调度、MLX 和 MTP 分别穿插。Ollama 官方 MLX 对比改变过量化格式；0.31 的 MTP 只按具体支持模型引用。真实系统记录与模拟调度结果分开。

- 近期主例采用 EAGLE 3.1、DFlash／DFlash 2、MiMo 与 V4 MTP。小米和 EAGLE 团队分别归属；同名引擎开关不证明草稿来源。不同目标模型／精度／后端的加速比不拼成排名。
- MacBook 例子按 GGUF 全部分片字节、真实可用统一内存与 KV 计算；“全部专家保留”与原精度质量不是一回事。元数据与数值见[业务笔记](../case-studies/inference-training-scenarios.md)。

- FlashAttention 解决注意力执行中的 IO；PagedAttention 解决 KV 的分配和映射；prefix caching 再利用已有计算。三者分别从问题推导，不能混成一种缓存优化。
- batch 对权重读取的摊销是第一步近似，随后加入 KV、带宽、矩阵形状和等待；prefill／decode 的瓶颈随实际形状变化。

- 量化文件位宽、实际运行位宽与原生矩阵指令格式分别记录；低位宽不预设更快。
- 预热不能无意引入相同前缀命中；冷加载、模型热、KV 热和图热分别控制。
- 批量加速、单请求延迟和 SLO 内吞吐不是同一个指标；投机速度必须重新放到在线负载下测量。
- 模型、tokenizer、模板、adapter、采样和 thinking token 口径固定，内部计时不替代客户端 TTFT。

配套研究笔记：[MacBook／RTX 配对](../case-studies/macbook-rtx-pro6000.md)。

## 第 9 章 分布式推理

- DBO／TBO／SBO、grouped GEMM 与 EPLB 分别作用于执行重叠、专家内核和物理放置。vLLM AFD 为实验性插件，强制均衡／缩层结果不能当作完整模型等质量服务。HiSparse 的当前 DSA 支持不自动推广到 V4／K3。

- V4-Flash 单 5090 教程与其八卡 MTP 测量分别引用；本轮固定教程是 ≥200 GB 主存及 AVX2/FMA 版本，不混用搜索缓存中的 ≥256 GB／AVX512 旧条件。Kimi K2 教程最大 batch＝4，不据此认定所有异构项目仅支持 batch＝1，也不改称 Kimi K3 的部署。
- batch＝1 是否合适取决于交互时限与到达率；整机比较包括 CPU、DRAM、SSD、功率、长 prefill 与质量，不只数 GPU。

- 基础 TP／PP／DP／EP 已移到第 6、7 章；本章从既定切分继续研究 PD／AF、Persistent KV、多级 HBM／DRAM／SSD／远端缓存和共享池。V4 的压缩 KV、窗口状态与不完整压缩块按 §3.5.2 分别处理，不假设只保存一种状态就能无代价恢复。

- A100 80GB SXM＋H20 SXM5 96GB、4090＋双路 Xeon KTransformers 与共享 KV 池各有独立实验和图。PD／AF／池化可以组合，仍需分别核算权重、激活和 KV 的寿命、交接频率与中转成本。V4 的 rollout 恢复用于连接第 10 章。

- PD 交接与 AF 逐层交接的频次不同；按请求、token、层和路由分别计数，不能共用一个“传一次状态”的公式。
- 需求匹配先统一单位：prefill 池与 decode 池都换算成给定请求分布下的请求／秒，再比较队列和 SLO。

- H20 SXM5 96 GB 型号已有官方依据，完整算力和带宽规格仍待补；不能拿 H100 或二手图填表。
- KT-Kernel 主示例的 4090＋双 6454S 与 SOSP 论文双 8452Y＋A100／4080 不同，性能按原配置引用。
- 跨代 NVIDIA 设备不自动具有直接 NVLink；真实 PCIe／NIC／host staging 路径及 KV 转换必须验证。
- 基本 PD 每请求一次交接是教学模型，实际流水、迁移、复用和故障可以增加交接；AF 也需按实际专家目的端核算。

## 第 10 章 训练系统

- 增加 Megatron Core 2026 的 Parallel Folding、细粒度重计算，以及 NeMo RL 的 R3。重放离散专家 ID，当前路由权重仍参与梯度；检查多轮缓存、token 对齐、缺失路由回退、logprob 定义和 MTP 范围。Sleep Mode 丢弃的 KV 需要另行重建，不与沙箱快照混淆。

- A100／A800 的本例主要差异为 NVLink，80 GB PCIe／SXM 的 HBM 规格分别对齐；H20 以对应任务的实测能力或明确区间推算，未取得完整官方规格的项目不填造。
- 1T／5T／10T 的 Dense 是固定卡数、token、精度与 MFU 下的教学情景，不能成为某代芯片的参数上限；实际 MoE 用总参数计状态、实际矩阵计计算。
- 50% MFU 为较乐观敏感性输入，需核对算法 FLOPs 与稳态计时边界。已计入 MFU 的通信、重计算与气泡不能重复加时；日历停顿另核算。

- 当前 RL 系统主例为 DeepSeek-V4 §5.2，R1 解释训练路线，不再采用 Kimi k1.5 作为系统主例。V4 的 WAL、教师 hidden state 缓存与 OPD 按报告描述，不能将一般同步／异步设计选项写成 V4 已实现的全部机制。

- 4090 集群的问题要写成有条件的判断：先确定训练目标、期限、显存状态和实际 PCIe／NIC 路径，再排除具体并行方案；保留小模型、微调或宽松期限下的可行场景。
- 检查点损失的 c/τ + λτ/2 + λr 仅用于独立、稀少故障和固定成本的初步估算；大规模关联故障与异步持久化需要另算。

- 同一个 MFU 数字只有在算法 FLOPs、设备峰值、精度及重计算口径一致时才可比较。
- 异步采样提高吞吐并不自动保证相同收敛；策略滞后和质量曲线必须共同记录。
- 检查点进程写完文件不等于所有分片已持久化；恢复正确性包括数据游标和随机状态。
- Kimi K3／V4 的训练与环境设计属于报告中的特定实现，不反推其未公开训练总成本。

## 第 11 章 资源调度与运行环境

- 章首和 11.2.2 回扣第 1 章的系统抽象边界上移：通用代码执行使 OS 环境、虚拟化与多租户隔离重新成为主要问题；模型调用共享与 GPU 作业隔离仍在各自机制处保留。详见[衔接说明](../research/system-abstraction-boundary/report.md#environments)。
- 调度以 ASI／SpotGPU、RLBoost、DistRS 与 SpecBox 的具体任务为线索。分配比例不等于 MFU；DistRS 的 CUDA 验证包含 CPU 和 GPU；SpecBox 是 Docker 原型预印本，不将结果写成 E2B 的测量。
- 模型路由采用完成同等质量任务的时间和费用。reasoning 预算、实际思考和可见输出分开；usage 若已有包含关系不能重复计价。前缀命中率、TTL、创建／读取／存储费、队列、限流及失败回退都要进入计算。
- 订阅产品、应用积分和开发者 API 额度逐项核对，不按月费推导固定 token 配额或中转利润。模型版本、服务商、精度、思考设置与缓存变化都可能使服务不再等价。
- 2026-09-07 的 Claude 与 Google 方案快照只作可更新输入。比较实际完成任务和未完成需求，不把纸面上限、宣传值或隐藏思考摘要当实际用量。
- E2B 的官方入口为 e2b.dev／docs.e2b.dev，公开实现采用 Firecracker。模板、暂停／恢复与快照派生分别说明；文件和内存被保存不意味着外部连接或副作用也恢复到过去。普通 CPU 沙箱不默认提供 GPU。
- DeepSeek-V4 DSec 继续作为 RL 环境案例。CPU 核时、内存驻留与等待服务的任务时长分别核算；工具／CUDA 计时控制资源竞争。性能实验不能证明完整隔离。
- OTel 与 OpenCost 作为配套记录和成本归集参考，不扩成独立规范课；内部成本与账单分别记录。正式实验仍需补任务轨迹、资源配置和真实计量事件。

## 第 12 章 端边云协同

- 图片精修、ASR／TTS 与 Computer Use 贯穿任务、协议与放置分析；业务背景简述后直接计算优化。RAW 的历史场景来自作者本次说明，30 MB／5 MB 等为教学参数；不冒充华为产品实测。RAW 可无损压缩；HTTP/3 也是标准 HTTP，协议收益需固定连接状态、带宽、RTT 与丢包，不能把默认配置慢归因于整个协议。见[图片精修笔记](../case-studies/raw-retouching.md)。

- 贯穿案例聚焦语音、代码 Agent 与视觉助手；一般网页、文件下载、投屏不作主要教学场景。协议解释只保留能改变这些 AI 任务的时限、状态与数据移动的内容。

- 《计算机网络的新黄金时代》第二篇讲广域网，第三篇讲无线。采用问题展开方式；当年的流量比例、移动网络现象和协议默认值不能原样当作今天的事实。
- QUIC 的加密与握手用 RFC 9001，可靠有序流用 RFC 9000，拥塞控制用 RFC 9002，不可靠 DATAGRAM 扩展用 RFC 9221。多流减轻跨流队头阻塞，同一流仍有顺序依赖。
- TCP+TLS、QUIC streams、QUIC DATAGRAM、RTP／WebRTC 应根据应用需求比较；帧截止时间、重传与丢弃策略先明确，再解释观测差异。

- Queqiao 的原案例仅覆盖特定路径和版本；236.5 ms 与 240.9 ms 的中位数不能独立证明稳定协议优势。
- 跨机单向阶段时间需要同步时钟或明示误差；客户端端到端计时优先使用同一单调时钟。
- 实时媒体 RTP 不保证资源预留或 QoS；QUIC 与 TCP 的差别也不能简化成“UDP 无队头阻塞”。
- 无 RTX 主机和实际功率记录时，放置与能耗图只能使用标明来源的输入或条件式扫描。

## 第 13 章 架构协同设计
