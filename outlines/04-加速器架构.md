# 第 4 章 加速器架构

> 写作大纲 · 按硬件组成与性能判断重排 · 草案 23 · 2026-09-10

第 3 章给出了模型执行需要多少计算、存储和数据访问。本章把这些需求放到真实硬件上：先认识加速器的组成，再依次解释谁来计算、数据放在哪里、怎样搬运与衔接，以及如何扩展和专用化，最后判断不同架构适合什么负载。

**本章判断：** 加速器的实际速度既取决于计算能力，也取决于数据能否及时到达，以及各类计算能否顺利衔接。容量、功耗与成本共同决定一个设计是否适用。

**前置与交付：** 依赖第 2、3 章；交付同一任务的容量需求、时间下界、候选架构及最值得验证的性能差距。第 5 章用真实实现与执行轨迹检查预测，第 6 章展开多芯片并行。

**阅读安排：** 用 Qwen3-8B 的 Q 投影建立共同例子，再以注意力与 V4-Flash 专家矩阵补充复杂性。每节先解释机制，再比较 NVIDIA、昇腾和 Apple；代际细节及完整证据放入[扩写资料](extensions/04-%E5%8A%A0%E9%80%9F%E5%99%A8%E6%9E%B6%E6%9E%84.md)。核心练习为实验 4-1、4-4、4-5；其余为延伸。实验编号沿用，配图按新阅读顺序编号。章末更新[跨章设计决定](decision-record.md)。

## 4.2 计算单元：矩阵、向量与控制

回答“哪些工作由谁计算”。先解释共同机制，再比较厂商实现；数据存放和搬运分别在 4.3、4.4 展开。

### 4.2.1 矩阵单元为什么适合神经网络

从大量重复乘加与操作数复用解释矩阵单元的吞吐优势。用同一矩阵的大小、分块数和边界浪费，说明峰值能力需要怎样的形状才能发挥；再换成小 batch 专家矩阵，观察利用率变化。

以 NVIDIA Tensor Core 和昇腾 Cube 为实现例子，代际变化只选择能说明执行粒度或精度差异的机制。NVIDIA Blackwell SM100 与 RTX Blackwell SM120 分开，具体指令与型号对照放入扩写资料。

### 4.2.2 向量与控制单元负责哪些工作

用 Softmax 的指数与归约、归一化、激活和专家路由说明矩阵乘法以外的工作。区分向量计算、标量控制和任务调度，解释矩阵单元变快后，其他工作为什么可能限制整体速度。

以昇腾 Cube／Vector／Scalar 的分工为例，再对照 NVIDIA 和 Apple GPU 的执行组织。先说明任务需求，再讨论不同单元配比；未披露的内部设计保留未知。

### 4.2.3 同一注意力在 NVIDIA、昇腾和 Apple 上的分工

并排标出 QK、Softmax 和 AV 在三种架构上的执行者及依赖。固定数据访问条件，分别只提高矩阵能力、只提高非矩阵能力，再增加上下文长度，比较完成时间怎样变化。FlashAttention-4 的资源分析用作可复算例子，具体 tile、周期和适用范围见扩写资料。

Apple 以 M2 Max 的 Metal GPU 路径为基线，明确 GPU 计算与独立 Neural Engine（ANE）的区别；M5 GPU 内 Neural Accelerator 作为代际对照。是否使用新单元按实际后端核对。

> **实验 4-1 ★〔核心〕：注意力计算与单元配比**
>
> 将 Qwen3-8B 的同一注意力计算映射到 NVIDIA、昇腾和 Apple，再固定访存条件，分别只提高矩阵或向量能力。算完成时间而非峰值总和；增大上下文后重做，判断哪项资源更值得增加。
>
> 条件：基础·形状、资源与依赖计算。

**计算结果（4-1）：** 只把矩阵能力翻倍，注意力 tile 的稳态下界一点没动（1,024 周期不变）——指数（softmax 的向量／特殊函数）立刻接替成为限制；矩阵与指数一起翻倍后共享内存又接替上来，三项同时翻倍才真正减半。四种 tile 尺寸上顺序相同。整设备侧，上下文从 8K 到 32K 时注意力工作涨 16 倍而访存只涨 4 倍，因此这条路径上更值得增加的是矩阵与配套的向量能力。昇腾与 Apple 只能给访存下界：前者官方 cube 峰值的累加精度为 unspecified，后者未公布 GPU 矩阵峰值。[单 SM 与设备两层结果](../experiments/ch04/04-01/README.md)。

### 4.2.4 低精度如何改变计算量、数据量与转换开销

跟踪低比特权重从存储、读取、解码或反量化到矩阵执行的完整过程。区分存储格式、执行格式和累加精度，将 scale 等元数据、转换开销及质量条件一起计入。

用同一个 V4-Flash 专家矩阵比较两条可用路径，再换成小 batch decode，解释数据量减少为何不一定带来同等倍数的加速。[局部实验](../experiments/ch04/04-02/README.md)用于说明转换、矩阵本体和工作区应分别比较；误差、模型内替换与内存峰值记录保留在扩写资料。

> **实验 4-2 ★〔延伸〕：低精度执行成本**
>
> 降低权重精度后，哪项成本没有一起下降？ 固定同一专家矩阵及质量要求，比较 Hopper／Blackwell 或 Apple 后端中可用的两条低比特路径；逐项计权重、scale、转换与矩阵工作。再改为小 batch decode，解释新低精度算力何时不能转化为相同倍数的速度。
>
> 条件：基础·计算。

**实测结果（4-2）：** RTX PRO 6000 上固定同一专家矩阵形状比较两条 INT8 路径：直算后 scale 与每次反量化为 BF16 再乘。完整路径中位 57.96／73.05 μs（batch=1），但 INT8 矩阵本体（40.20 μs）并不比 BF16 本体（5.26 μs）快——完整路径里的激活量化、padding、输出 cast 与逐次权重展开才是差别所在。batch 从 1 到 512，矩阵本体时间几乎不变，说明小 batch decode 下新低精度算力无法按倍数转化为速度。Apple 4-bit 用不同格式与计时范围单独保存，不与此表相除。[两条路径、分阶段计时与限制](../experiments/ch04/04-02/README.md)。

## 4.3 存储层次：数据放在哪里，能多快读出来

先看模型和状态能否放下，再看哪些数据值得留在片上，最后区分容量、带宽与延迟的限制。

### 4.3.1 显存与统一内存：权重和 KV 能否放下

沿用第 3 章的权重与 KV 计算，先求 Qwen3-8B 的驻留容量，再增加模型规模、上下文与并发。训练另计梯度、优化器状态和中间激活。

区分两个维度：HBM、GDDR 是内存技术，统一内存描述 CPU／GPU 等处理器的共享与访问关系。以 NVIDIA、昇腾与 Apple 的具体产品比较容量和组织；CPU／GPU 共享时，还要考虑其他任务占用。

### 4.3.2 缓存、片上缓冲与寄存器：减少重复读取

用一个矩阵块的输入、累加器与中间结果计算片上工作集。解释缓存自动保留数据、软件管理缓冲与寄存器分别承担什么，以及数据复用如何减少片外读取。各架构按实际存储组织对照。

选择 Hopper shared memory 与 Blackwell SM100 Tensor Memory 的变化，说明新增存储服务于哪些数据、缓解什么压力；容量、访问速度和同步代价分别分析。缓冲在执行时如何轮换留到 4.4。

### 4.3.3 容量、带宽与延迟分别限制什么

围绕三个问题展开：容量决定能否驻留，带宽限制单位时间搬运的数据量，访问延迟决定一次请求需要等待多久。通过增加独立访问解释如何隐藏部分延迟，以及为什么标称带宽未必能用满。

用[同一 KV 工作集的并发算例](../case-studies/memory-bandwidth-and-concurrency.md)说明：维持目标吞吐所需的在途字节至少等于目标吞吐乘以工作点延迟。在途事务数按实际访问计算，不能直接用 batch、线程或 SM 数替代。

以 H100／H200 的对照区分容量、带宽与矩阵能力的变化，再比较 Apple 的大容量共享内存。更多型号和规格留在扩写资料。

> **实验 4-3 ★〔延伸〕：存储容量与解码带宽**
>
> 相同容量为什么有不同的解码速度？ 用 Qwen3-8B／235B 的真实权重和 KV 工作集，在 A100、H100／H200、B200 与 M2 Max 条件下计算驻留与读取时间。先只替换容量，再只替换带宽，最后代入真实产品；改变并发与上下文后解释各代设计的收益范围。
>
> 条件：基础·计算。

**计算结果（4-3）：** A100 与 H100 容量相同（80 GB）、能装的请求数也相同（50 个），解码吞吐却差 64%；M2 Max 容量更大（96 GB、64 个请求）而吞吐只有 H100 的 1/8——差别全在带宽。逐项替换更直接：只加容量吞吐只涨 12–15% 且单步读取时间从 37.7 涨到 67.9 ms，只加带宽涨 135–292%。Qwen3-235B-A22B 的 470.2 GB 权重本组单卡全放不下，那时容量不是收益问题而是可行性问题。[逐设备与逐项替换](../experiments/ch04/04-03/README.md)。

## 4.4 数据搬运：怎样减少计算单元的等待

沿一个矩阵块从存储到计算单元的过程，解释寻址、搬运与交接。本节讲硬件提供的机制，第 5 章检查软件如何使用这些机制。

### 4.4.1 数据布局与寻址：怎样找到并取出一个矩阵块

从连续存放的投影矩阵出发，说明基址、步长和分块如何决定实际访问。再换成 token 分组与专家位置变化的 MoE，区分有效数据搬运和地址、描述符准备的开销。

在读者理解问题后，引入 Hopper TMA 的多维搬运、Rubin 的描述符更新与昇腾 NDDMA 作为对照；按各自接口说明省下的工作。

### 4.4.2 异步搬运与双缓冲：让搬运和计算重叠

先画同步加载的时间线，再用两块缓冲交替完成“计算当前块、搬运下一块”。由搬运时间、计算时间和依赖求稳态间隔，同时保留启动、排空与同步开销；异步接口是否产生重叠需要满足具体条件。

用 Ampere 异步拷贝与 Hopper TMA 解释减少寄存器中转、卸载搬运工作，再对照昇腾 MTE／NDDMA 与 Apple Metal 的缓冲和任务依赖。提高计算速度后重新求缓冲需求，比较额外容量、寄存器压力和同步成本。

### 4.4.3 单元间的数据传递：矩阵与向量计算怎样衔接

跟踪注意力中矩阵结果交给 Softmax、Softmax 结果再进入矩阵乘法的过程，标出中间张量、存储位置和可开始执行的时刻。比较经存储交换、专用交接路径及细粒度触发，判断减少了哪些中转和等待。

以昇腾 950 CV 通路和选定 NVIDIA／Apple 路径对照；Blackwell TMEM 与 Rubin tile 级触发放入已建立的依赖图中，具体规格与版本放入扩写资料。

> **实验 4-4 ★〔核心〕：片上缓冲与数据复用**
>
> 增加一块片上缓冲值不值得？ 沿同一 Qwen 注意力或 V4 专家矩阵，比较同步加载、异步搬运与专用交接路径。扫描分块和缓冲，算省下的中转字节、指令与等待，再增加矩阵吞吐，观察旧缓冲为何可能不够；提交收益开始变小的位置。
>
> 条件：基础·Python。

**计算结果（4-4）：** 在 80 KiB 片上容量这一档，同步单缓冲能用 128×32×128 块、下一层访问 1,560 MiB；异步双缓冲要为在途数据额外留一份输入空间，最大块退到 64×32×64、访问翻到 3,096 MiB——多出的 1,536 MiB 就是重叠的价格。64 KiB 与 256 KiB 两端没有差别，代价只出现在容量卡在两档之间时。128 KiB 之后最佳块与中转字节不再改善，收益到此变小。注意力侧 KV 块越小接口字节越少、行状态更新却多两个数量级，没有单一最优块。[分块扫描与限制](../experiments/ch04/04-04/README.md)。

## 4.6 专用架构：固定哪些工作，换来哪些收益

用少量代表路线比较专用化：先说明负载假设，再算减少了什么工作、增加了什么限制。

### 4.6.1 TPU：以矩阵阵列为核心的设计

### 4.6.2 Groq、Graphcore 与 Cerebras：片上存储与扩展

## 4.7 用架构解释性能与选择

将全章的计算、存储与数据路径汇总到同一任务，先估算，再解释实测差距，最后比较可行设计。

### 4.7.1 从计算量与访问量估算执行时间

回到 4.1 的 Q 投影，分别用计算量除以匹配精度的计算吞吐、实际访问量除以对应层级的带宽，估算各项时间下界。明确片上重复读取和片外读取的区别；非矩阵计算、转换及数据依赖单独计入。

先画阶段依赖，再判断哪些时间要相加、哪些在理想重叠条件下取最大值。区分时间下界、性能上界与实际完成时间；具体硬件参数和累加条件见[硬件资料](../calculations/HARDWARE-AUDIT.md)。

### 4.7.2 Roofline：batch 与上下文怎样改变瓶颈

使用第 1 章的 Roofline 方法，由算术强度连接计算与带宽上界。完整算一组 Qwen3-8B 的 Q 投影，改变 batch 后观察权重复用与主导限制如何变化，再用注意力说明上下文增长的影响。

[同一矩阵的复算](../calculations/results/projection-qwen3-8b-rtx4090-b256.md)作为数值例子；正文保留结论与条件，详细数值放入扩写资料。比较硬件时保持输入、执行精度和计量范围一致。

> **实验 4-5 ★〔核心〕：batch 与架构性能**
>
> 把 batch 变大，会改变芯片比较的结果吗？ 使用 Qwen3-8B 和 V4-Flash 的形状，生成三家架构及选定代际的 Roofline。分别只改变矩阵吞吐、存储带宽和非矩阵能力，再代入真实组合；用 prefill、decode 与不同 batch 说明哪项演进解决了当前瓶颈。
>
> 条件：基础·Python。

**计算结果（4-5）：** batch 从 1 到 256，Qwen3-8B decode 的算术强度只从 1.2 升到 15.8，仍在 H100 脊点 295 的左侧 19 倍处；四种架构的排序完全不变，全部由带宽决定——把 batch 变大不改变这个范围内的芯片比较结果。单因子改动给出干净的二分：prefill 只对矩阵吞吐敏感，decode 只对存储带宽敏感。V4-Flash 的 prefill 标量工作是 Qwen3-8B 的 28 倍，Roofline 的两条边都解释不了这一项。[Roofline 图、逐场景表与限制](../experiments/ch04/04-05/README.md)。

### 4.7.3 预测与实测为什么有差距

按形状利用率、片上容量、非矩阵工作、同步与主机提交逐项解释差距。使用[Mac 与 RTX 的局部测量](../experiments/ch04/04-06/README.md)说明后端路径、缓存状态和实际读取量会影响归因；昇腾采用指定公开记录。

本章用测量校准架构判断，第 5 章检查具体实现与执行轨迹，第 8 章完成服务测量。

> **实验 4-6 ★★〔延伸〕：Mac 与 RTX 的预测和测量**
>
> Mac 和 RTX 的差别能由架构解释多少？ 采集小矩阵、带宽和注意力测量，对照预测；昇腾用指定论文记录，数据分析替代硬件。
>
> 条件：进阶·单设备／公开记录。

**实测结果（4-6）：** 相同 FP32 矩阵在 M2 Max 与 RTX 上均通过参考检查；256 MiB 复制的载荷速率约 192 与 734 GB/s，但热缓存与运行库路径不同，不能直接当外存带宽。注意力两端也通过数值检查，但默认 SDPA 进入不同后端路径。匹配投影的 RTX 计数器显示：单行 GEMV 两种访问方式的前史读取量相同，batch 256 的 GEMM 才出现明显缓存差异，不能仅凭耗时归因。昇腾用指定论文记录另列。[记录、计数器与图](../experiments/ch04/04-06/README.md)。

### 4.7.4 在容量、速度、功耗与成本之间做选择

先排除容量或任务目标不满足的配置，再比较完成同一有效任务所需的时间、能耗与费用。用 H100／4090 历史问题和 M2 Max／RTX PRO 6000 配对说明按卡、整机与任务比较的区别。

将 4.6 的专用化方案加入候选：用增量固定投入除以单位有效产出节省求回本量，再加入利用率、交付期、真实需求、模型寿命和迁移费。改变负载或部署量后，允许选择继续、修改或停止。

**计算结果（4.7.4，权重驻留）：** 先问权重不再占用 HBM 之后还剩什么。按固定 Qwen3-8B 配置重建：完整 checkpoint 16,381,470,720 B，一步活跃权重读取 15,136,811,008 B，两者之差恰好是 decode 只取一行、不必流式读取的 embedding 查找表。每历史 token 的 KV 为 147,456 B，8,192 上下文下每序列每步读 1,207,959,552 B，权重与 KV 的交叉点落在 batch 12.53，即从 13 起 KV 读取超过权重读取；把权重移出这一接口，仅此内存服务的理想加速比在 B=1 时为 13.53、B=16 时降到 1.78，它不是整机加速比。上下文换成 32,768 时交叉点前移到 3.13。倒推供给：单用户 10,000 tok/s 仅 KV 读就需 12.08 TB/s，按每 stack 1.2 TB/s 至少 11 个 stack，按情景密度仅这段状态就要约 401 mm²。[逐项账与明确未计入的七条约束](../calculations/results/weight-resident-qwen8-8k.md)；长上下文变体见[32K 的同一账](../calculations/results/weight-resident-qwen8-32k.md)。

**计算结果（4.7.4，回本）：** 按案例的教学金额，增量固定投入 2,000 万美元、每百万有效输出 token 节省 0.50 美元，回本量为 4×10¹³ token；100 台各 10,000 tok/s、利用率 50%、寿命一年只交付 1.5768×10¹³ token，覆盖率 0.394，需要 254 台同等产出的全年有效流量。三类风险各自把这个数推得更远：寿命减半要 508 台，交付滑 26 周要 506 台（交付期从寿命里扣掉而不是往后加），有效速率掉到 6,000 tok/s 要 423 台。整站费用要单独进账：散热系数只乘电费、不乘网络与备份，标称情形站点合计 1,311,040 美元、折合每百万 token 0.0831 美元，吃掉所声称节省的 16.6%，净节省 0.4169 仍不足以回本；有效速率下降时同一设施摊到更少 token，站点成本升到 0.1386。机器数只是产出折算，还要有真实需求消化它。[四种情形与站点分项](../calculations/results/specialization-payback-baseline.md)，刚好够回本的机队见[254 台变体](../calculations/results/specialization-payback-fleet-254.md)。

> **实验 4-7 ★★〔延伸〕：负载变化与芯片资源分配**
>
> 选 Ampere→Hopper、Hopper→Blackwell、Blackwell→Rubin 或一条昇腾／Apple 演进线。先用前代代表负载提出资源分配，再换成大 Transformer、长上下文或稀疏专家，重新计算瓶颈并选择一次硬件改动。与公开设计对照，说明动机依据、预期收益、代价及最需要的验证；不要求复述所有新特性。
>
> 条件：进阶·历史与反事实推演。

**推演结果（4-7）：** 官方规格证实设计重心移动过：A100→H100 是矩阵 3.17× 对带宽 1.64×、容量不变；H100→B200 三项同步；B200→Rubin 反过来是带宽 2.40× 对矩阵 1.78×。四类负载中，大 Transformer prefill 仍计算受限，长上下文 decode 与稀疏专家 decode 跨到访存侧，后者的标量／矩阵比还是前代负载的 56 倍。据此选择把一次改动用在显存带宽与容量上；最需要的验证是目标分布里 decode 的实际时间占比与批内专家并集的真实分布。[逐代规格、瓶颈表与对照](../experiments/ch04/04-07/README.md)。
