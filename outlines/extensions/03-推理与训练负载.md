## 3.1 推理：复用、到达与交互

先算一次模型执行，再比较 Chat、Agentic 与 Real-time 的请求和依赖。输入输出不仅包括文本；图像、音频和视频还需统计像素、帧、块与实际传输字节。

<a id="detail-3.1.1"></a>

### 3.1.1 Prefill 与 Decode

沿 Qwen3-8B 和 V4-Flash 的第 2 章算例，把整段输入代入实际矩阵，计算 prefill 的投影、注意力与专家工作。前缀命中后只处理未缓存部分，但仍可能读取既有状态；最大上下文长度与真实新输入长度分别统计。

对比单 token decode 与批量输入的矩阵形状。低并发下，一次读取权重只服务少量 token；增加 batch 可以摊薄权重读取，随后 KV、容量、专家分布与等待又可能成为限制。prefill 常偏计算密集、decode 常偏带宽密集，是可由形状检验的起点。

分别计算输入处理、生成、排队与状态寿命。定义首 token 时间、逐 token 时间与完整请求时间；reasoning 服务还需区分首个内部 token、首个对用户有用的输出。将各阶段换成同一请求分布下的需求，为第 8、9 章的批处理和 PD 分离准备输入。

### 3.1.2 Chat 与 Reasoning

**占位 TC-05：** 补 token 单价、思考长度与成功任务成本的区别。 详见[成本下降调研](../../research/token-cost-2023-2026/report.md#economics)。

从单轮问答进入多轮 Chat，比较输入、输出、重复前缀与到达突发。复用第 2.6 节的统计，观察平均长度相同而尾部不同的两组请求如何产生不同的 KV 峰值与等待。

用 ServeGen 的生产负载研究补上时间上的变化：相同 QPS、全局长度分布，仍可能因为不同客户集中在不同时段而改变 prefill／decode 需求。先保留客户组成与轮间间隔，再比较打乱这些关联的结果；Agent 工具依赖与真实前缀命中仍需各自的轨迹，不能由这份研究直接补齐。

> **实验 3-2 ★：相同均值下的不同请求分布**
>
> 先手算两组平均输入与输出长度相近的请求，再重放到达和完成过程；比较 KV 峰值、等待和 p95，识别平均值遗漏的约束。
>
> 增加同一组 Qwen3 请求的时段变体：两分钟内均为 4 requests/s，长输入与长输出两类请求总数相同，但混合比例从均匀改为先 9:1、再 1:9。按短时间窗算两阶段需求，找到平均配置开始积压的位置。ServeGen 用于构造客户分布，实际发送速率、成对长度和多轮关联在生成后重新检查，见[计算与实验输入](../../case-studies/workload-and-provisioning.md)。

> 条件：基础·手算后重放。

以 DeepSeek-R1 的推理路线和 V4 的公开能力设置为例，区分 reasoning 与最终回答、串行思考、并行采样和验证。比较质量改善、生成长度和延迟约束；推理能力不是单独一种固定请求分布，也可能进入 Agent 和实时任务。

### 3.1.3 Agentic：模型与工具的循环

沿代码 Agent 的一条具体轨迹，连接生成、工具执行、结果回传和下一次 prefill。每轮输入中有旧前缀、先前 reasoning 或回答、以及新增工具结果；不同上下文策略会改变可复用部分，不能用对话轮数直接代替计算量。

比较串行调用、并行工具与多候选探索。工具等待未必消耗 GPU 核时，却可能占住 KV；分支共享前缀并分别增长尾部。计算活跃生成、等待恢复和可换出状态，为内存池与缓存路由建立负载依据。

统计模型调用数、有效输入 token、reasoning／非 reasoning 输出、工具运行与失败重试。沿依赖图找决定任务完成时间的路径，说明单次模型加速为何未必同比缩短任务；第 11 章继续计算 CPU、环境与恢复资源。

### 3.1.4 Real-time：连续感知与交互

用实时语音和持续视频感知两类交互说明采集、编码、模型执行与反馈。语音沿识别或音频编码、语言推理、语音生成和播放计算；视频助手沿采样率、帧尺寸、视觉编码与回答计算，区分处理每一帧与按任务抽帧。级联、流式与端到端模型分别数帧、块、像素和 token。

对照上传一张 RAW 后等待 AI 精修成片的请求：它仍是推理服务，但主要约束可能是完整输入与输出的搬移，不要求连续播放。这里交代负载差异，第 12 章用作者的图片精修经历详细推算上传、执行和回传。

首段可播放时间、块间隔、播放缓冲和取消响应共同决定体验；已经过期的结果即使算出也可能无用。用一条语音轨迹计算端到端预算，连接第 12 章的端边云传输、第 8 章的服务调度和第 11 章的任务控制。

## 3.2 训练：状态更新与计算预算

先理解参数怎样更新，再比较预训练、中期训练、SFT 和 RL 的工作组成；最后用规模规律与公开训练投入解释预算如何分配。

<a id="detail-3.2.1"></a>

### 3.2.1 预训练、中期训练与 SFT

在第 2 章单层矩阵上补上反向传播，数梯度、激活与优化器状态，解释训练为何比推理需要更多计算和存储。`6ND` 放在这里作为稠密参数矩阵训练的粗估，随后加入长上下文注意力、MoE 激活、重计算、输出头与精度的影响；它不决定最佳模型大小或训练数据量。

两者通常延续相同的自回归学习与梯度更新过程，区别主要来自数据质量与混合、上下文长度、训练进度和能力目标。“Mid-train” 的阶段划分随团队而异，按具体报告解释；用 Qwen3 的通用、推理数据强化与长上下文阶段，以及 V4 的预训练说明数据变化怎样改变计算形状。

用整理好的输入—输出轨迹解释监督微调，数有效标签 token、训练轮次与数据准备成本。相对大规模预训练，公开案例中的 SFT 常占较少训练工作；不将其写成对所有任务都很快的定律。本节简要交代它在能力塑造与 RL 初始化中的位置。

### 3.2.2 RL：生成、反馈与学习

从刚讲过的推理和 Agent 轨迹出发，解释训练数据如何由当前策略生成，再由规则、模型或实际环境验证。DeepSeek-R1 用于交代 RL 训练路线，DeepSeek-V4 用作系统主例；一次训练迭代需要的不只是生成 token，还可能需要代码执行、工具环境和多个模型前向。

把样本筛选与组织、策略更新、新权重同步接到 rollout 之后。计算生成、奖励／验证、反向更新、参数与状态传输的阶段时间；只有阶段需求统一为同一批有效样本，才能判断资源应给采样还是学习。具体并行、共置和调度机制留到第 10 章。

依据 V4 报告 §5.2，介绍长上下文 RL、OPD 教师前向和可恢复 rollout 提出的工作：长轨迹留存、教师权重读取、hidden state 与 logits 的存储选择、抢占后的 KV 恢复。这里只计算规模与数据寿命；第 9 章展开生成服务恢复，第 10 章展开 RL／OPD 系统，第 11 章展开 Agent 沙箱。

### 3.2.3 Scaling Law 与计算预算

**占位 TC-06：** 补更长训练、蒸馏与能力密度的关系，以及训练换推理的条件。 详见[成本下降调研](../../research/token-cost-2023-2026/report.md#density)。

明确 scaling law 的对象是固定数据与训练条件下的统计关系。由多组模型规模 N、数据量 D、计算预算 C 和验证损失拟合关系，保留未参与拟合的实验检验预测；Llama 3 的预算到损失、再到任务表现的两步方法作为历史实例。

比较相同预算下“大模型、少训练”与“较小模型、更多数据”的选择；说明结论为何随数据、优化与实验范围改变。Chinchilla 的 token／参数比例用于理解一次研究的结论，不作为今天所有 dense、MoE 和混合模型共用的固定常数。

用 Qwen2.5 报告中的学习率、batch 与模型规模实验，以及 Beyond Chinchilla-Optimal 对长期推理费用的研究，解释拟合时哪些条件需要控制。将使用次数与质量目标加入总成本，比较多训练一个较小模型和服务时多用计算；pretraining、RL 和 test-time compute 的增长关系分别讨论。
