# 图执行的范围与成本

核对于 2026-09-08。本文将 [GraCE 的已读正文](../references/proceedings/OSDI/2026/selected/osdi26-ghosh.pdf#page=4)与 [vLLM／SGLang 的版本路径](../references/framework-history/2026-09-08/graph-selection/README.md)连接到 5.4、9.1 和既有实验。以下数值为教学计算，没有运行模型或测得图执行收益。

## 捕获范围为什么变化

vLLM v0.6.0（2024-09）的 `ModelRunner` 在没有 prefill 且注意力元数据允许时重放 decode 图；固定输入与 KV 地址，重放前更新 token、position、slot mapping 等缓冲。它没有每步复制整份 KV。该路径的历史限制不能用来描述今天的 V1。[历史源码](../references/framework-history/2026-09-08/graph-selection/vllm-060-model-runner.py)

到 v0.9.2（2025-07），V1 已将 attention 留在 eager、周围的计算分段捕获，避免一个难捕获操作阻断整条链；attention 输出直接写入后续图可用的缓冲。指南同时提供有后端条件的全图选项。双模式 PR 于 2025-08 合并，随后捕获与编译逐渐解耦：固定主线的 dispatcher 根据 token 数、是否 uniform decode、LoRA 情况和允许模式选择 FULL、PIECEWISE 或 NONE。推测验证也可能是 uniform batch，但每请求有多个 token，不能只用请求数作为图形状。[2025 指南](../references/framework-history/2026-09-08/graph-selection/vllm-092-compile.md)、[当前分派实现](../references/framework-history/2026-09-08/graph-selection/vllm-current-dispatcher.py)

SGLang 的 BCG 则在捕获中遇到显式 eager 区段时暂停，执行该区段后继续捕获。按其 2026-08 公告，跨断点返回的 tensor 需要保留稳定边界缓冲，重放时将新结果复制进去；这与能够直接写入固定输出缓冲的接口有不同成本。它省下为切图而追踪整个模型的工作，仍要执行 eager 区段、更新元数据和保持地址有效。公告中的 prefill 全图仍为显式启用的实验功能，有注意力后端和请求槽位条件。[官方公告](https://www.lmsys.org/blog/2026-08-17-advanced-cuda-graph/)

这一段演进解释“怎样让更多计算进入图”，尚未回答“这些图是否都值得用”。固定主线 vLLM dispatcher 优先寻找可用 FULL 图，再查 PIECEWISE，最后回退；这是配置及兼容性分派，不能当作按每段实测耗时自动寻找最优模式。

## 从少一次提交到少一次拷贝

GraCE 区分了三个问题：修复阻碍捕获的代码、减少重放前的输入数据复制，以及根据测量选择保留哪一段图。它只为外部输入等确需更新的参数处理拷贝；同一图内前一个 kernel 直接产出的中间结果不必复制一遍。

以 Qwen3-8B 的 hidden size 4096、BF16 为形状来源，256／2048 token 的 hidden tensor 分别为 2／16 MiB。若需要额外复制到固定边界，HBM 至少多读写一次，共 4／32 MiB。教学取可用于该复制的 HBM 流量带宽 2 TB/s，得到 2.10／16.78 微秒下界；原算子正常读取输入的字节仍然存在。不能把此带宽当作真实 H100 或其他设备的实测值。

再独立给一段教学算子链设 GPU 工作 20 微秒、**已经暴露在关键路径上的**逐 kernel 提交等待 20 微秒，则普通执行为 40 微秒。图重放提交和元数据分别为 3／2 微秒：

| 执行方式 | 2 MiB 外部输入 | 16 MiB 外部输入 |
| --- | ---: | ---: |
| 普通执行 | 40.00 μs | 40.00 μs |
| 图重放，额外复制输入 | 27.10 μs | 41.78 μs |
| 图重放，教学间接寻址路径额外 6 μs | 31.00 μs | 31.00 μs |

这里固定 GPU 时间以隔离交接成本，并非两个真实 Qwen batch 的相同执行时间。假设各项位于串行关键路径；有重叠时重画时间线。小输入选择普通图，大输入选择间接寻址图；如果只支持前两种，大输入就应保留普通执行。这是先估算、再 profiling 的理由，不能用 kernel 个数乘标称启动延迟替代实际暴露的等待。

GraCE 的间接寻址用小量指针更新替代大块数据复制。可改写的 JIT kernel 与不可改写的库 kernel 采用不同路径，后者还要执行更新参数的前置 kernel；H2D 指针提交与 GPU 解引用都不是免费。它不消除正常输入读取，也不说明任意更换指针都保持形状、布局、寿命和依赖正确。仅有更少字节不能保证更快。[正文 §3–4](../references/proceedings/OSDI/2026/selected/osdi26-ghosh.pdf#page=6)

若额外准备这条 31 微秒路径需要 1 秒，相对 40 微秒普通执行，每次省 9 微秒，至少要重放 111,112 次才超过准备成本。这个计算连接 10.6 的副本寿命；编译缓存、图重捕获、形状变化和真实命中次数会改变答案。

## Padding 与图内存要放回模型预算

对 Qwen3-8B 的一层三矩阵 FFN，参数项为 `3×4096×12288=150,994,944`。将 1536 个真实 token 补到 2048，额外 512 行的矩阵乘增加 `2×512×150,994,944≈154.62 GFLOPs`，是这一层真实 FFN 矩阵工作的三分之一。不能把减少的提交时间当作纯收益；也不能将这个比例套到整层 attention 或整次请求。

SGLang 全 prefill 图同时处理 token 桶与 request 槽位。补 token 会增加 dense 矩阵工作，空 request 槽位以零长度表示，注意力可按实际长度跳过大部分工作；两者不能按同一个 padding 比例估算。实验分别记录真实 token、填充 token、请求槽位及实际后端。

图的容量也不能简化成“每多一个形状必然多一份完整激活”。多个图和区段可能共享内存池与输出缓冲；跨 eager 断点的边界值仍要保留。捕获上限若低于最大 prefill chunk，最大请求可能继续 eager，同时保留已有图内存。覆盖最大 chunk 后，又可能用既有图池替代那段瞬时激活峰值。应分别记录常驻量和峰值，检查图是否挤占 KV 容量，再由实际分配路径决定哪些字节可相加。[SGLang 的内存分析](https://www.lmsys.org/blog/2026-08-17-advanced-cuda-graph/)

## 采用边界与实验安排

GraCE 采用 PyTorch 2.4，25 个选定负载含训练和推理，以每 iteration 时间为主，主要单卡为 H100 NVL 94GB；多卡与 A6000 另有配置。其对 vLLM “只能部分编译”等描述属于论文背景，不代替当前框架证据。论文报告的筛选前 116 个图与优化后 123 个候选图是不同集合，不能把分母混用；额外编译时间也不是服务稳态开销。本文采用机制及选择方法，不将论文加速比移到 Qwen3／V4／K3。[正文 §5](../references/proceedings/OSDI/2026/selected/osdi26-ghosh.pdf#page=11)
