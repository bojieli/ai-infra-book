## 上下文工程的来源与取舍

第 8.2.4–8.2.5 以作者 **AI Agent 书第 2 章**为主来源：[章节快照](../references/author-materials/2026-09-09/agent-book-chapter2.md)、[实验台账](../references/author-materials/2026-09-09/agent-book-chapter2-ledger.md)。读取范围为“KV Cache 友好的上下文设计”“状态更新的两种实现与缓存代价”“上下文压缩策略”，以及实验 2-3、2-10 的登记；未重跑兄弟项目的实验。

本书已有 QKV 与引擎缓存原理，直接从消息改变的位置开始。固定系统提示、工具列表和已有历史，分别改变前部时间戳、工具排序、末尾状态与工具结果。用真正生成的 token 前缀确定失效位置，再计算重建、保留和继续 decode 的资源。跨模型、adapter、格式与混合状态的复用限制仍沿现有大纲。

状态更新比较两种方式：替换旧状态会使其后缀需要重建；持久追加保住前缀，但增加陈旧状态、KV 容量与后续注意力读取。沿 Agent 书的 S（状态大小）、R（更新间后缀）、N（更新次数）建立对照，API 缓存价格模型仅用于账单，不能把缓存读取单价比例当成 GPU 成本比例。

压缩在两次调用之间进行，标出首个改变的 token 与仍可复用的前缀。账目包含摘要模型调用、重建 prefill、未来 decode 的历史读取、文件补读和质量变化。借用实验 2-10 的六种策略与原始记录入口；章节中的历史结果与台账中的实际复验范围不能互换。这里不重复 Agent 书的提示词、Skills 和产品教程。

## 两朵云中的三个论文短例

演讲提供问题展开方式：[2026 两朵云](../references/author-materials/2026-09-09/ai-agent-two-clouds-ffa-2026.md)。技术入口采用已公开论文，2026-09-09 核对标题、摘要与版本页面；本次未作全文性能审计，正文不搬加速比例。

- **AOI，3.1.4／12.1.3。** [Agent-Computer Observation Interfaces Enable Dynamic Computer Use](https://arxiv.org/abs/2606.29472v1)。用瞬时弹窗在动作间消失的例子，分开观测与动作频率，记录帧、音频和持久文字的产生、筛选与消费。论文摘要特别指出部分模型加入关键帧会退化，因此不能把“多看帧”当作普遍改进；短例保留事件覆盖与 token 竞争这一反例。
- **Latent Bridge，12.2.3。** [The Latent Bridge: A Continuous Slow-Fast Channel for Real-Time Game Agents](https://arxiv.org/abs/2606.24470v1)。固定快慢模型，比较快模型独立执行、文本交接与学习到的 latent 交接，列出双方周期、状态字节、投影开销与信息过期。论文中模型规模相近，快慢不等于大小；中间通道也不是无需训练的通用特征复制。先判断慢规划能否改善任务，再计协作代价。
- **Programmable KV，8.2.4 的扩写。** [Models Take Notes at Prefill: KV Cache Can Be Editable and Composable](https://arxiv.org/abs/2606.17107v1)。用事实更新区分改旧字段、重建后缀和追加更正；组合缓存单独检查位置及上下文依赖、模型适配与输出质量。普通 KV 不能仅凭 RoPE 重定位就宣称可任意等价拼接。

三个短例各解决一个系统问题，复用现有图与练习；不把整场演讲展开成新的 Agent 章节。

## Groq 的小例子

第 4.6.4–4.6.5 采用[Groq 文章](../references/author-materials/2026-09-09/groq.md)的 KV 容量问题：片上放下权重后，增加上下文与并发，需要多少额外状态、设备和互联。先算容量下界，再检查切分与单序列速度。Groq 规格回既有官方资料，旧文估计售价与理想吞吐不当实测。

早期 FPGA 空间计算经历在已收录的 H100／4090 文章中出现，本轮不重复。该小例子的作用是揭示容量约束，不能仅凭 SRAM 带宽宣布服务成本胜负。

## 技术判断怎样形成

第 5.3.4 采用[MSRA 读博五年（一）](../references/author-materials/2026-09-09/phd-summary.md)“FPGA 编程的挑战”“从 idea 到 system”：先想做接口库，发现 HLS 生成结果达不到所需流水线，再识别可用原语子集与读写依赖，转向代码变换。让读者比较继续封装、改变表示、编译变换三种选择。ClickNP 已有技术案例，此处只补判断转折，不重复项目介绍和求学经历。

第 13.4.1–13.4.2 采用[网络的智能应该放在哪里](../references/author-materials/2026-09-09/network-intelligence.md)的历史“10 年／100 行／1000 台”经验，拆成负载寿命、可实现的热路径规模与摊销部署量。它是当时 FPGA 项目的启发式，不是当代硬件门槛；用本章固定投入与单位节省重新求交点，改变一个变量后允许撤回专用化决定。
