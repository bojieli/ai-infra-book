# RAW 图片精修的传输与计算

本笔记支持第 8 章图片精修、ASR／TTS 与 Computer Use 的对照。图像信息背景在大纲和正文只简述，以下详细输入供实验复算。作者在本次讨论中补充的华为图片精修经历，是“为什么需要传送更大的原图”的历史来源；下列数字是教学输入，不是该服务的测量或内部规格。模型、协议配置、年代与性能在有原始记录后再补。

## 图像信息与任务要求

路径为拍摄 → 原图上传 → AI 精修 → 成片编码 → 下载显示。调整阴影、高光和白平衡需要输入保留相应信息；已经完成色调映射、裁剪和有损压缩的图像，与传感器或较早阶段的数据有不同的编辑余地。不能保证恢复传感器饱和或已经丢弃的信息。

[华为专业模式说明](../references/outline-checks/2026-09-07/edge-media/huawei-pro-raw.html)确认 RAW／DNG 保留更多后期处理信息且占用更多空间；[Adobe Indigo](../references/outline-checks/2026-09-07/edge-media/adobe-indigo.html)说明色调映射前后的像素与编辑差异。两份资料不证明作者历史服务的云端模型、上传格式或传输协议。

RAW 不必是完全未压缩的数据。[Adobe 的 DNG 说明](../references/outline-checks/2026-09-07/edge-media/adobe-dng-compression.html)讨论无损压缩；计算时读取实际文件字节，检查压缩方式与图像管线，不能按扩展名假定固定比例。已经压缩的数据再次压缩能省多少也需要实测。

## 一次完整成片的教学预算

全部使用十进制 MB 与 Mbit/s，假设连接已建立、上传完才执行、结果完整生成再回传、无排队。云端处理包含本例的模型和成片编码，不另加一次同样的编码成本。

| 输入 | 教学值 |
| --- | --- |
| 原图 | 30 MB，例如 20 MP × 每像素一个 12-bit Bayer 采样；实际文件另计压缩和元数据 |
| 成片 | 5 MB，明确指定格式、分辨率和质量，不能仅以文件更小评价 |
| 上行／下行有效传输能力 | 20／100 Mbit/s |
| RTT | 100 ms |
| 云端处理 | 0.3 s |

上传发送时间 `30×8/20=12 s`，下载 `5×8/100=0.4 s`。单请求、单响应的传播合计约一 RTT，得到简化预算 `12+0.1+0.3+0.4=12.8 s`。本地准备、握手、拥塞、重传和排队可能增加时间；允许流水时应按实际依赖重算。

将模型处理加速十倍，只把 12.8 s 降至 12.53 s，节省 0.27 s。仅将上行变为 100 Mbit/s，则为 `2.4+0.1+0.3+0.4=3.2 s`。这些计算用于寻找值得测量的方向，不能证明实际链路一定能达到所给有效吞吐。

若一种无损方案在该输入上实得 2:1，且新增编解码合计 0.15 s，估计 `6+0.1+0.3+0.4+0.15=6.95 s`。2:1 与 0.15 s 均为条件输入；只有省下的传输时间大于新增处理时间，这项改动才有利。先回小预览与交付完整精修图分别计时。

## 从时间差追到协议与执行

上行带宽时延积 `20 Mbit/s×0.1 s/8=0.25 MB`。原图约为它的 120 倍，握手省一次 RTT 与增加长期有效吞吐的收益不同；换为短语音块后需要重新比较。

按 [RFC 9114 §1–2](../references/outline-checks/2026-09-07/edge-media/rfc9114.txt)，HTTP/3 把 HTTP 映射到 QUIC，多流隔离了部分流之间的等待。单个可靠图像流仍需恢复缺失内容，拥塞和路径容量也没有消失。实验应对照默认与充分调优的 TCP 客户端、复用连接与 HTTP/3，并逐项记录窗口、慢启动、丢包与应用处理。

端侧预处理、无损压缩、分块精修与双路径各有独立的收益条件。分块处理需验证图像邻域、全局曝光和模型依赖；双路径要计共享瓶颈、汇合等待、蜂窝流量与电量。不能把文件上传改进泛化成所有 AI 交互的同一加速比。

实验和图计划分别嵌在第 8 章的任务预算、协议、无线和执行位置小节中；语音继续使用 [Queqiao](queqiao.md) 的实际记录。本轮没有运行图片精修模型或网络性能实验。

## Computer Use 的逐轮截图

教学条件取截图 0.8 MB、有效上行 6.4 Mbit/s、上传之外的截图处理／判断／操作／界面更新等合计 2.5 s。先按串行依赖算，上传约 1 s，一轮共 3.5 s；N 轮同条件下约 3.5N s。它不是对某个 Agent 产品的测量，也不能把模型判断时间当成完整轮时。

若截图变为 0.2 MB、编码比基线多 30 ms，同一上行下约为 `0.25+0.03+2.5=2.78 s`，每轮省 0.72 s，30 轮约省 21.6 s。压缩、裁剪和分辨率改变必须保留任务所需文字与坐标；否则新增重试可能吃掉节省。差分传输依赖一致的基准帧，操作结果尚未出现时不能预取未来截图。

实验先固定任务轨迹与成功要求，再分别改连接复用、截图大小、变化区域传输和编码流水；完整原图回退也计入。ASR／TTS 使用 Queqiao 记录，分别衡量识别完成、首段播放、连续供给和打断，三个案例都围绕减少具体等待展开。
