# 模型路由：从 token 单价算到任务成本

对应当前第 11.4.3–11.4.5 节、实验 11-8 与图 11-7；作为既有实验的手算变体。先比较一组完整任务，再改变缓存条件，找出选择翻转的位置。以下 A／B 都是假想服务，数值是教学输入，不代表任何模型、厂商报价或实测表现。

## 给定任务与计费条件

向两个候选分别提交同一组 1,000 个任务，每个任务只调用一次。按同一质量规则判定，假设 A 有 800 个通过、B 有 980 个通过，二者均满足题设的 75% 最低通过率。后面的费用分母是通过任务数，所有失败尝试的费用保留在分子中；没有假设失败后独立重试直至成功。

为便于手算，假设两套 tokenizer 各自计得输入 20,000 token，其中可复用前缀 19,000、新增输入 1,000。现实中应分别读取用量，不能把同一文本长度等同于跨模型相同 token 数。两个服务的缓存各自建立，前缀相同不表示状态能够跨模型复用。

| 教学输入 | A | B |
| --- | ---: | ---: |
| 普通输入单价，费用单位／百万 token | 1 | 2 |
| 缓存读取单价，费用单位／百万 token | 0.1 | 0.2 |
| 计费生成单价，费用单位／百万 token | 4 | 8 |
| 实际思考 token／次 | 1,800 | 100 |
| 可见输出 token／次 | 200 | 200 |
| 通过同一质量判定的任务比例 | 80% | 98% |

约定计费生成已包含思考与可见输出，A 为 2,000、B 为 300 token。公共前缀全命中或全不命中，新增输入始终按普通输入计费；未命中前缀也按普通输入计费。为隔离这几项，本题约定没有额外缓存创建、存储和工具费用，预热费用亦为零。接入真实合同后应补回这些项目。

计费字段必须先去重。Claude 缓存文档将未缓存、创建与命中读取的输入分别计数；Gemini 价格页的生成项包含 thinking。它们支持核对方法，不提供本题数值，也不意味着两家 API 的 usage 字段可以直接通用。[Claude 官方说明](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)、[Gemini 官方说明](https://ai.google.dev/gemini-api/docs/pricing)；已归档的选读范围见[本批记录](../references/interviews/2026-09-08/sixth-pass/reading-proof.json)。

## 单价更高的候选何时更便宜

A 的前缀始终命中，每次花费为 `(1000×1 + 19000×0.1 + 2000×4)/10⁶ = 0.0109`。全部任务花费 10.9，除以 800 个通过任务，得到每个成功任务 **0.013625** 费用单位。

B 命中时每次为 `(1000×2 + 19000×0.2 + 300×8)/10⁶ = 0.0082`；不命中时为 `(20000×2 + 300×8)/10⁶ = 0.0424`。B 的三项单价都更高，但全部命中时每个成功任务只花 **0.00836735**，因为生成量更少且通过任务更多。

令 B 的请求命中比例为 `h`，保持前述用量和质量条件，则每个成功任务的平均费用为：

`C_B(h) = [0.0082h + 0.0424(1−h)] / 0.98`。

与 A 相等时，`h = 1291/1520 ≈ 84.9342%`。低于该点 A 更省，高于该点 B 更省；B 只命中一半时，1,000 次调用花费 25.3，成功任务成本变成 **0.0258163**。这要求比较任务真正消耗的资源和复用条件，不能用最低 token 单价代替决策。

这里 `h` 是请求命中比例。本例每次前缀长度相同，因此前缀内部的 token 加权命中比例也等于 `h`；相对全部输入的缓存读取比例是 `0.95h`。前缀长度不同时要重新加权。公式还假设命中与质量无关；真实回放应逐任务保留联合记录。

## 完成时间改变可选集合

再给定完整请求耗时：A 为 10 秒，B 命中为 4 秒、不命中为 12 秒，均已包含排队和所有生成过程。若业务要求至少 90% 的提交任务同时通过质量判定并在 6 秒内完成，A 不可行；在上述独立性假设下，B 需满足 `0.98h≥0.90`，即 **h≥91.8367%**。费用交点本身不足以满足该要求。

这些耗时是独立的教学输入，不用 token 数除以某个平均速度制造实测延迟，也不将隐藏思考与已包含它的首 token 等待重复相加。扩写实验时用真实框架或 API 的离线记录替换输入，保持任务、模型版本和质量判据对应；尾部要求用完整请求记录验证。
