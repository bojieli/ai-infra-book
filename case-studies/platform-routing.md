## 近期调度研究的落点

### ASI：资源空闲为什么仍然排队

阅读论文的负载分析、§4 碎片整理与 SpotGPU，以及相关评估条件。该研究覆盖六个月、155,410 张 GPU；本章采用其 CPU 配套、成组需求和网络位置共同约束放置的观察。GPU 分配比例从 68% 到 93% 是该部署加入低优先级任务后的分配指标，不能写成算力利用率或 MFU。单卡份额碎片在这份轨迹中影响很小，不据此推广到所有集群。[论文](https://www.usenix.org/system/files/osdi26-li-suyi.pdf)

本书实验从第 6、7 章的模型配置出发，在纸面资源图上比较等待、整理与通信损失，不要求重建其生产调度器。

### RLBoost：额外 rollout 资源的收益上限

阅读 §3–5 的组织、部分响应迁移、权重拉取与 §6 实验设置。论文以 Qwen3 8B–32B、同步 GRPO 和 H100 实例研究稳定训练组与可抢占 rollout 的组合；训练实例为八卡，额外实例为两卡，网络配置不同。迁移保留生成 token，再在接收实例 prefill 重建状态；不能表述成直接搬走完整 KV 或完全没有恢复成本。论文价格按多个云与地区汇总，不能作为今日某一家云的可购买报价。[论文](https://www.usenix.org/system/files/nsdi26-wu-yongji.pdf)

本书计算 `可用窗口 − 权重就绪 − 恢复等待` 之后的有效工作，再检查训练更新是否已成为瓶颈；带工具的 Agent 另记环境状态。

2026-09-09 补读实现、评估和附录，并核对[固定 PolyRL 的权重与恢复路径](preemptible-rollout-and-weight-readiness.md)：前端出口不等于后端网卡总带宽，TP=2 接收路径仍传完整权重，已收到的批量进度也未必全部用于续接。论文 Qwen3-14B 表格与官方配置存在层数／Q 头数差异，计算采用官方固定配置；历史价格保持论文口径。

### DistRS：验证请求与训练批次不是同一种服务目标

阅读 §3 负载、§4–5 设计与 §6 方法。实测对象是 CUDA 代码生成的验证服务：CPU 编译、GPU 执行，不能概括为纯 CPU reward。论文按批次完成约束分配资源，利用历史批次搜索配置，并调整超时带来的偏差。其分离式训练到达模式通过调整原轨迹的批间空隙构造，需要保留这一条件。[论文](https://www.usenix.org/system/files/nsdi26-zhu-ruidong.pdf)

教学算例先给 `T_min = max_i(到达时刻_i + 各阶段执行时间之和_i)`，再加入有限 worker 的排队；这个下界忽略竞争，用于判断可节省的资源，不冒充完整调度解。

2026-09-09 进一步读调度算法与评估，补入[条件剩余时间、最迟启动和固定 verl 入口](reward-deadlines-and-feedback.md)。这一轮将论文的资源节省与训练吞吐分开，并检查逐条评分、排队超时和实际释放之间的实现差别；PolyRL 的文档示例也与 RLBoost 论文配置分别记录。

### SpecBox：利用模型生成期间准备环境

阅读 v2 的设计、实验设置与消融。该预印本利用流式意图和工具切换历史提前准备沙箱；实验为单台 16 核、256 GiB 主机上的 Docker 原型、32 个工具服务和 200 条构造后执行的多轮轨迹，模型经云 API 调用。不是 E2B／Firecracker 的生产测量，也不是任意真实 Agent 的代表分布。[论文 v2](https://arxiv.org/html/2607.23933v2)

书中采用时间重叠与预热浪费的比较；结果复用只在输入、文件版本与状态条件满足时成立。大文件传输与共享内存机制只作为原论文背景，不能移植成跨机器零拷贝承诺。

## 思考、缓存与时间的代表算式

**互斥计费项。** 将每次调用映射到 `未缓存输入 × 单价 + 缓存创建 × 单价 + 命中读取 × 单价 + 计费生成 × 单价 + 另计的存储及工具费用`。不同 API 的 usage 字段可能是包含关系；先归一化，避免把缓存输入或 reasoning 加两次。完整任务费用再加环境和所有失败尝试。

**100 对 1,000 个思考 token。** 教学假设同一任务质量、输入 10,000、可见输出 200、输入／生成单价 $2／$10 每百万 token，思考按生成计费。100 个思考 token 得 $0.023；1,000 个得 $0.032，后者约为前者 1.39 倍，思考部分才是十倍关系。若前者生成速率为 50 token/s、后者为 150 token/s，且 prefill 等共同耗时 1 秒，则简化串行时间分别为 7 秒和 9 秒。速率是教学假设，未对现实模型做等质量测量。

**10 轮公共前缀。** 按 Sonnet 5 上述标准价格作条件计算：每轮公共前缀 8,000、新增且不复用部分 2,000 token，第一轮创建 5 分钟缓存，后九轮均在有效窗口命中。未缓存时输入总费 $0.20；采用缓存时为 `0.024 + 9 × 0.0056 = $0.0744`。此例只算输入，输出、思考、工具和环境另加；没有模拟增长历史全部可复用的情况。缓存创建价格是该部分输入的计费价格，不额外再叠一次标准输入费。

**缓存亲和性与队列。** 同模型两个后端的教学输入：共同网络 50 ms，A 排队 200 ms、命中后前缀处理 50 ms；B 排队 20 ms、未命中处理 500 ms。进入后续生成前分别为 300 ms、570 ms。若 A 队列增长超过 470 ms，此处 B 才更快；后续生成、质量与付费还需继续比较。端到端 P99 不能简单相加各阶段 P99。

最低前缀长度、TTL、前缀一致性和工作区隔离均按具体模型／平台处理；Claude Sonnet 5 当前最低缓存长度为 1,024 token。Gemini 2026-09-02 的缓存文档区分 Interactions 的隐式缓存与 generateContent 的显式缓存，不能混用入口或 usage 字段。来源：[Claude 缓存](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)、[Gemini 缓存](https://ai.google.dev/gemini-api/docs/caching)。

## E2B 的环境生命周期

读取固定提交的架构说明，以及 Sandbox、Persistence 和 Snapshots 文档。公开实现以 Firecracker 恢复模板快照，通过按需页读取和文件覆盖层减少启动时立即搬运；创建 API 返回、首个工具可执行和首次触碰大量数据的耗时分别记录。[固定架构原件](../references/outline-checks/2026-09-07/platform-routing/e2b-architecture.md)

暂停保存文件系统和内存，恢复继续同一个沙箱；快照可派生多个新环境，原环境短暂停顿后继续运行。文档指出快照期间活动连接会断开，客户端需要重连。模板是可重复构建的初始环境，运行快照则含当时状态；RL 的干净重置不等于恢复任意快照。普通工具环境的预算不能当作 GPU 验证资源配置。[持久化](https://docs.e2b.dev/sandbox/persistence)、[快照](https://docs.e2b.dev/sandbox/snapshots)

实验需要在扩写阶段补固定版本、资源配置、时间戳和完整任务记录；没有账号时提供同一记录的离线分析路径。隔离强度不能由性能实验或一次目录清理测试证明。
