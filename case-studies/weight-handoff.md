# RL 阶段切换与权重分发

第 5.4→10.5 的扩写依据，核对日期 2026-09-08。[来源与读取范围](../references/framework-history/2026-09-08/weight-handoff/README.md)保留 2025 年实践、2026 年接口与固定当前实现；本轮只做静态阅读和教学计算，没有运行模型或 RL 训练。

## 能放下两个阶段，还要能完成交接

SGLang 团队 2025 年的实践文章从重启引擎、磁盘加载，讲到保留虚拟地址的内存暂停，最后按权重与 KV 分阶段唤醒。vLLM 的 2025 年 Sleep Mode 文章也解释保留进程、编译与图执行准备的价值。它们处理的是每轮反复发生的切换；历史文章的模型、硬件与速度不能直接迁移到当前实验。

沿固定 [Qwen3-8B 配置](../references/outline-checks/2026-09-07/scaling-history/qwen3-8b-config.json)，把未共享的 embedding／输出头、36 层 attention、门控 MLP、归一化参数相加，得到 **8,190,735,360 个逻辑参数**。BF16 原始权重为 16,381,470,720 byte，即 **15.2564 GiB**。这是矩阵与向量计数，不包含对齐、量化元数据、运行时派生状态和内存分配开销。

教学假设：每卡本任务可用预算为 64 GiB，训练驻留状态 40 GiB，rollout KV 池 24 GiB，共有运行时与工作区 4 GiB。训练状态的 40 GiB 是给定输入，必须由所用训练后端的 trace 校准，不能只从 8B 参数数推出来。

训练独占时是 `40+4=44 GiB`，rollout 时是 `15.2564+24+4=43.2564 GiB`，都能放下。但若训练状态还在就恢复完整 rollout，交接峰值变成 **83.2564 GiB**。先恢复推理权重，完成同步，再释放或换出训练状态，最后恢复 KV，峰值则为 `max(40+15.2564+4,15.2564+24+4)`，即 **59.2564 GiB**。腾出的显存来自执行次序；主机容量、换出链路和实际缓冲仍需满足约束。

保留虚拟地址有助于继续使用兼容的 CUDA Graph，但新映射的物理内存没有自动恢复内容。vLLM level 1 备份旧权重，level 2 丢弃权重并保留声明范围内的模型 buffers；KV 都需按路径重建。若旧权重之后必被完整替换，按假设的 25 GB/s 有效带宽，备份再恢复这份 BF16 权重仅载荷就需 **1.31 秒**，可能是可以省掉的工作。

能否省掉取决于谁会重新写回状态。已读固定 verl 的 vLLM 路径在 MTP、LoRA 等条件下选择较浅 sleep；actor 同步未必包含起草器独有权重，adapter 同步也不包含完整基座。SGLang 集成的 adapter 路径保留基座驻留，并按模式选择 CPU backup 和释放标签。两者不能按同名“休眠”推定相同内存收益。

## 权重更新也是一次并行布局转换

vLLM 2026 年原生 RL API 将同步拆为初始化、开始、分块传输和完成后处理；NCCL 广播、同设备 IPC 与后来加入的 Sharded RDT 是不同传输路径。IPC 避免绕经磁盘，不代表没有本地复制；传入 BF16 权重后也可能还有量化、重排及内核专用状态的恢复。

用[固定 Qwen3-235B 配置](../references/outline-checks/2026-09-07/scaling-history/qwen3-235b-config.json)只算 routed experts：每个专家的三块矩阵为 `4096×1536`、`4096×1536`、`1536×4096`，BF16 共 36 MiB。94 层、每层 128 个专家，共 **423 GiB**。在均匀 EP16、每专家无冗余副本的教学配置下，每 rank 每层保留 8 个专家，合计 **26.4375 GiB**。

若每个消费者接收全体专家后再丢弃不属于自己的部分，其每 rank 接收量是 423 GiB；按需发送则为 26.4375 GiB。假设每消费者独享 25 GB/s，接收端下界从 **18.17 秒**降为 **1.14 秒**。但若 8 个生产端各只有 25 GB/s 且共同承担全部专家载荷，生产端聚合下界为 **2.27 秒**，已比后者更高。这些只是该专家子集的带宽下界，未计训练侧 gather、CPU 调度、拥塞、复制和后处理；不据此宣称 16 倍服务加速。接收量之和也不能直接当作广播树每条网络链路的载荷。

attention、embedding 与输出头另算：DP／EP 下可能复制，TP 下还要检查 GQA 复制和切片规则。不能把整个模型的全部权重一律除以 EP16。Sharded RDT 的已读机制通过实际 weight loader 记录切片计划，并按所有权选择生产端；固定指南仍限制支持的 loader 操作，并拒绝会改变专家位置的 EPLB，不能直接拼接上一案例的动态重配。

## 流水线先算缓冲，再算重叠

一层的全部专家是 **4.5 GiB**；若某路径同时完整重组两层，单份工作集合已为 9 GiB。保留 PP／EP 本地所有权可以减少不必要的重组。接收侧若按本 rank 一层 288 MiB 的专家分片设计两个槽，看起来只需 **576 MiB**，但这还不是足够的通用缓冲预算。

同一模型的 `151936×4096` BF16 embedding 就有 **1.1592 GiB**。若某 worker 在该布局下完整接收它，且单次原子切片不能再拆，两个接收槽至少要 **2.3184 GiB**。固定 RDT 指南明确要求按最大原子切片确定缓冲；这些缓冲还在引擎常用内存利用率预算之外。实验需同时记录传输槽、层级 reload 缓冲和最终参数，避免将它们混成一份。

流水可以让下一层 gather、当前层传输与上一层后处理交错，实际周期由最慢阶段和共享资源决定。官方 2026 文章的 Qwen3-235B 案例展示 PP／EP 本地提取、再加入流水的演进；保留其具体切分作阅读对照，正文用上述矩阵与链路预算引出设计，不套用历史速度。

## 放回真实训练循环

暂停调度、释放显存与完成权重更新分别确认。已读 vLLM 文章解释 DP／EP 各 rank 若停在不同集合通信中会无法交接；固定 verl 使用引擎级调用覆盖 DP 进程，不能以单个 TP worker 的 RPC 返回代替全部就绪。SGLang 的 `retract` 允许退回等待队列后重建 KV，`in_place` 则依赖旧 KV，二者适用情形不同。

固定 verl V1 指南继续说明部分轨迹保留 token 和行为 logprob，换版本后重建 KV；跨角色异步还需样本版本与准入规则。这里沿用[状态与概率身份](rl-state-and-reproducibility.md)，不把“引擎恢复”当作整个 RL 系统的可复现性保证。
