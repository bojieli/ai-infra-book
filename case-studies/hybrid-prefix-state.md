# 混合模型的前缀状态与恢复成本

2026-09-08 的扩写笔记，落在 2.4→8.2→9.5；本轮深化既有 8.2.4／8.2.5、实验 8-4 和图 8-3。先算同一模型的状态，再解释三个框架怎样选择恢复位置。以下为教学预算，没有运行模型或测得服务性能。[版本原件与读取范围](../references/framework-history/2026-09-08/hybrid-state/README.md)单独保存。

## 从一个当前状态到多个可恢复的前缀

第 2 章的 K3 配置包含 69 个 KDA 层和 24 个 MLA 层。KDA 每层 96 个头、每头 128×128 的递推状态，短卷积宽度为 4。采用 SGLang 固定部署计算器中的 FP32 递推状态、BF16 短卷积与紧凑 MLA 缓存；TP=8，注意力头均分，没有 DP attention、DCP、PP、推测草稿或额外检查点量化。这是一条指定执行路径的有效载荷，不能代替所有后端的分配报告。

先在模型逻辑范围计算一份 KDA 检查点：

- 递推矩阵：`69 × 96 × 128 × 128 × 4 B = 414 MiB`。
- Q、K、V 三路短卷积各保存前三个位置：`69 × 3 × 3 × 96 × 128 × 2 B = 14.5546875 MiB`。
- 合计 **428.5546875 MiB**，按上述 TP 切分为 **53.5693359375 MiB／卡／检查点**。

同一路径的 MLA 历史为 `24 × (512 + 64) × 2 B = 27 KiB/token`，在注意力 TP 组内复制，不能再除以 8。8,192 个历史 token 为 **216 MiB／卡**；八卡合计为 1,728 MiB。这里的 64 维分支按固定实现保留，不能从 NoPE 名称把它删去；第 2 章另列的展开式参考实现也不能混进此处的容量计算。

对一个 8K 前缀，假定实际物化并保留每个正整数间隔边界，零位置使用空初始状态，则：

| 保留间隔（token） | 检查点份数 | KDA 检查点载荷／卡 |
| --- | ---: | ---: |
| 4,096 | 2 | 107.138671875 MiB |
| 1,024 | 8 | 428.5546875 MiB |
| 256 | 32 | 1,714.21875 MiB，约 1.674 GiB |

这是同一条前缀的保留策略对照，不是框架默认间隔。32 份快照比该前缀的 MLA 历史还大得多；“循环状态不随上下文增长”描述一份状态，不能推出保存任意历史边界也只占一份。共享祖先只计一次；活动请求槽位若与快照共享，应按实际所有权去重，否则另计。分配器对齐、图缓冲、权重、推测中间状态和工作区仍占用其他容量。

## 文本匹配的位置与能够恢复的位置

教学轨迹给两个请求相同的前 10,752 个 token。全注意力内容已经就绪，但 KDA 仅在 4,096 和 8,192 处保存了兼容快照。因此只能从 **8,192** 恢复，尚需重算 **2,560** 个已匹配 token。这里没有将 2,560 token 换算成固定毫秒；其矩阵形状、历史注意力与分块位置决定实际时间。

再把前缀哈希粒度设为 256、物理分配块设为 4,096。这两个数用于说明分工，不声称是 K3 的默认配置。10,752 虽然是哈希边界，但更细的查询键不会生成缺失的递推状态。只有在该位置实际留下快照，并确认其他状态也可用，才能从那里继续。物理分配、匹配粒度与执行时保存检查点的边界分别检查；恢复前还要让共享的可变状态获得私有写入位置。

这也是 vLLM 当前协调器需要复核所有状态组、SGLang 统一树需要逐组件确认候选位置的原因。滑窗只保留尾部，循环状态只在已保存的位置有效，不能把每组“最深命中”的数值简单取小就结束检查。Ollama 的固定 MLX 路径同样要求每个有状态层具备对应快照；在 trie 中切出一个节点，并不能从后来的递推状态反推出那个中间时刻。

## 用再次出现的前缀决定保留位置

vLLM v0.5.5（2024）的 APC 文档以全前缀哈希映射不可变 KV 块。Marconi（MLSys 2025）把问题推进到混合状态的准入和淘汰；2026-06-10 合入的 vLLM PR #37898 明确采用 Marconi-style 准入。它借全注意力已命中、循环状态未命中的差别发现公共前缀，与论文的 radix 实现不同。随后合入的稀疏保留、共同边界处理和部分块机制，使它能够在更细的位置恢复，而不必同等缩小物理分配块。

沿三个 Agent 请求演示：第一次只保存自身提示末尾；第二次发现一个被共享的内部前缀，执行到那里时才留下状态；第三次才可能直接受益。再与定期间隔、每轮提示末尾、常用分支边界比较。缓存收益由再次访问机会、省下的实际前向工作、增量驻留与复制／取回开销共同决定。源码里的策略名称不代表在所有后端、压力和连接器组合下自动生效。

SGLang 2026 年的 Unified Radix Cache 将共享前缀身份与状态复用条件分开：K3 组合全历史和 KDA 检查点；V4 组合完整路径与滑窗语义，压缩池等跟随相应状态搬移。Ollama 2026 年 6 月的 MLX 文章则用 Agent 分支、删除旧 reasoning 和重试解释选择性快照；本轮核读的 recurrent cache 路径明确假设 batch=1，不能据此断言 Ollama 已能服务完整 K3，或把本地能力等同服务器批处理性能。

第 9 章将同一问题移到 CPU／远程池时，先确认可恢复的共同边界，再算取回与排队。更长的外部命中还需要协调本地部分尾块的所有权及状态就绪；元数据查到一段前缀，并不代表字节和检查点已经可以交给下一次前向。
