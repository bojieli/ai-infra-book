# 从内核瓶颈到训练产出

2026-09-08 的编辑与实验笔记。只补已有小节和实验变体：第 4、5 章把注意力的代际演进算到片上资源；第 8 章确认框架实际执行路径；第 10、13 章把程序效率接到训练完成时间。本轮没有运行 GPU 性能或训练实验。

## 注意力的瓶颈怎样随硬件改变

已读 [FlashAttention-4 正式会议稿](../references/proceedings/MLSys/2026/papers/mlsys2026-ae8b0b5838ba510daff1198474e7b984.pdf)物理页 1–12，涵盖硬件分析、前向、反向、评估与限制；其余参考文献未逐项阅读。官方目录归属 MLSys 2026，PDF 首页页脚误留 MLSys 2025 模板，引用按官方目录记，不修改原件。以下复算正文表 1，不由曲线截图估读速度。

先用第 2 章 Qwen3-8B 的 head dimension 128，取一个 `M=N=d=128` 的 BF16 attention tile。这里只计算 QKᵀ 与 PV，不包括投影层。采用论文 B200 分析中的单 SM 输入：矩阵单元每周期 8,192 FLOPs，指数单元每周期 16 个结果，共享内存每周期 128 字节。共享内存数字是作者测量采用的输入，不能写成整卡 HBM 带宽。

| 资源 | 本 tile 的需求 | 最少周期 |
| --- | --- | --- |
| 矩阵单元 | `4MNd = 8,388,608 FLOPs` | `4MNd/8192 = 1024` |
| 共享内存读取 | QK 的两个操作数及 PV 的 V，共 98,304 字节 | `3MNd/8192 = 768` |
| 指数单元 | `MN = 16,384` 次 | `MN/16 = 1024` |

共享内存算式限定论文的 128×128 MMA 指令形状、维度为 128 的倍数，以及 QK 从共享内存读两侧、PV 从 TMEM／共享内存分别读 P／V 的安排。扩大 tile 后，同一操作数可能被多条 MMA 指令重复读取；不能用一次从 HBM 载入的字节替代这里的读量。

三项资源下界的最大值是 1,024 周期。假想只把矩阵吞吐再提高一倍，矩阵部分降至 512，指数部分仍是 1,024；瓶颈未被移走。把 M 改为 256，三个下界分别是 2,048／1,536／2,048，也不能仅凭 tile 变大就断言更快。它们是稳态资源下界，实际延迟还受依赖、流水填充排空、寄存器、L2、调度和同步影响；不是本书实测周期，也不是 Hopper 和 Blackwell 的整核实测对照。

用这个计算解释 FA3 到 FA4 的延续与变化：矩阵能力增长使矩阵与 Softmax 的交接更重要，FA4 利用 TMEM 中的中间状态安排两个 tile 交错，并给修正操作独立安排执行资源。部分指数由普通算术单元分担，能缓解特殊函数单元压力，却会增加指令、寄存器和数值误差。前向节讲到这里即可；反向的 2-CTA 共享、跨 SM 交换和 dQ 归约只作实验分析的延伸，不再扩成代码教程。

原论文评估使用 B200、BF16、总 batch token 数 32K，并扫描序列长度和头维度；其中旧 DeepSeek 形状只是历史实验条件。不能把注意力内核的峰值比例当作整模型 MFU，或外推成 batch=1 decode 的请求加速。确定性反向还要固定归约顺序，存在额外等待；近似指数也要单独检查数值误差与任务质量，不能称为逐位相同。

## 从算法名称到实际后端

[固定实现与文档](../references/framework-history/2026-09-08/attention/README.md)保留三个层次：上游 CuTeDSL 内核、服务框架 wrapper、实际选择条件。源码只阅读所记范围，不表示三套框架全量代码已读。

- **vLLM**：先选 attention backend，再由该 backend 决定具体 FA 版本。固定提交中的 `FLASH_ATTN` 路径在支持时为 SM90 优先选 FA3、SM100 优先选 FA4；但 Blackwell 普通注意力的框架默认优先表把 FlashInfer 放在前面。ALiBi、head dimension、量化 KV、batch invariance 等还会触发不同限制或回退。因此“在 B200 上运行 vLLM”并不证明该请求使用 FA4。
- **SGLang**：同一实例可以把 prefill 和 decode 交给不同后端，目标验证的后端另受 speculative attention mode 控制。固定实现还把图状态与元数据交给对应执行者。它调用自己的 FA wrapper；其中确定性开关与 vLLM 的回退处理不同，不能把一个项目的限制推广到所有同名 FA4 实现。
- **实验安排**：沿实验 4-1 的资源计算，在实验 5-3 加一个可选 GPU／trace 对照；再让实验 8-2 固定模型、精度、页大小和请求，记录 prefill、decode、验证实际后端、FA 版本、图模式、回退与独立阶段时间。只切换经检查可比的一项；若两条路径不能共享相同配置，就记录约束，另设对照而不宣称单变量加速。

上游 FA4 README 说明目前覆盖 Hopper 与 Blackwell；不代表论文中的 B200 专用设计直接覆盖每条代码路径。框架 current 文档是获取日快照，真正实验以固定提交、安装依赖和运行日志为准。

## 已分配的卡怎样变成保存下来的训练进展

已读 [Machine Learning Fleet Efficiency](../references/proceedings/MLSys/2026/papers/mlsys2026-fbe2b2f74a2ece8070d8fb073717bda6.pdf)物理页 1–11，重点为 §3.2 的定义和 §4 的生产分析。论文在 Google TPU 资源池提出 MPG；下面改编为同型 GPU 资源池的教学数据，不是 Google 测量，也不声称所有训练平台已经实现该指标。

让读者沿一次固定模型与训练目标的 Qwen3 运行，先看四种 GPU 时间，最后才给指标名字。假定资源池有 100 张同型卡，观察 1 小时；作业可由多个同步训练组构成。

| 时间范围 | 教学观测值，GPU·秒 | 解释 |
| --- | --- | --- |
| 资源池容量 C | `100×3600 = 360,000` | 全部可供使用的设备时间 |
| 单卡分别显示已分配 | 350,000 | 分配率约 97.22%，但同一作业的其他卡可能尚未就绪 |
| 每个训练组所有必要资源同时就绪 A | 300,000 | 按组宽度累加可以同步前进的区间 |
| 已保存训练进展对应的执行 G | 240,000 | 扣除初始化、编译、供数、保存停顿，以及故障后丢失的工作 |
| 同一进展的理想计算时间 I | 120,000 | 固定模型数学工作量、形状及各精度峰值后得到的计算基准 |

由同一批区间得到 `SG=A/C≈83.33%`、`RG=G/A=80%`、`PG=I/G=50%`，相乘为 `I/C≈33.33%`。97.22% 的单卡分配率不能直接与 50% 的程序效率相乘，遗漏的既有组不齐的等待，也有没有保存为训练进展的工作。提高内核性能、减少启动恢复和改善成组分配，影响的是不同部分。

RG 的分母严格沿用 SG 的“所有必要资源同时就绪”分子，不是上表 350,000 的单卡占用时间。跨作业汇总必须先按一致定义累加这些设备时间，再做比例；不能把各作业百分比的简单平均相乘。跨硬件、精度或负载比较时先分组，不能把作业组合变化误认为硬件或编译器退化。

论文 PG 使用未优化 HLO 的数学工作量与计算峰值作为固定参考，目的是让融合、重计算或布局变化后仍可比较程序完成时间。这是**仅按计算构造的参考值**，与本书用于定位 HBM、共享内存、网络瓶颈的多资源下界用途不同。带宽主导的 decode 即使已接近可达到的速度，计算指标也可能很低；低 PG 不能直接解释为 GPU 空闲，不能要求任何工作负载都达到 100%。PG 也不自动等于每个框架日志中的 MFU，必须核对分子与计时范围。

训练实验 10-10 增加上述观测记录的变体，让读者从稳态完成时间补回日历损失；第 13.1.2 回收这个例子，决定先优化哪一段。RL 另看有效样本及质量，在线服务另看满足质量与 SLO 的请求，不能把 checkpoint 口径硬套到推理吞吐上。
