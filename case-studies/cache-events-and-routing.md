# 缓存事件与路由判断

第 10.5 节的扩写与实验依据，核对日期 2026-09-08。沿用[缓存取回案例](cache-tiers-and-routing.md)的 Qwen3-8B 前缀，只增加一个问题：路由器看到的缓存位置，是否仍能兑现为节省的时间？[归档与读取范围](../references/framework-history/2026-09-08/cache-events/README.md)分别记录固定源码、集成指南和发布元数据；本轮未运行推理服务。

## 从框架保存状态到路由器使用状态

SGLang 2024 的近似路由树、2025 的 HiCache，以及固定当前 Model Gateway 的文本匹配，是已有案例的演进线。本轮补查另一条明确的集成：Dynamo 消费 worker 的分层事件；在满足配置条件时，SGLang HiCache 的共享 Mooncake 池还提供对象事件。不能把这个消费者的能力归到普通 Model Gateway，也不能因引擎支持 CPU 卸载就推断外部路由已看见 CPU 命中。

固定 Dynamo 指南要求 vLLM 原生 CPU 路由集成使用 vLLM 0.24.0／Dynamo 1.3.0 及相应自描述事件配置；发布元数据分别记录 2026-06-29 和 2026-07-22。SGLang 指南要求具备 0.5.11 引入的 host 事件，并另列 Mooncake 事件和布局条件。日期用于确定版本范围，不能证明每种部署组合都已验证。

两条后端路径支持范围不同。已读固定 vLLM 集成对 CPU 路径给出验证范围，对磁盘仍保留限制，共享池尚不支持；已读 SGLang 集成能配置 Mooncake 共享池，但事件晚于已有对象开始订阅时，池索引会先漏掉旧对象，序列缺口会清空索引。指南还明确不支持 DCP 与该共享池索引的组合。实验选择一种满足条件的后端，正文只讲这些差异如何改变可用路径。

GPU→CPU 异步拷贝完成后才报告 CPU 驻留。一个块可以同时在两层，`remove(GPU)` 不代表 `remove(CPU)`。事件包含位置与块身份等元数据，不携带整个 KV 载荷；恢复位置索引也不等于恢复丢失的 KV。模型、请求附加身份和缓存布局的兼容仍由相应系统保证，路由的近似评分不能代替 worker 的实际复用检查。

## 缓存过期怎样改变选择

沿用 TP=1、BF16、8,192-token 前缀，总 KV 为 1,207,959,552 byte。以下时间均为教学假设，和既有案例仅改变 A 的等待：A 最早在 80 ms 执行；B 等待 20 ms 后重算 180 ms，首 token 为 200 ms。有效前缀命中后的剩余工作为 10 ms。

A 真有可用 HBM 前缀，首 token 为 **90 ms**；若各层都已失效，首 token 为 **260 ms**。假设从实际记录校准出可复用概率 `p`，并暂用这两个固定结果近似，则 A 的期望为 `90p + 260(1−p) = 260−170p` ms。平均时间优于 B 需要 `p > 6/17 ≈ 35.29%`。

取 `p=90%`，平均值为 **107 ms**，但 10% 请求仍要 260 ms；在这个两点分布中，A 的 p99 是 260 ms，无法满足假设的 220 ms 目标，B 的固定 200 ms 可以。实际分布中的排队、淘汰与负载可能相关，实验应按请求记录复算。Dynamo 的 host hit weight 是路由评分的系数，既不是这里的概率，也不是以毫秒为单位的取回预测。

如果 CPU 副本还在，情况又不同：25 GB/s 的有效 host→GPU 带宽给出 **48.32 ms** 传输时间。假设取回可从到达起执行，并与 80 ms 等待重叠，A 仍是 `max(80,48.32)+10=90 ms`；若必须等调度后才开始拷贝，就成为 **138.32 ms**。先确定真实依赖，再使用 `max` 或相加，不能把一个 GPU 淘汰事件直接记作全部重算。

## 事件缺失与尚未完成的前缀

已读 vLLM 发布器用有界队列保存已发布的事件批次供重放；当前默认容量是 10,000 批次，单位不是 token 或请求。若教学输入稳定为每秒 2,000 批，只覆盖约 5 秒，突发流量会缩短时间窗口。消费者必须知道自己的连续进度，以及可重放范围是否仍覆盖缺口。

已读 Dynamo 恢复状态机在可恢复的初始接入和序列缺口处请求完整状态，期间缓冲新事件，再依 watermark 衔接后续事件；局部索引维护树和事件缓冲。源码明确多层快照不是同一时刻的原子快照，要靠后续事件重放收敛。这里只读了声明的局部路径，不能据此保证任意故障下都无损恢复，更不能把索引恢复当作 KV 数据恢复。

Agent 的并发分支还有相反的空窗：首个请求已经选定 worker，却尚未完成 prefill，真实缓存事件还没有发布。固定 Dynamo 配置提供可选的短 TTL 预测树，按路由决定暂记前缀，与事件树分别保留。这样可以减少分支被分散的机会；取消、失败、同批尚未完成的前缀和额外排队仍会影响收益。实验需检查实际重复 prefill 与首 token，不能从“都去了同一 worker”直接推出“都命中了缓存”。
