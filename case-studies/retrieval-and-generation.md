# 检索与生成的协同预算

核对日期：2026-09-08。用于第 13.1／13.4 和既有实验 13-1、图 13-1；它回收第 2 章矩阵、第 9 章请求与第 6／7 章的数据通路，不增设 RAG 专题。论文与读取范围见 [ASPLOS 2025 阅读记录](../research/2026-infra-survey/reading-asplos-2025.md)。本节数字由配置和声明假设推算，尚未运行检索／模型实验。

## 检索选择会改变下一阶段的工作

[Accelerating Retrieval-Augmented Generation](../references/proceedings/ASPLOS/2025/public/iks-v1.pdf)给出的启发是：检索与生成应在相同回答质量要求下比较。较慢的检索若能用较少文档提供有效证据，可能节省更多生成工作。精确最近邻只保证所选向量度量下的结果，不能保证证据真实、文档相关或回答正确；需要逐任务检验。

论文使用 NQ／KILT、BERT 检索器、微调 T5 和 4-bit Llama 3，生成质量分别采用 exact match 与 Rouge-L recall。不同指标的分数不能互相排序。图 2 的不同文档数、检索配置与吞吐提供历史观察；本书用 Qwen3 重新计算资源，不能移植其质量关系。

固定 [Qwen3-8B 配置](../references/outline-checks/2026-09-07/scaling-history/qwen3-8b-config.json)，batch=1、无前缀命中。教学输入为 512 个问题／模板 token，每篇文档恰好 128 token。假定一项质量实验筛出了两个合格候选：A 返回 8 篇，检索用时 200 ms；B 返回 32 篇，检索用时 20 ms。这四个数是教学条件，实际实验需要重新获得。

| 量 | A：8 篇 | B：32 篇 |
| --- | ---: | ---: |
| 输入长度 | 1,536 token | 4,608 token |
| BF16 KV | 216 MiB | 648 MiB |
| 各层线性矩阵工作 | 21.337 TFLOPs | 64.012 TFLOPs |
| 因果注意力有效配对工作 | 0.696 TFLOPs | 6.263 TFLOPs |
| 按假设有效 200 TFLOP/s 换算的 prefill 工作时间 | 110.168 ms | 351.378 ms |
| 检索＋上述 prefill 估计 | 310.168 ms | 371.378 ms |

线性矩阵来自 36 层的 Q、K、V、输出投影及三块 FFN 矩阵：令 `d=4096`、`d_kv=1024`、`f=12288`，其参数数为 `36 × (2d² + 2d·d_kv + 3d·f) = 6,945,767,424`。输入 T 个 token，矩阵乘法为 `2T × 参数数`；QK／PV 的因果有效配对为 `36 × 4d × T(T+1)/2`。KV 按每 token 144 KiB 计算。

这是主要矩阵的工作模型，未计 norm、激活函数、位置处理、输出头、padding 和内核实际执行的额外配对；有效计算速率也是假设，不能将该列当作实测 TTFT 或完整性能下界。检索、取文档、tokenization、排队、host→GPU 交接和采样都要补入完整时序。输出阶段则另算，每个 decode 步读取的既有 KV 也会随输入增长。

在这个模型里，A 多花的 180 ms 检索时间，小于节省的 241.210 ms prefill 工作时间，故顺序执行的估计提前 61.210 ms。若其他条件不变，prefill 的假设有效速率提高到约 268.011 TFLOP/s，二者相等；继续提高后选择会翻转。缓存命中、文档顺序、批处理和到达分布同样可能改变结论。这个练习训练的是找出选择边界。

## 数据在哪里，决定该把什么工作搬过去

IKS 把向量扫描与局部 top-K 放到存储侧，主机发送查询并归并局部结果。用独立的教学输入算这条路径：`2^25` 个 768 维向量、每维 2 byte，共 **48 GiB**。一次扫描的点积工作约 51.540 GFLOPs；不计额外读写时，batch=1 的向量主导强度约为 1 FLOP/byte。若 16 个查询能共享一次扫描，点积工作增加 16 倍，语料读取保持一遍，强度约为 16 FLOP/byte；等待凑批和 top-K 工作另计。

若这些向量都须经过假设有效 64 GB/s 的主机链路，单遍供数约需 **805.306 ms**。若具备所需计算与数据格式支持的存储侧单元可用假设有效 1 TB/s 内部带宽扫描，供数时间约为 **51.540 ms**。八个分片各接收一份查询并返回 32 个 `(score, id)`，按 4-byte score 与 8-byte id 算，查询共 12,288 byte，返回共 3,072 byte；这些是逻辑载荷，未计协议、同步、对齐和主机归并。

不能把两项供数时间直接当作系统加速比。向量计算、top-K、分片中最慢者及共享内存争用均可能限制收益；索引更新也要考虑布局和一致性。IKS 的论文讨论明确指出，全库扫描可能拖慢其他使用同一扩展内存的应用。第 13 章据此比较独立加速与共享容量的收益。

## 用真实系统检验选择

实验 13-1 的选做变体使用 Faiss 的 Flat 与 HNSW 检索结果，送入固定 vLLM 或 SGLang 上的同一 Qwen3。先固定语料、embedding 模型、度量与归一化，再扫描文档数和检索参数；记录回答质量、检索耗时、token 数、prefill、KV 和最终完成时间。基础路径可分析配套记录，实测规模由设备容量决定。

当前 [Faiss 索引说明](../references/proceedings/ASPLOS/2025/public/faiss-faiss-indexes.md)列出的普通 `IndexFlatIP` 使用每向量 `4d` byte；[选择指南](../references/proceedings/ASPLOS/2025/public/faiss-guidelines-to-choose-an-index.md)还强调建索引成本和 HNSW 的空间开销。因此上述 2-byte 存储教学例不能作为默认 Faiss 的内存估计：同样的向量数用 FP32 Flat 需要 **96 GiB**，HNSW 还要增加图结构。用压缩索引时同时重新测精度和访问量。

IKS 是采用 RTL 参数、周期近似模拟器及软件模拟接口评估的研究系统。已读作者 v1 物理页 1–13，图 2、图 5 已查看；第 14–18 页参考文献未读。原稿摘要与结论的加速范围、ANNS-2 的 `efSearch` 标注、MAC／FLOP 口径及 H100 峰值表示存在不一致，均不作为本书的性能数字或硬件规格。记录见 [iks-reading.json](../references/proceedings/ASPLOS/2025/iks-reading.json)。
