# 流式交接的顺序与缓冲

第 5.2 节与实验 5-2 的扩写依据，核对日期 2026-09-08。[StreamTensor 公开稿](../references/proceedings/MICRO/2025/paper-014.pdf)的物理页 3–14 已选读，设计、评估与边界见[阅读记录](../references/proceedings/MICRO/2025/streamtensor-reading.json)。本例补充现有的[容量、布局和数据复用](buffer-capacity-and-data-movement.md)：省去中间写回以后，仍要让生产顺序、消费顺序和缓冲容量彼此兼容。

## 形状相同，还要看访问顺序

StreamTensor 的类型同时表达分块形状、遍历顺序和重复访问。两个接口都写着相同的完整张量形状，并不足以说明 FIFO 可以直接相连：生产者先输出的块，可能不是消费者先需要的块。布局转换需要缓冲；若希望继续消掉转换内部的 FIFO 和重复缓冲，匹配条件还会更严格。

它把分块、融合、资源分配分为相互反馈的选择；FIFO 的初始延迟和生成间隔来自厂商 HLS 工具的 profile。这支持第 5 章已有的方法：先保证变换语义，再取得会影响决策的成本反馈。它没有证明所有 GPU 内核都能照此融合，也没有使真实测量变得多余。

## 从五个块数出峰值

从前文 Qwen3 投影输出中取五个 `[64,128]` BF16 块，每块 **16 KiB**。显式给定生产完成时刻为 4、5、6、7、8，消费取走时刻为 5、7、9、11、13；单位是教学时间格，不是 GPU 时钟。消费发生在这一格开始，生产在结束，允许同一格释放后再写入。记累计生产 P(t)、累计消费 C(t)，FIFO 占用为 `P(t)-C(t)`。

逐格计数，时刻 8 已生产五块、取走两块，峰值为三块，即 **48 KiB**。这是维持这份既定生产进度所需的容量；不是任意调度的最小缓冲。若允许生产者因背压停顿，较小 FIFO 也可能完成，而完成时间是否增加要沿消费者和下游依赖重新算。

再假定布局转换采用完整块的 ping-pong 实现，每个槽 16 KiB，两槽另占 **32 KiB**。为保持上述并行进度，交接部分共需 80 KiB；若只剩 64 KiB 可用，这个方案已经不可行。统一两侧布局后可以去掉这份转换缓冲，但生产者或消费者可能增加指令。这里固定的是所选实现，未声称 32 KiB 是所有布局转换的理论下界。

计数时分别登记 FIFO、重排缓冲、算子内部输入与累加器；同一物理存储确实可复用时才合并。对于分支再汇合的图，还要检查等待另一条输入是否阻止上游继续生产；单条边的占用上界不能替代整图的进展分析。

## 保留怎样的实验结论

论文在 AMD U55C 与 Vitis 2024.1 上测量生成的设计；GPT-2 的 FPGA 路径为 W4A8，对照 GPU 为 W8A8，旧 FPGA 对照还包含 FP16。它将一个 Transformer block 放到 FPGA，反复换参数执行多层；不是整模型的所有层同时驻留。动态形状依赖上界提示，运行时控制流可能回退到主机。表中 TTFT 与 decode 方向也不同，因此不把整体比值写成 FPGA 普遍优于 GPU。

正文沿用实验 5-2 的融合选择，增加上述五块计数作为选做变体；让读者改变消费间隔或允许背压，判断最初的容量排除是否仍成立。图 5-2 用自绘累计生产／消费曲线标出两者最大差值，再标重排槽的独立占用。现有 GPU 实验仍测真实内核的读写和同步，不将教学时间格标成硬件实测。
