# vLLM 启动与编译缓存的历史对照

归档日期 2026-09-07。六个文件的 URL、固定提交和校验值见 [sources.json](sources.json)。

- [论文工具说明](profiler-readme.md)固定 vLLM **0.10.1.1**，获取提交 `8a4a6f28a9e840185d3b1657957d4c64781988cb`。已读 README 的准备、实验和复现说明；这是历史实验栈，不覆盖当前模型与后端。
- [打点部署脚本](profiler-apply.py)已读完整代码：直接替换安装路径中的五个 vLLM 文件。归档用于理解历史计时，本轮未执行；后续实验在独立环境使用同版本，不能将替换脚本直接套到新版本。
- [日志分析](profiler-log.py)已读第 34–68、138–184 行，并检索打点字段。其 `kv_cache_profiling` 减去嵌套的编译时间，`total_time` 又使用包含子阶段的 `init_engine`；`actual_total_time` 来自日志首尾。三种值有不同含义，不能把所有字段相加或把日志首尾自动当作请求可服务时间。论文还做了关闭编译的阶段对照，应一并保留。
- [当前编译设计](vllm-compile.md)固定 vLLM 提交 `51da0ca66c8065619c79e35dff97aa99aeaf5644`，已读正文。编译缓存按相关配置、PyTorch 配置与被跟踪代码区分；形状专门化的 autotuning 会增加准备成本；编译规格与 CUDA Graph 捕获规格分开。文档先用 piecewise 示例说明，后面另列 full graph 条件，不能将示例当成所有后端的唯一模式。

当前设计文档只能证明该提交的机制。论文版本曲线、文档所举早期模型和当前框架行为分别记；尚未完成 vLLM 全版本历史研究。选入 10.6 的[算例与采用边界](../../../../case-studies/moe-and-startup.md)，并接回 5.4 和 12.2。
