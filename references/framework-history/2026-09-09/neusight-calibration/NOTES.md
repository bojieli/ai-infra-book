# NeuSight：资源下界之后，怎样校准执行时间

> 2026-09-09。ASPLOS 2025 节目顺序 78，DOI 10.1145/3669940.3707265。选读物理页 2–14，其中第 14 页为工件说明，参考文献不计入正文阅读；页 1 摘要此前已筛读。本轮实际查看图页 6、7、8、9、11、12、13、14。没有运行下载代码、模型、预测器或 GPU 实验。

**建议有限采用，仅补现有第 13.5.1 的延伸材料。** 第 1 章已经讲从下界到预测，第 4 章已有形状利用率，第 5.3.3 已区分依赖合法性、成本模型和真实测量。NeuSight 能补的新判断是：预测器也有自己的适用条件；校准必须包括框架实际选择的 tile、精度、融合与调度，而不能只给设备峰值换一个系数。它适合帮助决定最小实验该测哪里，无需再建“性能预测模型”专题。

## 论文的方法与范围

正文物理页 5–8 把 kernel 拆成输出 tile，估计 tile 数与执行波次数，再在 Roofline 上界之下预测有效利用率。这样学习的对象比整模型时间更小，结构约束也更明确。它仍依赖旧设备上的 profiling 数据：tile 数据库来自 kernel 名称、线程块数和输入形状，新目标的 tile 通过相近记录估计。没有在目标设备运行，不等于不需要任何测量，也不等于已经知道新库会采用哪种执行方式。

物理页 7 的“一次每 SM 一个 tile”是聚合模型；线程块并发被利用率项近似吸收。不要将这个假设写成 GPU 的硬件限制，或将波次数直接视为完整执行时间。与第 5 章一样，先辨认真正的 kernel 和数据依赖，再问模型解释了多少。

主要数据用 FP32 收集：NVIDIA 路线为 PyTorch 2.1.0／CUDA 12.1，AMD 为 PyTorch 2.4.1／ROCm 6.1。NVIDIA 预测器由较旧设备训练，在 H100、L4、A100-80GB 等保留设备上评估；AMD 路线用 MI100／MI210 数据训练，再评估 MI250。因此这里不是完全没有 AMD 样本的跨厂商外推。FP16／Tensor Core 的补充实验针对一组 BMM，不证明当前 BF16／FP8 整模型、MoE dispatch 或新融合内核都得到同样精度。

物理页 10 的生成推理指标是生成第一个 token 的时间，训练按前向和反向迭代计量；不包含完整 decode 输出序列、服务排队、请求调度和 Agent 工具等待的统一模型。论文的四卡分布式实验分别考察 DP、TP、PP，使用一个 microbatch。多节点表给出最多 3840 节点的预测，作者明确未在相应真实集群验证；不能把它写成万卡预测精度已经成立。

工件附录提供历史数据、模型参数和复现脚本，指定约 50 GB 完整空间。我们只下载用于核对机制的少量文档和源码，没有下载预测器权重或完整测量数据。论文误差数字描述的是其评估集合，不是下一款 GPU 的误差保证，也不是统计置信区间。

## 固定源码关闭了哪些疑问

论文给出的 `sitar-lab/NeuSight` 仓库目前跳转到 `scai-tech/NeuSight`。原地址 API 的最终响应保留在 [sources.json](sources.json)，固定 main 为 `6945927d9afcca2b9daf021f8395e53edc5b4eef`，2025-06-23。根 README 和 ASPLOS 工件 README 已完整读过；这是可追溯的历史研究实现，未发现证据可将它当成当前推理框架的通用预测后端。

- **tile 选择仍受数据库覆盖限制。** `MetaTable.get_tile` 按算子名过滤后，用声明的输入特征寻找近邻；按 CUDA 版本过滤的代码被注释。预测包装器又固定传入 `cu121`。本轮没有验证它对新库 dispatch、全新 tile 家族或 CUDA 版本变化的误差；不能用“模型参数没变”推断预测仍适用。
- **融合不是简单删除字节就充分描述了。** 所读实现累计运算量和外部输入输出字节，以列表最后一个向量算子选择预测器；论文 §4.4 写的是第一个算子。两者保留为版本差异。该分支不能任意承接矩阵与向量混合的所有融合，未支持的代表算子会拒绝；本轮不扩展到未读 parser 的全部匹配规则。
- **固定精度进入了计算公式。** 矩阵和向量路径多处按每元素四字节计算。FP16 补充试验的“改输入特征即可适配”不能视为这些普通入口已自动正确处理全部精度。矩阵路径中 M／N／K 的约定也必须沿代码核对，不能按习惯替换维名。
- **分布式汇总的能力有限。** aggregator 对 DP、TP、PP 使用互斥分支；PP 显式要求 `num_micro_batch == 1`。预测器通信路径含四卡计数、指定设备名和 0.72 的带宽系数。普通汇总主要按 kernel 时间求和，DP 另作通信就绪与串行链路重叠估计；它没有在这条路径上统一求解任意混合并行、多 stream 竞争和服务尾延迟。

因此，合理实验入口是检查预测明细、定位偏差最大的阶段，再与固定软件版本的 trace 对照。书中当前 Qwen3、DeepSeek V4、Kimi K3 的模型和执行图不能直接替换论文配置，尤其不能把论文 Table 5 的历史表格当作模型规格库。

## 怎样接回最小实验

沿第 13.5.1 的现有案例，先用容量和带宽下界排除明显不可行的候选；只在剩余方案的差距接近不确定性时，引入形状／tile 效率的预测，再测会改变排序的算子。保存输入形状、精度、库版本、实际 kernel 与 tile、单独执行和重叠执行的条件。模型提供的是一个可检验的预测，不能替代这些条件。

给读者一个很小的教学记录即可：两个串行阶段预测为 8、2 ms，实际为 6、4 ms。总时间都为 10 ms，整段误差是 0，但逐阶段误差分别为 33.3%、50%。若准备优化第二段，预测的时间占比 20% 与实际 40% 会改变投入判断。随后再比较“预测第一阶段缩短一半”的收益与实测，提醒读者不能只验整段总数。这些是独立教学数字，非 NeuSight 实测，见 [arithmetic.json](arithmetic.json)。

实验 13-6 可以沿已有关键假设表加入这项校准检查，不增加核心实验；图 13-5 仅标出预测值、实际值和下一项补测。第 1／4／5 章无需重复增加论文段落。

## 保留在证据记录的疑点

物理页 7 的利用率表达式用两个 sigmoid 输出相减。单凭 sigmoid 不能保证差值为正；所读代码也用 `gamma-alpha/num_wave`，外层把负预测裁到 0。教学反例设 gamma=0.1、alpha=0.9、波数 1，即可得到负利用率，再被裁成零时间。这个检查只说明该表达式不能作为普遍的物理下界保证，不表示已发布权重一定在论文数据上出现此情况；本轮没有运行权重。书稿采用前应对新输入做独立下界与有限值检查，正文不展开这一代码疑点。

论文中还存在不能混用的表述：引言分布式平均误差为 5.4%，实验段为 7.7%；AMD 图 9 图例包含 MI250，而图注只列 MI100／MI210；Table 5 的 BERT-Large 行为 12 层、hidden 760，不能直接抄成标准模型配置。本轮不为这些差异补造解释，亦不把其数字写进正文主论证。
