# Spindle：共享组件如何改变多任务训练的资源分配

> 2026-09-09。ASPLOS 2025 节目顺序 76；DOI 10.1145/3676641.3715992。选读作者 arXiv 2409.03365v3（2025-02-11，20 页），不视为出版社 PDF 的逐字同版。正文范围为物理页 2–13，附录为 18–20；第 13 页只将参考文献前的正文计入阅读。参考文献页 14–17 没有按正文通读。没有运行下载代码、模型或 GPU 实验。

Spindle 值得进入第 10.3.1 的延伸材料：同一多模态训练任务中，编码分支与共享模型部分的工作量、扩展效率、就绪时间不同。将 GPU 平均分给分支，或让每个分支轮流占满集群，得到的是不同候选；选择要回到整步完成时间、共享参数的更新和实际交接成本。它补充了固定层流水和 MoE 专家交换之外的一个判断：**资源分配应沿真实模型的分支和汇合重新计算，最轻的分支不一定值得继续加卡。**

## 已读论文讲清了什么

物理页 4–8 先把连续、相同类型和输入规模的算子缩成 MetaOp；它是调度图压缩，不意味着这些层被编译为一个融合 kernel。同一依赖层内的 MetaOp 可以并行，跨层还要等待前驱。每个 MetaOp 通过目标设备上的离散 profiling 点拟合扩展曲线；每卡 batch 和所选 kernel 改变，效率也会变。论文先解连续资源分配，再按合法设备数、完整算子数离散化，用贪心 wavefront 编排执行，最后处理设备放置。

物理页 8–9 明确写出两种依赖。前向激活、反向梯度随波次交接；共享参数在不同任务中的梯度贡献需要积累并在对应设备组内同步。共享参数减少了重复存储，也会形成同步组。只画前向算子矩形，或让任务独立更新同一个参数，都不足以验证完整训练语义。任务权重、有效样本或 token 归一化、dropout／随机状态还要由具体训练入口核对；本轮未完成全运行时的训练等价证明。

物理页 9–10 和附录 C 给出三类历史配置：Multitask-CLIP 约 1.20B，OFASys 约 0.66B，作者组合的 QWen-VAL 约 9.25B。它们分别用对比损失、encoder-decoder LM 和 decoder-only LM 作为跨模态部分，计算重心由编码器逐渐转向共享 LM。QWen-VAL 由当时 QWen-VL／QWen-Audio 结构组成，不是 Qwen3 或当前通用多模态模型的别名。适合借鉴这种“改变计算重心再选择分工”的比较，不把旧模型规模作为全书新主案例。

真实实验使用最多 8 节点、每节点 8 张 A800 80 GB，节点内 NVLink、节点间 400 Gbps InfiniBand；正文报告 100 次迭代的平均时间。基线按论文作者定义的多任务执行方法适配并手动调参，不能将相对加速写成当前 Megatron／DeepSpeed 的一般结论。附录 E 的 QWen-VAL 30B／70B、256 GPU 是模拟结果；本轮不拿其 1.34／1.36 倍作实机预测。

附录 D 的动态任务实验通过改变任务集合构造变化。变化发生时先保存当前模型，再加载新任务与保存模型继续训练。因此“重规划小于 3 秒”只覆盖规划器，不等于全系统改配只需 3 秒；profile、保存、加载、建组与重新稳定都要单独计入。改变任务比例也可能改变训练目标，性能比较须保持所声明的样本和更新语义。

## 论文与公开源码的距离

官方 PKU-DAIR/Hetu-Galvatron 的 `spindle` 分支在取证时指向 `1c03a149c3aabcf3eac9585d44dd5cec8933edff`，提交日期为 2025-03-19。API 分支、提交和未截断递归树的原始响应，以及五个代码文件和 README 已保存于本目录的 `sources/`；[sources.json](sources.json)记录 URL、时间、HTTP 状态、字节数和 SHA256。根 README 完整读过，仍为通用 Galvatron-2 文档，不能以它证明 Spindle 的全部论文功能已进入普通发行版本。

选读源码得到以下有限结论：

- `spindle_compute_graph.py` 的 `LayerInfo` 接受外部时间函数，`get_time` 使用每卡 batch；合法设备数可按 batch 整除过滤。因此时间函数、batch 和合法配置必须同时保存。其示意 FLOPs 公式也不是 Qwen3 GQA／SwiGLU 的完整模型账本。
- `spindle_planner.py` 读到候选选择、连续二分、层数取整和设备映射。`device_mapping` 的局部分数按算子／设备分配变化计数；这个函数没有把真实张量字节、NVLink／InfiniBand 带宽与每卡显存显式写入分数。不能将论文 §3.5 的所有放置能力直接认定为该函数已逐项实现，也不能据此断言未读文件没有别的机制。
- 文件名 `spindle_placement.py` 下本轮完整读到的是调度矩形数据结构与绘图函数。名称本身不能证明它包含完整的容量约束放置器。
- 所查 `hybrid_parallel_model.py` 前 105 行仍是通用 GPipe／PipeDream-flush 包装路径；本轮没有建立它与论文 `SpindleTask`、共享参数设备组、动态任务恢复的完整调用对应。公开研究代码可以用来解释候选生成，当前证据还不够承诺一个整套 Spindle 训练复现实验。

这些是固定 2025 分支的选读结论。没有由此声称 vLLM、SGLang 或当前训练框架拥有相同机制；也不把论文的“异构负载”误写为不同型号 GPU 的异构集群。

## 留给现有练习的一次条件翻转

给四张同型卡两个独立编码分支 A、B，随后汇合到同一共享模型段。保持输入、权重和数值目标一致，先用教学 profile 比较：A 在 1／2／4 卡上需 12／6／3 ms；B 需 6／4.5／4 ms；汇合后模型段在四卡上需 8 ms。这里的数字全部是教学假设，不是论文曲线或硬件测量，且只演示前向依赖片段，不宣称完整训练步。

两分支依次使用四卡，再运行共享段，合计 15 ms。分支各用两卡并行，等待较慢的 A 后再汇合，交接前为 14 ms。于是并行候选只能承受 **不足 1 ms 的新增暴露交接与重配成本**：增加 0.25 ms 时得到 14.25 ms，增加 3 ms 就变成 17 ms。共同存在的搬运应放进两条路径各自的 profile；只把差额计入这里，避免重复收费。接着给真实模型填入分支形状、激活字节、前后向、共享参数梯度和峰值驻留，再用 trace 判断还缺什么。

现有实验 10-5 可把这个例子作为选做分支：给真实模型的两组曲线和数据边，由读者判断该轮流用卡还是并行分工；图 10-5 沿原时序图标记两路汇合和暴露交接即可，不新增核心实验或单独配图。训练动态改配还可选算一次摊销：教学设定规划 3 秒、保存 20 秒、加载 35 秒、建组与稳定 2 秒，总共 60 秒；每步只省 50 ms，需要超过 1200 步才获益。所有算式由[独立脚本](arithmetic.py)核对，结果见[arithmetic.json](arithmetic.json)。

## 仅留在证据笔记的疑点

论文物理页 6 的 Theorem 1 仅列出时间函数正且不增，就推出连续资源的最优方案为每个 MetaOp 固定分配、同时开始和结束。单靠这两个明示条件不足以支持该结论：两个单位任务、总资源 2，令 T(n)=1/n²。静态各分 1 需要 1 单位时间，先后各用 2 只需 0.25+0.25=0.5。反例只说明需要更多约束或更准确的定理表述；没有查阅被引的 1981／1982 年理论原文，也不据此判定论文实测失效。正文不引入这个定理。

物理页 12 的图 10 有 6.2% 的交接占比，正文概括为“不超过 6%”；可按近似描述阅读，不移植为上界。图例中的 `Sp* w/o DP` 在本段消融语境指去掉 device placement，不能按常见缩写理解成删除 data parallelism。图 11 相对连续松弛的距离只覆盖所评估模型和约束，不能泛化为所有训练工作“距全局最优不超过 7%”。
