# Ratte：先数有效候选，再比较生成速度

2026-09-09。依据已归档的[作者 PDF](https://www.doc.ic.ac.uk/~afd/papers/2025/ASPLOS-Ratte.pdf)，完整读取物理页 2–4、7–12，查看页 12 表 3、4 与例子。未读页 5–6、13–16，不记作通篇已读。具体页提取与图像散列见 [ratte-reading.json](ratte-reading.json)。本轮没有运行论文代码、编译器或模型。

## 正确性参考从哪里来

页 2、4 说明只对比不同优化等级仍有盲点：如果两条路径经过同一个错误 lowering，二者一致也不能证明编译正确。Ratte 为支持的方言组合提供独立解释语义，并在生成程序时跟踪变量值、类型等信息，避免生成含未定义行为的输入。普通语法合法、编译未崩溃，与动态执行结果具有可比较的含义，是不同的条件。

页 7–10 描述了可组合解释器和生成器：不同方言的操作通过接口使用所需的语义信息，不必每增加一个组合就重写整套生成器。比如整数除法除检查类型外，还要排除零除和最小有符号整数除以 −1 的溢出；动态 tensor 的类型允许省略尺寸，但生成 cast 时仍需知道具体尺寸是否相容。这里只采用这些检查如何影响候选有效性的思路，不把 Haskell effect system 细节加入正文。

参考实现也有范围。页 2 将生成限制为无环程序；某些高层操作 lowering 后仍会出现循环。页 10–11 实现共支持六个核心方言中的 43 个操作，arith 侧重整数与 index，linalg.generic 仅支持基于置换的索引映射，tensor 只支持列出的子集。实验以 LLVM 为目标，用 CPU runner 执行。因此不能由此声称 Ratte 验证了任意 MLIR 方言、GPU 并发、浮点归约或本书全部模型算子。

## 有效测试速度的手算

页 12 表 4 的 Arith 组合中，MLIRSmith 生成 1,000 个程序需 67 s，全部可编译，但只有 1.10% 被 Ratte 解释器判为无未定义行为。Ratte 生成 1,000 个程序需 191 s，论文称生成时按构造保持有效。

只按生成时间算，MLIRSmith 约为 14.93 个/s，Ratte 约为 5.24 个/s；如果把报告的有效率作为筛选条件，前者本批约 11 个有效程序，折合 0.164 个/s，后者为 5.24 个/s。这个推算不是论文实测的端到端测试加速：尚未计入后续编译、解释筛选、执行、定位误报与人工审查时间，也没有控制测试程序复杂度和覆盖能力。MLIRSmith 的原设计目标偏向崩溃测试，而非这项语义差分任务，不能据此断言它在原本任务上低效。

另外两组不能直接照套：Tensor 的 0% 是这一千个样本中的结果，不证明未来必然为零；LinAlg 的无未定义行为比例为 N/A，脚注明确有些程序的循环过大而难以检查，不能当成 0%。未修改版的 7.8% 只对应 canonicalize，不代表成功生成可执行代码。

接回现有 Agent 算子实验，分别统计提出候选、成功编译、通过数值合同、完成计时和实际进入服务路径的数量，以及各阶段耗时。候选失败要进入搜索成本；“更快提出更多候选”与“在预算内找到可用优化”分别评价。这个方法只需在实验 5-6 加一个计数要求，不新增论文小节。

## 边界输入与对照解释

页 12 图 12 的输入是 `(-2^63 + 1) / -1`，正确整数结果为 `2^63 - 1`，可在有符号 64 位中表示。正文解释错误 lowering 的中间计算产生 `-2^63 / -1`，引入溢出／poison。这能说明最终数学结果合法，不保证某个变换的中间步骤合法。本轮仅在 Python 整数上复算边界关系，没有执行旧版 MLIR，也没有检查当前修复提交。

表 3 第 7 行该例的 oracle 记录为 NC，正文则用独立语义解释 lowering 的风险；因此不将所有六个误编译都描述成“由差分 oracle 检出”。表中共八项，包括六个误编译与两个错误拒绝；状态分别有 Submitted、Confirmed、Fixed，不能写成八项全部修复。

独立参考与生成器也是实现，仍需用单元测试、交叉验证和明确语义维护；论文的构造保证不等于对全生态的形式化证明。已有 Qwen3 数值合同、独立验证器与未参与搜索的边界形状继续作为实验主体，Ratte 只提供为何需要这些条件的历史证据。
