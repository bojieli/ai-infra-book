Abstract
Processing-in-Memory (PIM) delivers enormous perfor-
mance by taking advantage of internal DRAM bandwidth
and parallelism. However, graph applications are difficult
to adapt to PIM due to their irregular access patterns. We
present the first Fine-Grained PIM (FGPIM) design that fully
accelerates vertex-centric push-based graph applications by
accelerating both their update (computing vertex updates)
and apply (summing up the updates) phases.
For the update phase, we design a tuple-based LLC that
can coalesce at different granularities to group graph up-
dates together and propose multi-DRAM column processing
FGPIM instructions to match the cache coalescing to the
row-level parallelism of the FGPIM. With this acceleration,
the apply phase becomes the bottleneck, and we propose
bank-parallel FGPIM instructions with predicates to allow
FGPIM to accelerate the conditional updates as well.
We achieve an average speedup in the region of interest of
1.8×/3× compared to naive FGPIM and 4.4×/9.8× compared
to state-of-the-art non-PIM baseline (HBM2/DDR4), and
DRAM energy reduction of 67%/86% and 88%/94%. These re-
sults show the importance of providing a complete solution
that accelerates both the update and apply phases.

1 Introduction
Processing-in-Memory reduces data movement and provides
higher bandwidth and parallelism by placing compute in or
near DRAM. However, PIM has struggled to gain industry
acceptance, in part due to difficulties in modifying standard
DRAM interfaces. Fine-grained PIM (FGPIM) [19, 20] ad-
dress this by using similar commands and timing as standard
DRAM, which makes it readily compatible with existing sys-
tems and memory controllers. For example, to process data
in DRAM with FGPIM, a standard DRAM row activation
command is issued, which “opens” the row for the FGPIM
processing unit and then an FGPIM processing command is
issued to process the row’s data in DRAM.
FGPIM typically adds SIMD processing units and tempo-
rary storage (TS) on-die to some of the DRAM banks. This
takes advantage of the enormous parallelism and bandwidth
across multiple on-die banks (each bank can execute inde-
pendent operations) and the parallelism within banks (each
bank activates a 1-8KB row and can process multiple 64B
columns of it in parallel at each activation). However, this
design is highly-efficient only for regular data accesses with
parallel processing at both the DRAM row level (activating
new rows for irregular accesses is expensive [13, 26]) and
the DRAM column level (processing less than the full 64B
SIMD column for irregular update is wasteful).
In this work we co-design on-chip cache coalescing with
FGPIM to fully accelerate vertex-centric push-based graph
applications [7, 30]. Fully accelerating these applications re-
quires a design that addresses both of their phases: The up-
date phase, where each vertex modifies its neighbors with a
highly irregular read-modify-write accesses (graph updates),
and the apply phase, where the accumulated data for each
vertex is combined with the previous values in a regular, but
conditional, manner. For the update phase the challenge is

Previous work has addressed only the update phase. The
naive approach of using FGPIM operations to directly process
vertex updates in DRAM without bringing the data back
to the CPU [2, 25], achieves an average 3.3× speedup due
largely to a 61% DRAM traffic reduction compared to a state-
of-the-art non-PIM solution [23] (Naive FGPIM in Figure 1).
However, that approach is unable to take advantage of
the SIMD parallelism within the FGPIM units as each vertex
update is sent individually. Moreover, it misses out on signif-
icant reuse across activated DRAM rows, as so many FGPIM
update commands are issued that the memory controller
cannot schedule them efficiently due to limited queue size.
Irregular updates can be addressed by coalescing them
over time into fewer, but more regular, updates. Our base-
line state-of-the-art FGPIM architecture AIM1 [1] combines
FGPIM update computation with in-cache coalescing within
each cacheline, as the cacheline granularity matches the FG-
PIM DRAM column SIMD granularity. Doing so delivers a
4.6× speedup (+Column Coalescing (AIM) in Figure 1).
We go beyond the state-of-the-art in the three steps shown
in Figure 1. First, cacheline coalescing is far from the best we
can achieve as 88% of the data sent in the cacheline coalesced
FGPIM update commands are zeros, because no updates were
coalesced to those locations. This wastes cache space (storing
zeros) and DRAM bandwidth (sending zeros).
Our first step increases the number of updates we can
coalesce in each cacheline before sending them to the FGPIM

by supporting larger coalescing granularities. We show that
the optimal coalescing granularity provides significant en-
ergy benefits by reducing the DRAM row activations by 93%
at a modest 4.8× speedup (Step 1: +Optimal Granularity).
While the optimal granularity improves cache usage, it
still sends separate FGPIM commands for each DRAM col-
umn in the cacheline of updates, which wastes bandwidth.
Our second step processes multiple columns with a single
FGPIM command (Step 2: +Multi-column), which achieves
6.1× speedup.
With appropriate coalescing granularity (Step 1) and multi-
column FGPIM processing (Step 2), the irregular update
phases cease to be the performance bottleneck and further
performance requires accelerating the apply phase. While
the highly regular access pattern of the apply phase is an
excellent match for FGPIM’s SIMD processing, the opera-
tions themselves contain conditionals, which are not a good
match.
Our third step addresses the apply phase by adding pred-
icated [12], bank-parallel operations to the SIMD units. With
this we can parallelize the apply phase across all banks and
deliver a 9.8× speedup while reducing DRAM traffic and
row activations by 97% and 96%, respectively (Step 3: +Bank-
parallel instructions).
Our proposal, CoGraf, is the first FGPIM design to fully
accelerate irregular push-based graph applications. It does
so through a co-design of in-cache coalescing with FGPIM
execution to match the coalescing granularity to the FGPIM
units’ DRAM-row accesses to accelerate the update phase and
bank-parallel predicated execution to accelerate the apply
phase. Specifically, we:
• Explore optimal coalescing granularities and propose a
tuple-based LLC to support them.
• Enhance FGPIM to process updates across multiple DRAM
columns and show how these variable-latency commands
can be statically scheduled by the memory controller.
• Propose predicated bank-parallel FGPIM instructions to
accelerate the data-dependent apply phase.
• Demonstrate the benefit of each step and explain why dif-
ferent graphs benefit differently based on their structure.
2 Background and Motivation
