Abstract
Task Scheduling is a popular technique for exploiting parallelism
in modern computing systems. In particular, HW-accelerated Task
Scheduling has been shown to be effective at improving the performance of fine-grained workloads by dynamically assigning tasks
to cores based on their data dependencies with minimal overhead,
allowing the handling of tasks with execution times in the order
of thousands of cycles. However, the performance of applications
assisted by accelerated Task Scheduling is limited by the fact that
once a task has all its dependencies fulfilled, it is typically executed
on the first available core, which might not be locality-optimal. We
thus propose a novel approach to Task Scheduling that leverages
HW-accelerated Label Propagation (LP), a graph clustering algorithm, to group tasks with intersecting data patterns such that they
are executed on the same core. We show that our approach can
significantly improve the performance of task-based applications,
improving overall program execution times by up to 1.50× while
simultaneously reducing average task sizes by up to 1.81×, augmenting both synthetic benchmarks and real-world applications
running on a 24-core RISC-V processor mapped to the Alveo U55C
FPGA. These gains rely heavily on the low-latency nature of our
proposed label propagation accelerator, which will typically cluster
dynamic task graphs in under 300 cycles, up to 581× faster than
an equivalent software implementation. Furthermore, by ensuring
that ideal placement predictions are used as a hint rather than a
hard constraint, we allow the system to benefit from improved data
locality for memory-intensive applications while also maintaining high core utilization in compute-bound scenarios. Our results
hence demonstrate the potential of HW-accelerated label propagation to improve the performance of Task Scheduling systems with
low-latency, dynamic data locality optimization.

Keywords
Task scheduling, data locality, graph accelerators, RISC-V, FPGA

Introduction

Task Scheduling is a parallel programming paradigm built around
the concept of tasks, small program segments (usually functions)
that are allowed to be executed in parallel. Tasks might have data
dependencies among themselves, so that some task 𝐵, depending
on the results from some task 𝐴, might only be allowed to execute
once 𝐴 has committed its results to memory.
Such execution constraints might be inferred either at compilation or execution time. Inferring these constraints at runtime might
allow for more parallelism, given that an application might spawn
several tasks 𝐿 that depend on some other task 𝐾 for certain inputs
but not for all. If ordering constraints for this application were
to be defined at compile time, they would need to conservatively

The OpenMP standard supports Task Scheduling with arbitrary
pointer-based data dependencies among tasks since version 4.0
of the specification. Fig. 1 holds a sample task parallel program
adhering to OpenMP 4.0. This example illustrates how Task Scheduling can be leveraged to tap application parallelism without major
restructuring of the corresponding serial code, as that version of
the application can be recovered by merely removing the pragmas.
Given the information provided by tasking pragmas such as in
Fig. 1, the Task Scheduling runtime library will, during execution
time, build and continuously update a task graph representing the
data relationships between all known in-flight tasks. Fig. 1 includes
a task graph that might arise from the execution of its OpenMP
listing. In this directed acyclic graph, an edge (𝑢, 𝑣) indicates that
task 𝑣 should only be allowed to execute after task 𝑢 is concluded.
This constraint typically arises from task 𝑣 depending on some data
produced by task 𝑢, but it might also be the result of write-after-read
or write-after-write dependencies between these tasks.
To ensure a legal execution of the program, the Task Scheduling
runtime will thus ensure that only tasks without any incoming
edges are allowed to execute. When they are finished, the runtime
removes them from the graph, potentially making other tasks ready
to execute by leaving them without any incoming edges.

The locality-insensitive baseline

Task graphs typically admit multiple different legal task execution
orders. A ready-task (one without any incoming edges in the graph)
might be assigned to any core in the system to be either immediately executed or held in a queue. Different ready-task assignment
strategies impact performance in distinct ways. Some strategies
might assign tasks to cores in a way that minimizes cache misses,
while others might be more beneficial to avoiding core idleness.
Task Scheduling runtimes such as the GNU OpenMP library and
Nanos follow the same general strategy of maintaining core-private
ready-task queues that are only fed by a single control thread. To
mitigate load imbalance, cores are allowed to steal tasks from a
random victim core whenever their own ready-task queues are
empty. This load-balancing method is called Random Task Stealing,
