## 给现有题目的补充，建议不增加题号

已有 21 道改编题覆盖这些方向。这次建议补来源说明和少量同题追问，不扩成新的核心实验或知识小节。

- **I03 的来源说明**可以增加阶跃 KV 方向的弱交叉证据；依旧由第 2.3／8.2 章给出分页、容量与访问量的回答。该帖没有问到页大小，不能把 I03 的具体题干回填成阶跃原题，也不能将同帖的 SVD 自动解释成 MLA 或低秩 KV 压缩。
- **I19／I21 的同题追问（本书改编）**：设计一个包含多模态输入、工具执行与重试的 Agent 评测任务，哪些记录决定它确实完成，哪些记录仅用于诊断性能？在相同任务和质量判据下，怎样比较两个运行方案的耗时与费用？来源只提供 MiniMax benchmark 的方向；此完整题干与回答路径是本书改编。沿第 3.1.3／3.1.4 固定工作负载，第 11.2.5 检查环境初态与重置，第 11.5.1／11.5.2 检查尝试身份、任务完成和失败费用，再由第 12 章拆输入／传输／模型／工具的时间，第 13.1.1 固定比较条件。不要因为某方案模型 token/s 更高，就省略工具失败或外部状态不一致的尝试。
- **第 3.1.3 既有并行工具变体（本书改编）**可以用阿里云子 Agent 方向校验：把一条 AgentLoop 分成两个分支后，哪些依赖、状态驻留与通信增加，什么条件下才缩短完整任务？沿既有轨迹画依赖图、区分共享前缀与增长尾部，再接第 11.1 的资源驻留与第 11.5 的续接。没有原帖提供的实测数值，本交付不新增数字、答案校准或来源归属。

MiniMax RL 专栏涉及的奖励、重要性采样和框架名，已由 I17／I18 与第 10.5 章覆盖。它没有披露可核对的训练／rollout 拓扑、状态恢复或系统实现，因此本批对“2026 年基础模型公司训练／RL Infra 一手具体考核”的缺口没有实质补齐。下一轮应优先找有具体系统场景、可核时间和独立作者的原文，而不是继续扩大商业题库标题数量。
