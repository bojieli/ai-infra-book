# Qwen3 请求计数与跨章衔接

2026-09-09。并行审读第 2→6→8→9→10 章及相关 Qwen3 案例，确认一处计量口径冲突和一处实验衔接缺口。本轮只修改对应段落；没有运行用户当前计算项目、模型或设备实验，也没有把所有章节与全部模型报告标成读完。

## 输出数与前向次数

第 2 章和[模型资源笔记](../../../case-studies/model-resource-accounting.md)原先把 G 定义成输出数，却用 G 次额外单 token 前向累计 KV；第 8／9 章已经按首输出来自 prefill 计数。现在统一为：prefill 前已有 S 个位置，本次输入 P 个，结束后 H=S+P；普通请求输出 G 个 token，首输出由 prefill 给出、最后输出不再前向时，后续调用 D=G−1。

单请求的旧历史参与量为 `144 KiB×[DH+D(D−1)/2]`，追加 KV 为 `144 KiB×D`，保留上下文时的有效 KV 为 `144 KiB×(H+D)`。当前 token 当步参与、物理页、真实 HBM 流量和完成后释放另计。原来明确以调用次数给定的 C08 数值保持，不改用户计算代码。

边界例子能显示这不是单纯换字母：16-token prompt 只要一个输出，prefill 已完成生成，不应再加一次 decode。在每页 16 token 的教学预算下，有效 KV 是一页 2.25 MiB；误加一个已计算位置会变成两页 4.5 MiB。8192 输入／129 输出应使用 128 次后续前向；命中 6144 位置并新补 2048 时，后续历史仍从 8192 开始。

## PD 实验接回同一模型

实验 9-2 的 32 层、1 GiB 示例本身正确，但仍需按该节承诺代回 Qwen3-8B。保持教学有效带宽 25 GB/s，36 层、8192 历史的 BF16 KV 为 1.125 GiB，纯载荷时间约 48.32 ms；旧例约 42.95 ms。增加这一对照，再沿已有池配比继续，不能将条件式下界写成 A100／H20 实测。

对应章节、延伸材料和 skeleton 已做相同修订。新增段落之外的并发用户修改保留；[修改记录](input-proofs.json)保存精确前后文字和当时文件散列，散列仅描述修订时的工作区，不要求用户随后停止编辑。

## 已核对的口径

Qwen3-8B 的 36 层、4096 隐藏维度、32／8 个 Q／KV 头与 128 头维一致；Qwen3-235B 的 KV 为 188 KiB/token，与 8B 的 144 KiB 分开。PP 的单隐藏张量 8 KiB 与所查双张量接口 16 KiB 也已明确区分。训练 16／18 byte 每参数分别对应不同梯度精度，检查点 14 byte 不包含梯度，这些不是待修错误。

[独立脚本](arithmetic.py)仅读取两份已归档官方配置，复算参数、KV、普通请求边界、分页以及 PD 载荷时间；[结果](arithmetic.json)不代表框架实测。其他模型、全部算子实现与完整书稿仍需后续审读。
