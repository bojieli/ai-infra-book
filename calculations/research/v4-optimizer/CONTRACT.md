# V4 optimizer reference contract

This candidate inventories every locked checkpoint tensor and reconstructs packed FP4 logical K before counting parameters. The base and MTP inventories remain separate. Default omits MTP from updates but reports its exact logical count; include_mtp=true inventories and updates its corresponding groups. Quantization scales and integer hash tables are metadata, not ordinary trainable weights. This is one optimizer step after gradients exist, not a forward/backward training step.

## Official evidence versus explicit choices

The archived DeepSeek-V4 report §2.4 and Algorithm 1 give Nesterov Muon, ten hybrid Newton–Schulz iterations (eight coefficient triples 3.4445/−4.7750/2.0315 then two 2/−1.5/0.5), update scaling sqrt(max(rows,cols))*gamma, weight decay, and AdamW exceptions: embedding, prediction head, RMSNorm, mHC static biases and gating factors. Section 4.2.2 gives momentum .95, decay .1, gamma .18, Adam .9/.95/1e−20. Learning rate is an explicit scenario input, default the reported Flash plateau 2.7e−4; it is not a universal Pro schedule. Adam step is an explicit positive integer.

Source inference/model.py supplies shapes, not the unpublished optimizer implementation. In particular wo_a is reshaped to independent output groups for its forward einsum. Choosing those source groups for Muon is a declared training matrixization assumption; stored_matrix is an alternative. Other 2D tensors remain intact, including each independent expert projection: concatenating all experts into one NS matrix is prohibited. The attn_sink vector has no published matrixization rule and defaults unresolved; row_muon explicitly assumes a 1×H matrix. hc_head_fn spans the head/mHC boundary and defaults unresolved; scenarios choose AdamW or Muon. These choices change update mathematics, not only runtime. ff n gate bias is a separate auxiliary-loss-free load-balancing update, requiring load observations; its count is not silently charged AdamW/Muon.

## Selected arithmetic

Let one independent matrix have E=n*m elements after optionally transposing so n<=m. The transpose policy is algebraically equivariant for this polynomial, but its use by the production optimizer is not established. Ten iterations each materialize A=X X^T; B=A A; C=b A+c B; X'=a X+C X. This is 4n²m+2n³ matrix FLOPs and 3n²+2E ordinary scalar operations per iteration, with GEMMs charged 2mnk. The coefficients are fixed by the report, not a user-selected arbitrary NS depth.

Outside NS: momentum plus Nesterov 4E; Frobenius squares/reduction/epsilon addition/division 3E plus one sqrt; rescale plus weight decay/update 4E. Thus Muon scalar work is 11E+10(3n²+2E). Explicit epsilon is added even if zero. epsilon=0 has an undefined all-zero Nesterov matrix; the tiny numerical reference rejects it rather than silently inventing a zero policy. Positive epsilon is a distinct declared normalization scenario. Shape-dependent sqrt(maxdim)*gamma costs one sqrt and one multiplication per distinct logical shape at setup, separate from every-step work. One shared Muon decay coefficient costs two ordinary operations per step.

AdamW reuses the public training_nonmatrix algorithm convention: 14P ordinary operations plus six shared coefficient operations per step, P square roots and two powers. These are algorithm counts, not machine instruction counts. Coefficients are shared across all Adam groups. Gradient accumulation, gradient computation, clipping, dynamic loss scaling and distributed collectives are not inside this update ledger.

## State and execution

The declaration uses FP32 master weights, input gradients, Muon momentum and Adam first/second moments. Each Muon matrix reports per-iteration tensor input/output bytes and individual X/A/B/C/CX temporary sizes. GEMM operands are counted per role (X twice in X X^T, A twice in A A). Elementwise polynomial combine uses one fused logical pass for each output. These interfaces do not imply physical HBM traffic or simultaneous allocation. Persistent state survives steps; input gradient and NS temporaries are step-local. No full peak or cast/quantized weight copy is claimed. Report §3.4.1 specifically supports BF16 NS GEMMs, so the declared FP32 interfaces are a mathematical reference choice, not an assertion that production NS reads FP32 operands.

The official distributed scheme needs complete independent matrices per optimizer owner; dense capped ZeRO bucket balancing, padding and redundant replicas differ from independently distributed experts. No rank topology is supplied, so the ledger cannot divide state/work by a GPU count or reuse a nominal <10% padding remark as a guaranteed bound. Source synchronization uses stochastic BF16 and local FP32 reduction, but data-parallel owner mapping and padding are required to compute traffic. These remain explicit nulls. full_optimizer_exact is always false. conditional_selected_parameter_updates_covered means the selected eligible parameter groups are classified; it does not cover external router bias updates, cast/quantization, distributed work, or actual runtime.
