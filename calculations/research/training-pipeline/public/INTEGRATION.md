# Public integration candidate

Shared source remains unchanged. Copy `src/infra_calc/topics/training_pipeline_schedule.py` and `tests/test_training_pipeline_schedule.py` to their ordinary public locations. Use a dedicated `training-pipeline-schedule` CLI command, `calculate(**scenario)` and `markdown(result)`. The result deliberately has its own schema; do not force generic Scenario precision or generic summary renderer.

`book.append.json` contains fourteen flat scenarios, ready to place under a new reproduction group. They cover GPipe/1F1B M=1/4/8/16, slow stage, one shared link and the existing nonlinear SiLU recompute policy. `sources.lock.subset.json` is an already-public Qwen3-8B subset; no new external download is required. Parent directory bindings.json pins code/dependencies/artifacts. Re-run focused tests after any integration changes.

Recommended chapter statement: official Qwen3-8B is partitioned 9 layers per stage over four stages, with embedding and loss/head ownership explicit. Full event schedules—not only bubble formulas—show forward/gradient dependencies and per-microbatch retention. The default conditional M=8 services yield GPipe .337s versus 1F1B .347s. GPipe saved/communication reservation peaks are about [1.929,1.929,1.929,2.566] decimal GB, while 1F1B is [0.966,0.726,0.485,0.323] GB. This is a partial activation reservation with opaque per-stage service times, not complete device memory or measured throughput. 1F1B is not guaranteed to improve makespan under arbitrary service/link asymmetry.

Public training_matrix/nonmatrix work is reused and conserved. The stage-specific actual work rows show head asymmetry even when a caller deliberately supplies equal service times. Time does not automatically follow FLOPs; callers may provide measured stage timings later. A claimed full training memory peak needs additional GEMM saved state, persistent state, gradients and workspace. Keep C55 original long-sequence/MoE/runtime extensions open.
