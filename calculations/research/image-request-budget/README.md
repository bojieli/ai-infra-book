# C66 图片文件请求预算候选

本候选只计算给定文件元数据和阶段时长，不执行RAW/JPEG解码、VAE、图片精修或网络请求。未接公共CLI/正文，未生成图，不据此勾选C66。

`calculate.py`使用标准库Fraction。默认原例：30,000,000 bytes上传、5,000,000 bytes成片、20/100 Mbit/s、残余请求RTT0.1秒、模型0.3秒；完整成片12.8秒，模型降为0.03秒只省0.27秒。准备/连接/队列/编解码/输出使用的默认零值均为声明教学假设，不是测量。

完整顺序是输入准备→额外压缩→连接→单次请求往返预算→上传→排队→输入解码→额外解压→模型→成片编码→下载→输出使用。RTT只作为排除字节发送/建链的残余预算计一次，其显示位置是串行记账位置，不宣称真实往返整体发生在上传之前。连接复用仅去除额外建链，不去除请求传播。

压缩需要明确传输bytes、额外编解码时长、相同质量契约和调用方授权；契约是条件输入，不是质量验证。默认格式名称RAW/JPEG不建立任何压缩等价性。压缩越过带宽阈值可能得不偿失；节省为零、无额外开销、永远不赢分别给状态。未知必需时间/速率拒绝，未知本地时间保留null；本地剩余预算非正时不存在有限上行速率使远端更快。

完整成片和预览不混用：候选仅有完整成片时间，preview保持null；不宣称预览或分块路径已经实现。`result.json`固定原例、模型加速、连接复用与5档上行/压缩/本地时间比较。

运行`python calculate.py`再生固定结果；`python check.py`核原值、0.27秒节省、等时阈值两侧/等号、阶段守恒、零收益边界与非法输入。检查独立手算关键公式，不验证实际文件、编解码质量或生产网络；当前作者自检尚不代替另一审阅者验收。
