## 1. C77: decoded PCM to actual Omni audio-encoder input

**Original requirement:** PLAN.md:190 explicitly retains original-waveform preprocessing; outlines/extensions/03-推理与训练负载.md:89 requires following speech through acquisition, encoding, language and playback, counting frames/blocks separately. outlines/02-模型架构.md:301 includes the official encoder→Thinker→Talker path. Existing `omni_audio_encoder.py:146` explicitly begins at valid precomputed mel frames and excludes resampling/STFT/mel/log normalization and raw masks. `omni_understanding.py:38–59` accepts mel lengths and connects their encoded positions to language, so rebuilding that Transformer/request account would be duplicate work.

**Missing computation:** the source-defined PCM length/padding→windowed STFT→power→128-bin mel→log/dynamic clipping/normalization→mask/valid-length transformation and bytes entering the existing encoder. The locked processor config already specifies 16 kHz, hop 160, n_fft 400, 128 features, dither 0, max 4,800,000 samples and 30,000 frames. Fixed extractor and audio utility code still need a minimal official-source lock; no such feature_extraction/audio_utils source was found in current public sources. Do not infer padding from an approximate seconds-to-frames formula.

**Implement independently:** one decoded mono FP32 16 kHz waveform first; other rates reject unless an independently specified resampler is added. Fix the exact official extractor version and its CPU/PyTorch or NumPy branch. FFT operation counts depend on implementation: choose and disclose an exact reference algorithm, or retain vendor FFT internal work as an explicit primitive while providing exact dimensions and interfaces. A naive DFT cannot be labelled the actual library FFT. Count pad/reflect/window/power, mel matrix, clipping/log/scaling and masks separately; outputs feed the existing encoder exactly once. Audio decode, resampling and runtime latency stay outside scope unless actually implemented.

**Acceptance:** compare numerical mel/masks against the fixed official code on zero, impulse and deterministic nonzero waves; include hop boundaries, reflect-padding short-input behavior, exact maximum/truncation boundary and mixed lengths. Verify valid-frame→encoded-position bridge against `encoded_length`, temporary shapes/dtypes and no duplicate encoder matrices. Public candidate must have a portable test, source lock and short waveform scenarios. This finite frontend closes a concrete missing stage, not the whole C77 runtime.

## 2. C33: join Qwen235 placement to token/expert execution and communication ownership

**Original requirement:** PLAN.md:115; outlines/06-超节点.md:103–117 requires EP/expert TP/attention TP/service-replica groups with data ownership, actual remote destination sets, per-expert matrices and busiest device. Experiment 6-3 includes multiple models and bandwidth/latency sensitivity; the first independent closure should be the already fully specified Qwen235 branch.

**Already available:** `qwen235_placement.py:14` supplies TP/EP/PP local shards and capacity; its scope at :263–270 says EP attention/KV replicas process the **same cohort**. `moe_dedup.py:12` instead accepts separate tokens per source rank; `grouped_experts.py:9` accepts expert counts and a different contiguous/striped owner model. These are useful subaccounts but are not a shared identity/ownership execution contract.

**Missing computation:** given one route table `[layer, request_id, position, selected_expert_ids, weights]`, derive local expert rows/TP shard work and the necessary message graph from the *same* eight-rank layout. A critical counterexample prevents naive concatenation: if every EP already holds the same cohort's attention output, its expert inputs are local and an extra source-token dispatch is unnecessary; cross-EP output combination remains necessary. A sharded-token-attention organization is a separate execution policy, not a silent reuse of the replicated-attention capacity formula. Include TP partial outputs, EP sums and PP hidden transfer exactly once.

**Implement independently:** BF16 TP2/EP4/PP1 and TP1/EP4/PP2 first; fixed official Qwen235 config/index and explicit synthetic routes (clearly labelled) suffice. Use common-cohort ownership first. Metadata sizes, wire dtype, network startup/bandwidth and workspace are explicit inputs, not inferred measurements. Include balanced, hot-expert and equal-histogram/different-token-destination cases. No V4 training work is duplicated.

**Acceptance:** all token-expert assignments conserved; local expert matrices sum to the real adapter; unique expert weights and KV match placement; every remote message has a consumer without fabricated dispatch; TP/EP partial sums reconstruct a small direct MoE numerical result; PP/head endpoints and busiest-rank capacity limits hold. Report analytical resource bounds only. Broader C33 four-model scan and calibrated runtime remain separately pending.

## 3. C56: training input supply competes with checkpoint writes

**Original requirement:** PLAN.md:150; outlines/10-训练系统.md:163–175 explicitly asks samples/s, input bytes/s, CPU preprocessing, length packing, pinned staging/H2D and checkpoint contention. Experiment 10-6 is marked basic calculation. This requirement is independent of V4 optimizer implementation.

**Already available:** `checkpoint_async.py:12` models finite snapshot slots and a serialized writer; checkpoint reshard/baseline/fault/resume cover persistence and recovery. `host_transfer.py:10` and `stream_buffer.py` provide transfer/FIFO mechanics. The training input reader/CPU packing supply and its shared storage-resource competition are not inputs to the checkpoint simulator, so existing checkpoint outputs do not answer whether input starvation occurs while writes run.

**Implement independently:** a finite Qwen8 training stream with explicit per-sample stored bytes and token lengths, CPU preparation times, token/label/mask wire dtypes, pack policy, bounded host/device slots and caller device-consumption time. Join reads and checkpoint writes on an explicit shared or independent storage service; use existing real model state bytes for checkpoints, not a rounded parameter label. CPU core count, compressed bytes/token and bandwidth are workload assumptions. A V4 payload can later be an explicit byte input without pretending its optimizer layout is complete.

**Acceptance:** sample/token conservation including tails and padding; exact input transfer tensor bytes; independent event enumeration of read→CPU→H2D→consume and checkpoint durability; finite-buffer backpressure; byte and core-second demand vs supplied service; zero-checkpoint, independent-storage, write-bottleneck and CPU-bottleneck cases; before/after idle time and buffer byte-seconds. Distinguish predicted idle intervals from a real device idle trace. Reuse transfer/state formulas instead of copying their work into another total.
