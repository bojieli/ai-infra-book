# C13 Qwen3-235B eight-rank placement contract (pre-implementation)

Model evidence: official Qwen/Qwen3-235B-A22B revision 8efa61729e24bd65b1d152b5ab5409052aa80e65, locked config and checkpoint index. Existing qwen3_moe.weights enumerates shapes. Require expansion of every layer template to match the complete checkpoint-index key set and require BF16 parameter bytes to match index metadata.total_size=470187269120. Index identifies keys/shards and aggregate bytes, not per-tensor header shapes; shapes remain config/implementation-derived and will be labeled so. No new weights or model family.

Proposed calculate(tp=2,ep=4,pp=1,length=8192,capacity_bytes=80*10**9,workspace_bytes=2*2**30,group_size=128,scale_bytes=2). Exactly tp*ep*pp=8, no DP. Rank identity (pipeline_stage,expert_rank,tensor_rank). All EP ranks participate in the same request cohort; attention is explicitly replicated across EP groups. EP does not imply independent request batches, and KV is not divided by EP. This is a declared valid ownership organization, not an assertion that all serving runtimes implement this exact schedule.

Pipeline: contiguous balanced layer ranges, first remainder stages get one extra layer (94 is not divisible by every PP). Embeddings reside only stage0; final norm/head only last stage. All per-layer tensors and KV belong to the owning stage. First/last stage asymmetry must be preserved.

Attention TP: Q heads split equally; O projection splits matching input columns. K/V heads partition when TP<=4. TP=8 replicates each physical KV head across two TP ranks, mapping rank to floor(rank/2), aligned with its contiguous Q-head slice. K/V projections and KV bytes replicate accordingly. Hidden RMS norms, Q/K per-head norm vectors replicate on every TP/EP rank. No sequence-parallel KV saving assumed.

MoE EP: assign 128 experts in contiguous disjoint ranges to EP ranks. Each expert's gate/up output channels and down input columns split across TP. Router weight remains full BF16, replicated across TP and EP; no shared expert exists in this config. All experts remain resident, regardless of top8 activation. Router parameters are persistent; token-specific router logits, probabilities and dispatch indices are temporary workspace, not permanent per-layer allocations.

Embedding/head: vocab-row sharded across TP, replicated across EP, kept BF16. Their chosen vocabulary 151936 divides all supported TP values. Final norm and all 1D norms remain BF16. Attention and expert eligible matrices use either BF16 or declared symmetric rowwise 8/4-bit grouping. Apply packing to the LOCAL shard shape, including down/O column slicing; rows independently round bits to bytes and ceil(local K/group_size) scales. Scales are scale_bytes each; no zero point. Storage is teaching format, not a released quantized checkpoint or kernel capability claim.

Per-rank result: layer/expert/head/vocab ownership, tensor categories with local shapes/copies/source identity, logical parameter count, payload/scale bytes, replication and unique-coverage conservation; BF16 K+V per request = 2*local_layers*local_KV_heads*128*length*2. Device budget bytes explicitly decimal capacities. Per rank maximum request count uses (capacity-weight-workspace)//KV; cohort maximum is min over ranks, zero when any rank cannot fit weights plus workspace. Do not sum free memory across ranks. Weight residency excludes temporary dequantization/collectives/allocator pools; supplied workspace is a conditional reserve only, runtime peak remains unknown.

Metadata: explicitly distinguish quantization scales, tensor ownership metadata as host-side descriptive records (no fabricated device storage), router BF16 weights, and runtime dispatch/index metadata whose sizes depend on token batching and implementation and remain within unknown workspace. No routing trace or balanced route histogram changes resident expert capacity.

Representative scenarios: TP2 EP4 PP1; TP4 EP2 PP1; TP2 EP2 PP2 (47 layers/stage); TP1 EP1 PP8 (12/12/12/12/12/12/11/11 layers). Cover each 8x24GB and 8x80GB, 8192 and32768 context, all BF16/8/4-bit. Include TP8 EP1 PP1 as explicit KV-replication regression and group_size1000 to expose post-shard scale rounding. At least four independent closed-form per-rank hand calculations, metadata tail checks, index full key/count/bytes conservation, illegal topology and boundary +/-1-byte tests. C13 remains open beyond this declared organization; no performance or communication-time conclusions from capacity.

Execution consistency: after attention, TP row-parallel O output is summed inside each EP replica; identical attention inputs give the same hidden state on every EP replica. Router/top8 decisions must be identical across these replicas. Each EP evaluates only its owned selected experts, sums TP partial down-projection outputs, then sums EP contributions (each expert contribution exactly once) and broadcasts the complete hidden state for the next attention. PP boundary forwards the same cohort hidden state to the next stage's corresponding TP/EP groups. This declares a consistent but potentially communication-heavy execution; collective buffers/time are not calculated here. EP is not used to multiply the allowed cohort requests.

Updated scenario grid includes the original C13 48GB budget as well as 24GB and80GB. All four organizations, both retained lengths and all three storage formats remain in the grid, including failures.
