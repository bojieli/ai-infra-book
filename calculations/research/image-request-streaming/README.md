# 同图分块与预览：显式依赖候选

这是C66图片请求预算的有限分块变体，依据 `outlines/12-端边云协同.md` 12.1.2及同名扩写：只有模型依赖允许时上传/处理才能重叠，首预览与完整成片分别计时。仅写本research目录，没有公共接入或真实图片处理/传输。

`calculate.py`接受给定文件分块元数据、上/下行速率、独立前向/反向传播、准备/建链/最终拼接时间，并输出逐事件依赖、资源、起止时间和两个交付时刻。它不接收整体RTT预算，也不借用串行预算里放在上传前的RTT阶段作为真实传播时间线。

## 同输入、同工作、不同屏障

默认3块，每块输入10,000,000 bytes；成片输出块分别1,000,000、2,000,000、2,000,000 bytes。每块处理0.1秒、编码0秒；总输入30MB、成片5MB、处理0.3秒与原例相同。上行20Mbit/s、下行100Mbit/s，前向/反向传播分别0.05秒；连接已可用，准备/拼接均声明0秒。

- `whole_image`：所有输入块到达后才开始处理；所有成片块编码完成后才允许成片下载。仍执行同样每块处理/编码工作，故是显式屏障对照，不宣称实际整体模型与分块runtime耗时相同。
- `independent_blocks`：必须显式传 `independent_blocks_authorized=True`，且每块 `required_inputs`必须等于自身索引列表 `[i]`。这表示调用者授权模型、文件编码和成片块无需其他块、halo或全局attention，且最终业务质量不变。仅有文件分块不满足这个条件，实际RAW/JPEG精修不由本候选证明可分块。

三项独立串行资源是uplink、server（处理和所有编码共享）及downlink。上传和服务端按块索引顺序执行；下行采用制品就绪时间FIFO、同刻预览优先、不可抢占。每条传播事件接在相应序列化之后，不占链路服务资源，允许多块同时在途；不得把N块的传播延迟相加称链路序列化占用。最终拼接仅在全部成片块到达后开始。

## 预览有独立依赖、成本和质量

可选preview元数据包含 `after_processed_chunk`、`bytes`、`encode_seconds`及独立 `quality_contract`。预览依赖已处理的前缀0..指定块，额外编码在该块编码后占用server，额外bytes与成片共同争用downlink。这里的前缀预览可以是局部视图，**不是默认全图预览**；要依赖全部已处理块，应指定最后一个块索引。预览质量合同不能替代最终质量合同。

默认预览在处理第一块后编码，500,000额外bytes、0.05秒额外编码，质量明确为已处理前缀的较低质量局部预览。因此有预览时总下行5.5MB，不能继续按5MB报总传输量；没有预览元数据时首预览仍为null。

| 模式 | 局部预览到达 | 完整成片可用 |
|---|---:|---:|
| 整图屏障，无预览 | 未声明 | 12.80秒 |
| 独立块，无预览 | 未声明 | 12.36秒 |
| 整图屏障，额外局部预览 | 12.29秒 | 12.85秒 |
| 独立块，额外局部预览 | 4.32秒 | 12.36秒 |

独立块输入到达4.05、8.05、12.05秒；处理/编码完成4.15、8.15、12.15秒，无预览成片块到达4.28、8.36、12.36秒。加预览后，首成片块4.15秒先开始下载，4.20秒就绪的预览必须等至4.23秒，再序列化0.04秒并反向传播0.05秒，因此预览4.32秒到达。不能将4.20秒编码就绪或4.27秒发送完当客户端收到。

整图模式全部输入12.05秒到达；无预览处理结束12.35秒，回传0.4秒及反向传播0.05秒得到12.8秒。额外预览编码延迟最终编码完成至12.4秒，完整成片12.85秒。提前局部预览没有自动缩短完整成片。

## 验证

运行：

```sh
python3 calculations/research/image-request-streaming/calculate.py
python3 calculations/research/image-request-streaming/check.py
```

结果在 `result.json`，核验在 `check-result.json`。检查通过5037项断言，含54组上传/服务端/下行瓶颈参数网格和11项非法输入。核验从独立手算与max-plus标量递推开始，不用候选汇总时间作为期望；逐事件检查依赖先后、三项串行资源不重叠、上下行bytes守恒及每次传播的位置。

另有一个可手算的争用反例：两块各1byte输入、2bytes输出，上/下行均8bit/s，各处理1秒、零传播。无预览下载区间[2,4]和[4,6]，成片6秒可用；额外3bytes零编码预览在2秒与首成片块同时就绪，按声明同刻优先规则先下载[2,5]，两成片块随后[5,7]、[7,9]，预览5秒而成片延至9秒。它证明预览争用必须计入，不证明该优先策略最优。

## 仍未证明的事项

这是调用者声明独立依赖和工作量下的调度计算，不证明某RAW格式、JPEG编码器或精修模型真实支持独立块；质量仅为显式合同，不是像素/视觉质量测量。没有codec执行、WAN流控/丢包、实际队列、握手往返或未声明的全局拼接工作。准备、连接、每块编码及最终拼接的零值都是教学假设。

与串行图片预算组合时，应二选一相应执行模型，不能把整段RTT、整图模型耗时或整图文件编码再次叠加。分块候选不扩展到ASR/TTS/C67，也没有宣称实际服务可行性或deadline保证。公共CLI、场景、图和正文链接由主线独立接入。
