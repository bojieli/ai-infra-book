Original requirement: `outlines/extensions/02-模型架构.md:261`, Experiment 2-9, asks to put four-model request work into capacity, Roofline and link models. `research/ch2-6-coverage-audit/mapping.json` T08 correctly remains partial. Existing request totals alone do not identify arithmetic precision or physical traffic.

One input forward produces the first output; only G−1=3 subsequent forwards run, and final retained length is 131. Each model has four logical forward calls. No restore transfer is required by S=0. This does not imply identical tokenization or quality.

Use one public `h100-sxm` device (H100 SXM 80GB), not an implicit eight-GPU aggregate. Preserve the selected official record and its complete supporting evidence. Existing official-source supply rows are BF16/FP32-acc Tensor dense 989.4 TFLOP/s; FP8/FP32-acc Tensor dense 1978.9 TFLOP/s; FP32 vector dense 66.9 TFLOP/s. Nominal capacity is 80×10^9 bytes; memory bandwidth is 3.35×10^12 bytes/s. These are official peak conditions, not sustained service or allocatable free memory. Sources are existing `nvidia-h100` Table 3 and `nvidia-h100-page` product specifications; use hardware.select_peak rather than searching numeric maxima.

Sparse attention or routed experts do not establish NVIDIA structured 2:4 sparsity. No structured peak is admitted. FP8 nominal accumulator dtype does not establish full internal IEEE FP32 arithmetic; preserve supporting_evidence concerning the relevant instruction scope. Do not substitute TF32 for unmodified FP32 work.

## Precision admission by model

**Qwen8:** projection Q/K/V/O, gate/up/down and head have an explicitly selected uniform BF16 mathematical account, with FP32 accumulation a separately declared Tensor arithmetic interpretation. QK can use this same input interpretation. Crucially, the unchanged request stores P as FP32 and V as BF16: PV cannot silently inherit the BF16 Tensor rate. For the primary unchanged request, `matrix_pv_mixed_or_unresolved` has known FLOPs and a null service rate until a cast or mixed-input algorithm is specified. A future explicitly FP32-upcast-V alternative may use FP32 vector arithmetic, but its casts/bytes must be separate; a BF16-probability alternative changes the request contract and cannot replace the primary result. FP32 scalar reductions map only under the explicit aggregate vector-provider assumption; special ops retain named unknown rates.

**V4 Flash / Pro:** use original attention/expert matrix names and layer IDs. The existing Flash map provides candidate classifications: quantized attention projections and shared/routed expert products FP8; `wo_a_grouped`, `index_weights_proj`, selected attention QK/PV and rectangular index QK BF16; compressors, router, mHC and final head FP32. Routed FP4 is storage unpacked/dequantized to the selected FP8 compute path, never an FP4 hardware peak. Quantization/scale work remains scalar work and must not be discarded. Transfer this map to Pro only after checking its fixed same-function source dispatch and the actual named rows. Do not add sparse-kernel tile totals on top of effective attention work. Preserve source implementation/FP8 numerical compatibility as unknown on H100 if not demonstrated; a rate-normalized arithmetic budget is not proof the official kernel runs on this GPU.

**K3:** retain the fixed-config logical shapes and unresolved 69-layer A_log [96] versus checkpoint [128] conflict. Verified deprecated wrapper aliases do not resolve it. Router FP32 work is separately recoverable from `components.experts`; logical MLA BF16 teaching products may be offered only with that explicit interpretation, not as actual checkpoint execution. KDA matrix/state update, chunk algorithm products and mixed projection/expert quantization require separate input/accumulator classification; state FP32 alone does not make all operands FP32. `unclassified_matrix_flops` remains nonzero where evidence is incomplete. Never put total K3 matrix FLOPs over BF16 or FP8 peak.

**All four:** ordinary scalar FLOPs are not counts of homogeneous GPU instructions. A vector ceiling is a declared arithmetic-resource model. exp/rsqrt/sigmoid/compare/max/mask and other named special work keep separate counts and unknown rate unless a concrete implementation/provider is independently fixed. No guessed special rate in the primary scene.

## Capacity and physical interfaces

Qwen's uniform BF16 weights plus final logical BF16 KV form a necessary resident-capacity check for the explicitly no-offload single-device representation. Workspace, activations and allocations remain absent: a pass is necessary-only. For V4, keep checkpoint packed bytes, uniform BF16 comparison bytes, logical state and source allocated cache/compressor bytes distinct. Hash checkpoint I64 versus runtime I32 and other conversions prohibit calling the entire checkpoint a proven runtime minimum. Source cache allocation can separately establish a necessary state allocation condition if its exact implementation scope is fixed. K3 checkpoint mismatch prevents runtime admission; its large uniform-BF16 comparison is useful only as a declared alternative-storage comparison.

Known interfaces are neither disjoint nor necessarily HBM. Qwen weight-read-once/operator, activation operands and KV history/append need overlap labels. In particular, KV history payload must not be added to activation operands again. V4 uniform BF16 expert weight comparison and actual packed/scale visits are alternative representations of overlapping work, never cumulative traffic. Source gathered sparse KV traffic is a selected kernel interface, not measured HBM; multiple query visits and on-chip cache reuse matter. K3 recurrent read-once/write-once is a call-boundary logical payload, not T HBM transfers during chunk prefill. State resident bytes are capacity, not request traffic.

The primary output therefore reports interface-normalized times separately with `physical_resource='unspecified'` and no HBM interpretation. Only caller-explicit, source-justified HBM transactions can populate a physical HBM lower-bound row. Existing stage_resource_bounds' automatic interface_bytes/HBM division is not reused as a physical assertion.

## Links and serial bounds

Do not manufacture TP/EP/PP topology merely because a single H100 cannot host a model. Shared-storage, CPU-offload, PCIe, NVLink and network transfers require an explicit placement/ownership contract. S=0 establishes zero prefix-restore payload for this scene, but complete communication time is still null: it does not prove all other traffic is zero. Weight load frequency, token transport encoding, offload schedule and directed link paths are unknown. No bidirectional aggregate bandwidth may be applied as a one-way rate without a direction proof.

Within an admitted reference arithmetic path, calls are serial. Compute a per-call maximum over known resource budgets, then sum calls; optionally preserve verified layer ordering before summing stage maxima. Pooling all work into a single maximum is separately labelled weaker. Do not sum maxima over arbitrary component buckets that may overlap. Unknown demand/rates preserve complete accounted bound=null while exposing a known-resource subtotal. If capacity or implementation admission fails/unknown, label arithmetic-normalized figures as conditional comparison only, not an executable latency lower bound. Full request latency, actual peak and quality equivalence stay null.

## Minimum implementation acceptance

- Fixed 0/128/4/1 request replay equals original for every numerical logical field. Each model's classified + unclassified matrices/scalars/specials equals its original per-call and total account.
- Qwen default FP32 P cannot select BF16 PV; FP4 storage cannot select FP4 execution; sparse route cannot select structured peak. Missing special rates must propagate null.
- Pro uses real per-layer counts; all three decode positions retain compression events and head work. Static weights are resident once, not multiplied by four calls.
- Partial/overlapping byte labels cannot feed HBM or link totals without explicit admission. Capacity success stays necessary-only; K3 shape conflict and V4 runtime-format boundaries remain visible.
- No complete runtime or cross-model winner is emitted. This closes a finite T08 bridge, not its quality-constrained model-selection experiment.
