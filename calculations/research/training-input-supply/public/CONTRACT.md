# C56 finite training-input supply and checkpoint contention

Fixed Qwen3-8B configuration supplies P=8,190,735,360 and the same 14P checkpoint layout as public checkpoint_async: BF16 weights, FP32 master and two moments. Gradients, RNG/metadata and arbitrary optimizer state are outside that payload definition. Device training time is an explicit caller input, not inferred from model FLOPs.

Inputs are pre-tokenized sample records: token count including any caller EOS, stored byte count, CPU preparation service. One CPU worker handles packs. Next-fit packing keeps each sample intact; oversized samples reject, no dropping, split or implicit special tokens. Every pack pads to the fixed token capacity. Wire representation is int64 input IDs, int64 labels, boolean validity and int32 segment IDs (21 bytes per padded token); segment-aware consumption is assumed. Actual tokenization, label-value generation, quadratic masks and GPU mask implementation are not modelled by these geometry counts.

Each pack has R(read)→P(CPU prepare/pack)→H(H2D)→C(device consume). R and P preserve pack order. Host slots are reserved from R start to H end, conservatively holding stored input plus wire tensors for the whole interval. Device slots live from H start to C end. Fixed round-robin slot identities impose R[p] after H[p-host_slots] and H[p] after C[p-device_slots], so finite buffering applies backpressure. Distinct host/device pools are not merged.

After every k consumed packs, snapshot S reserves the device and blocks the next consumption. Snapshot slots live from S start through W(write completion). Writes serialize. Reads and writes use either one shared storage resource or independent read/write resources with the same declared bandwidth. Writes are indivisible full payload jobs. A deterministic earliest-ready list scheduler, reads winning equal-ready ties, chooses one nonpreemptive schedule; no optimal/fair driver arbitration is claimed. Zero snapshot/consume/packing durations are legal boundary scenarios.

Exact rational seconds preserve event comparisons and byte-seconds. Reports distinguish training completion from final checkpoint durability, useful device service, snapshot service and residual device wait (including startup, input dependencies and checkpoint-slot waiting). Residual wait is not automatically all input starvation. Shared-versus-independent/no-checkpoint scenarios isolate different conditions; no measured idle trace is implied. Target samples/s and input/H2D rates use useful consumption time as a conditional no-idle target.

CPU core count is fixed to one, not silently parallelized. Bandwidth, sample compression ratio and service times are user workload assumptions. Snapshot host RAM, packed buffers and device buffers are explicit reservations; no hardware capacity feasibility or complete runtime peak follows. Durability equals write completion here; storage durability lag/fault behavior belongs to separate existing checkpoint models.

Five test groups cover 32 slot/checkpoint/resource combinations, source/CPU/H2D/consume dependencies, exact non-overlap, independently swept buffer peaks/slot occupancy, sample/token conservation, shared-storage starvation, CPU bottleneck, zero service, replay and invalid inputs. A future independent review is required before public integration.
