# Independent C36 growing remote KV audit

No correctness or scope blocker found in calculate.py. Independent checker: `python calculations/research/growing-remote-kv/check.py`. It passed72 explicit identity/epoch scenarios across both models, both placement policies,1/2/3 replicas, B1/B2, and0/1/4 steps;16 local-tail boundary cases;12 invalid inputs/context-overflow cases; and2 maximum-context zero-step cases. `check-result.json` records initial position identities, each replica's committed position set, local tail identities, and exact rational communication barriers.

Geometry agrees with pinned configurations: Qwen3-8B full-history KV147,456bytes/position/request, Qwen3.6-35B-A3B20,480bytes/position/request. Qwen3.6 local fixed state is62,914,560bytes recurrent plus1,966,080bytes convolution =64,880,640bytes/request. Batch multiplies every per-request byte/pair term. QK/PV uses prior+1 positions, while remote history reads exclude the current position.

The position-set proof starts every replica with prompt positions0..prompt−1. In remote_all, stepn reads exactly0..prompt+n−1 from an already-committed replica, creates positionprompt+n, appends it to every replica exactly once, and reaches the all-replica barrier before the next read. In prefix/local-tail, remote sets remain the prompt forever, while local new positions accumulate and supply only the previous tail at each step. The disjoint union of old remote, old local, and current positions equals the complete attention operand history.

Network arithmetic independently sums initial full-prompt sends once per destination, remote prior reads once per step from one replica, and current-position append sends once per destination only for remote_all. Local tail reads and current local operands do not accidentally become remote traffic. Replica counts affect initial copies, append traffic, and physical storage, but not read payload. Final unique history is distinct from remote physical replicated storage. The original prompt source's release remains explicitly unspecified.

Timeline checks independently reconstruct startup+bytes/B for each initial send, remote read, and sequential replica write using exact fractions. Every write start/commit and every subsequent read start matches the declared serialized communication cursor. Zero steps still include initial-copy communication and fixed local state but have no current append buffer, no token communication, and no local tail. These are valid initialization-only ledgers.

Tail budget check is exact: need−1 fails; need and need+1 pass. It covers only newly-added full-attention KV. It intentionally excludes fixed DeltaNet/conv state, weights, retained prompt source, transport buffers, and peak coexistence; actual_task_feasible remainsnull. Current append buffer is reported separately and is not falsely added to an overlapping grown local tail as a peak-memory claim.

Scope remains appropriate: all-replica commit is a declared illustrative protocol, not a validated hardware/engine consistency mechanism. Communication ordering compresses unknown local computation and is explicitly a communication-only skeleton. actual_decode_seconds and actual_task_feasible remainnull. Projections, experts, DeltaNet arithmetic, transport ACKs/retries/control messages, failures/recovery, and real overlapping schedules remain outside this ledger. Reader report should retain those limits and should not call this a complete decode runtime or a demonstrated remote-addressing implementation.
