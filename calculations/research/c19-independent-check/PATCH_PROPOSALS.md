# Proposed follow-up changes — not applied

These proposals are local review deliverables only. They deliberately avoid reimplementing the calculator. The seven `KnownBugRegressions` tests in `test_independent_scaling_law.py` describe reviewable intended behavior and can run in strict mode against a future implementation.

1. **Handle the E=0 boundary deliberately.** In the conditional fit, distinguish a tiny negative intercept attributable to numerical error from a substantively negative estimate. Use an explicitly justified, scale-aware tolerance. A boundary refit with E fixed to zero is preferable to silently clipping coefficients without recomputing residuals. Preserve positivity requirements for A and B. Recompute candidate SSE using the law actually returned. Validate against B1 and add a case that must still reject a materially inadmissible fit.

2. **Report per-pair fit rejection.** Validate pair shape and finite positive exponents first. Skip numerically rank-deficient/ill-conditioned candidate designs, recording the pair and reason, and select among successful candidates. Raise a useful error if no candidate remains. Avoid broad exception swallowing: malformed schema and invalid numerical input should remain errors. Preserve the present all-rank-deficient rejection check. B2 must pass without changing the good pair's coefficients.

3. **Evaluate normalized powers and budget allocation in logs.** Compute `logQ=log(C)-log(k)-log(N0)-log(D0)` and `logRatio=log(a)+log(A)-log(b)-log(B)`. Combine directly to obtain `logN`, validate/derive bounds, and clamp in log space before exponentiating where appropriate. Obtain D without overflowing intermediate products. For each loss term use `log(A)-a*(log(N)-log(N0))`, analogously for B,D, before exponentiation. Guard final sums. Apply the same principle to target D and transformed fit columns, keeping conditioning checks. The three B3 examples have finite true answers and should return them; rejecting them merely because an avoidable intermediate failed would not meet these regressions.

4. **Reject non-finite derived quantities before classification.** Check loss, training FLOPs/costs, per-call cost, lifetime cost, SSE/RMSE, and crossing arithmetic for finite representability. Raise descriptive `ValueError` rather than choosing a candidate with infinity/NaN. Preserve intentional `None` for an undefined crossing and for analytically infeasible sizes; do not turn arithmetic failure into physical infeasibility. Keep strict serialization as a final defense. B4 exercises the direct helper contract, while the existing passing independent check confirms `calculate` already rejects non-finite serialized results.

For genuinely unrepresentable final values, explicit rejection is sufficient; arbitrary precision is not required for this teaching tool. Preserve existing public result fields and documented proxy limits. A future patch should rerun both suites, strict regressions, and the three scenario comparisons. No claim is made here that these unimplemented proposals have passed tests.
