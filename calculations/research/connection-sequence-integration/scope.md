# C68 continuous-request public integration scope

The public `connection-sequence` command uses one event queue, two directional FIFO serializers and connection-owned directional congestion credit across four requests. It preserves pending ACKs, their physical reservations and later credit updates. Request-local file prefixes and packet identities do not leak across requests. Resetting congestion windows does not erase outstanding credit; old ACKs continue to update their original connection. Directional initial values remain distinct.

Seventeen registered scenarios cover 30MB upload/5MB response and 64KiB bidirectional requests, four handshake/window strategies and both response-received/ACK-quiet submission triggers, plus a loss confined to request 2. Think time is explicit. A four-message or two-message declared graph is serialized message by message; these are not actual TLS/QUIC handshake implementations. Ticket validity is an external condition; rejection/fallback and replay policy are not implemented. There is no idle window decay or real congestion controller. At most one selected initial data transmission is lost across the sequence; any other effective timeout is rejected.

The numeric candidate remains frozen in `../connection-sequence`. Public integration replaces duplicate input validators with the existing shared validators and adds verification of three locked RFC original sources. Complete result payloads for all 17 scenarios match the candidate except the added `reference_sources`. The new dedicated Markdown renderer separates request submit, connection-ready, complete-response and last-ACK endpoints and includes all events. The public CLI supports editable JSON input; the unified reproduction command generates JSON and Markdown for every scene.

The candidate's independent audit replays 118 small exact event traces and rejects six invalid inputs; these are independent physical FIFO, identity, connection credit and hand-oracle checks, not measured network performance. Five public tests exercise the four-strategy hand derivation, nonzero pending ACK interference, reset debt and distinct directional warm windows, selected-request loss and eleven invalid inputs. All 17 full public payloads were compared with the frozen candidate, and 34 actual CLI invocations compared JSON and Markdown output.

C68 still includes actual protocol/0RTT acceptance and rejection, a specified real congestion controller, ASR/TTS/screenshot/media delivery deadlines, multistream behavior and the complete Figure 12-4. This integration closes the finite sequential-request subtask, not all C68 or the whole book. Source hashes and the full-project verification performed at integration are recorded separately in acceptance.json.
