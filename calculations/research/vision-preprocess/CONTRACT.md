# C81 fixed RGB preprocessing contract

Input is one already-decoded contiguous HWC RGB uint8 NumPy array, on CPU. JPEG/PNG entropy decoding, ICC conversion, multi-image grouping and device transfer are outside this finite candidate. This choice adds an actual missing preprocessing stage without repeating patch projection, vision Transformer, merger/DeepStack or language work.

Use the already locked Qwen3-VL4 preprocessor configuration, with same-transformers-commit cbc1651a Qwen2VLImageProcessor TorchvisionBackend methods. The old model config's Fast processor name is not taken as proof of arbitrary AutoImageProcessor resolution: this candidate explicitly selects the fixed official torchvision implementation. It counts smart_resize geometry, HWC→CHW contiguous materialization, CPU disabled-grouping aliases, bicubic AA resize, fused rescale/normalize, patch/time layout materialization, grid tensor and optional visual entry cast.

Resize has align_corners=False, antialias=True, Keys a=-0.5. Torchvision0.22 routes CPU uint8 bicubic to native uint8; selected PyTorch2.7 generic non-AVX code generates coefficients in FP64, stores quantized INT16 coefficients in the FP64 buffer, multiplies/adds in INT32, and rounds/clamps to uint8 after each horizontal then vertical pass. Equal-size axes are skipped and an equal-size resize is a torchvision alias. Do not replace this with unqualified FP32 bicubic work, AVX or PIL counts. Normalization creates fused mean/std127.5 then casts image to FP32, subtracts and divides. A fresh coefficient cache has explicit initialization; the warm normalization-cache variant skips only that small setup. Resize coefficient tables are rebuilt per invocation, not assumed cached.

Semantic operand traffic includes repeated tap weights and broadcast mean/std; it is not measured DRAM or complete runtime footprint. Coefficient buffer allocation, retained normalization constants and final output sizes are explicit. Known per-element and polynomial arithmetic are counted, but TensorIterator metadata load counts depend on traversal/chunking; allocator and address/control machine instructions are not invented. Runtime peak and latency remain null. The selected logical/primitive budget is not a full CPU performance model.

Output processor pixel_values is FP32 with shape [grid_h*grid_w, 1536], grid_thw=[1,grid_h,grid_w]. Optional BF16 conversion belongs exactly once before existing vision projection; normalized temporal duplication is already present in the patch input width. The existing vision_encoding module can be called with resized_height/width and one image. Encoder cache identities/policies are not inferred.

Numerical proof runs verbatim AST-selected methods from locked official originals, with pinned torchvision0.22/PyTorch2.7 on non-AVX ARM CPU. Independently implement integer separable interpolation and explicit coordinate-loop patch ordering; compare every pixel/patch value, not just shape. Five full image cases, four additional strong-downsampling/single-axis kernel cases and five large/aspect boundary geometry cases pass. Six accounting/interface tests pass, including the existing vision input shape/byte contract. Large max-area reduction is geometry-only; no claim of full-size numerical/performance execution. This is selected-path validation rather than full Transformers loading or image-decoder testing.
