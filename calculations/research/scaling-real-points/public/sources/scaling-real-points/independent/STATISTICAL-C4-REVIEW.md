# Eight-point C4 statistical protocol: input follow-up

The revised protocol may treat losses on different validation samples as noisy estimates of a common C4 target. Identical evaluation samples are not required for statistical comparability. This follow-up supersedes any implication that sample-count differences alone prohibit fitting; the earlier strict same-subset gate remains historical. N>=2e9 holdout remains unchanged, and no points are removed because of loss values or nonmonotonicity.

For the eight log-matched points proposed after excluding the declared146m training-budget conflict, all final-validation logs name the same c4_validation/gpt2tok_c4validation_rerun_text_document source, the full0:1 selection and GPT2BPETokenizer with gpt2/vocab.json and merges.txt. The fixed official README defines this validation file from C4 en's official validation split using GPT2 preprocessing and append-eod. Logs refer to separate c4_subsampled paths for training. This supports a shared held-out population as documented by the official dataset split and preprocessing; it is not an independent raw-document hash/de-duplication guarantee.

Evaluation budgets6400/25600/51200 sequences of2048 differ, so noise and potential subset composition differ. Preserve those fields, avoid calling the observations repeated deterministic evaluations on the same samples, and report sensitivity rather than fabricated standard errors. The final-val run's training-path setting can be a placeholder used to load/evaluate the checkpoint: some names point to much smaller subsets. Do not infer D/U from that final-val placeholder; use the separate training source review and reported-coordinate protocol.

Author N estimates are unchanged and include embeddings. Each of these eight points also has logged hidden size/layer count for an Eq23 shape-derived N sensitivity column in N-loss-per-point-review.json. Neither rounded author estimates nor this formula are claimed as independently verified exact checkpoint counts. statistical-C4-eight-point-evidence.json binds the actual log lines and file hashes.

This evidence supports attempting the declared statistical fit and held-out predictions with limitations. Sparse two-dimensional design, batch/optimizer schedule variation and extrapolation uncertainty belong in the resulting diagnostics, not in an invented fit prohibition. Training D-coordinate conflicts and exclusions remain separately documented. This review does not itself fit or select hyperparameters.
