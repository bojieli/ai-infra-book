## 6.6 共享容量与远端访问

从局部不足、全局空闲的实际问题进入内存池，再分别检查冷状态和活跃数据的搬移频次。

### 6.6.1 局部容量不足与全局空闲

以作者早期 UB 内存池的设想进入：一台机器的计算已经很忙，内存却有剩余；另一台机器先被容量卡住。先判断借用容量能解决什么，再跟到后来的 KV cache 应用。

用四个节点各有 64 GiB 可用内存、同时需求为 80／48／32／32 GiB 的教学例子：总需求 192 GiB 小于总容量 256 GiB，仍有一个节点短缺 16 GiB。比较增加本地内存、迁移任务与从池中借用，区分容量节省、复制减少与实际访问成本；不把这个假设配置当成某款 GPU 的远程寻址能力。

### 6.6.2 内存借用与访问边界

按 UB OS 参考设计的内存导入、导出、借用与共享机制，画本地内存、远端内存和地址映射的关系。统一地址、可远程访问和缓存一致性分别解释；哪一方保留访问权、何时归还以及故障时怎样处理，回到具体机制。将容量与带宽分别算，不能把各节点标称内存带宽相加当成借用者可用带宽。

### 6.6.3 共享容量与 KV cache
