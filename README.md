## 这本书要做什么

> 本书通过量化估算、历史比较和实测，研究 AI 基础设施的资源约束、系统组织与演进。读者应能在给定模型、负载、设备和服务目标下建立资源模型，比较可行方案，并解释约束变化的影响。
>
> 分析方法与具体参数分开组织，结论随证据修订。

**主线是数据移动。** 从片上存储到跨地域系统，数据的位置、访问频率和执行依赖共同影响计算效率。对给定协议、算法与消息范围，可用以下模型作基础估算：

```
传输时间 ≈ 依赖轮次 × 启动延迟 + 传输字节 ÷ 有效带宽
```

排队、丢包恢复和资源竞争需要另行建模，避免重复计算已计入实测延迟或有效带宽的开销。基本记账规则在第 1 章的完整算例中引入：共享资源汇总工作量，串行依赖累加时间，充分重叠的最大值只给出理想下界。

**方法**采用量化估算、执行轨迹和测量校准，参考 Jeff Dean 与 H&P《计算机体系结构：量化研究方法》。分析依次建立需求、列出供给、检查资源与时间约束、比较候选改进，再复核完整系统。

**历史视角**关注负载、技术能力及资源条件的共同变化。各章的变迁表记录设计、约束、变化来源和证据，将历史事实与因果解释分别标明。

## 章节

全书分为**基础、执行与互联、系统**三部分。章名简洁、直观，不加冒号副标题；范围、问题与具体技术在章内展开。

| 部分 | 章 | 标题 | 范围 |
| :-- | :-- | :-- | :-- |
| **基础** | 1 | 认识 AI 基础设施 | 六层架构全景、请求路径、完整算例与基本记账规则 |
|  | 2 | 模型架构 | 从并行、存储与通信约束解释 Transformer 及其变体 |
|  | 3 | 训练与推理负载 | 推理、训练、交互任务与多模态流 |
|  | 4 | 加速器架构 | 芯片组织、存储层次、性能模型与架构演进 |
| **执行与互联** | 5 | 算子与运行时 | 分块与融合、算子编译、动态形状、图执行与本地部署 |
|  | 6 | 超节点 | Scale-up 域、域内集合通信与规模约束 |
|  | 7 | 数据中心网络 | Scale-out 网络与跨域集合通信 |
|  | 8 | 端边云协同 | 无线、设备协作、广域传输与数据放置 |
| **系统** | 9 | 单实例推理 | 状态管理、批处理、调度与服务目标 |
|  | 10 | 分布式推理 | 模型切分、阶段分离、路由与恢复 |
|  | 11 | 训练系统 | 并行、数据、检查点与 RL 训练闭环 |
|  | 12 | 任务调度与运行 | 多作业调度、模型路由、计量计费与环境运行 |
|  | 13 | 架构协同设计 | 模型、硬件、部署与费用的综合比较 |

第 1 章先用[六层架构全景图](skeleton.html#infra-panorama)标出应用与任务、模型与计算、训练与推理系统、编译与运行时、加速器与存储、互联与部署设施；作业调度、环境运行、观测和计费作为跨层能力，再沿一次请求解释协作。各章回到同一张图说明所在位置。

第 2 章从并行度、存储与通信约束解释 Transformer、GQA、MLA、线性与混合注意力、MoE 等结构，结合模型质量和训练稳定性分析设计理由。第 3 章分析训练、推理和交互负载，计算量按算子及阶段核算；分析方法随具体问题引入，并汇入附录。

第 4 章归入基础部分，承接模型与负载，解释硬件的计算供给、存储层次、执行机制和性能约束。第 5 章展开算子实现、编译与运行时，并用实际执行轨迹验证前章的模型。同一注意力计算依次经过数学依赖、负载形状、硬件数据通路与软件执行，再进入后续推理和训练系统；全书共十三章。

第 10 章讨论同一推理服务内部的请求路由、PD 池化与 KV 局部性；第 12 章讨论多个训练作业、模型服务和租户之间的资源分配、跨模型路由与计量计费，并承接沙箱、容器、虚拟机和环境镜像。第 13 章属于系统部分，综合检验模型与系统的联合选择。

## 定位

本书连接负载需求、算子执行、存储与通信代价、服务目标和架构选择，并用可检查的案例说明估算如何得到验证或修正。

现有作品各自站在栈的某一层上：**How to Scale Your Model**（DeepMind）方法同构，TPU 为主，算子达成效率与集合通信的实测分布不是它的重点；**Ultra-Scale Playbook**（HuggingFace）只有训练、只有 GPU；**MLSysBook**（Harvard / MIT Press）广度极大，前沿 LLM 基础设施的推导深度与一手案例不是它的重点；**Efficient Processing of DNNs**（Sze / Emer）止于芯片层且成书于 LLM 之前。本书写的是相邻六层之间的传导，从「制程与功耗作为输入约束」到「Agent 负载」，并用同一套代价模型横向比较 GPU、昇腾、TPU 等多种架构。

主要材料包括作者的《Unified Bus 背后的思考》、UB 协议规范和 OpenURMA（第 6、7 章），AKG 的 PLDI 2021 论文与 TVM、isl、Triton（第 5 章），[Queqiao 的语音与广域案例](case-studies/queqiao.md)（第 3、8 章），以及 OpenTallas、Pine 和 Agent 书的相关记录。综述用于解释设计取舍，规范用于定义行为，开源实现用于验证具体机制；分析、模拟、综合和硬件实测分别标注。

设备演进以相同算子比较 NVIDIA 与昇腾 910A、910C、950 的矩阵和向量配比、存储通路、搬运与同步。Cube 与 Tensor Core 在硬件层比较，Ascend C、CUDA、Triton 与编译工具在软件层比较；动态 shape 按适用范围、实现责任和实际代价展开。CloudMatrix384 论文 v2 明确披露 910C 的双 die 和 AIC／AIV 组织，v3 改用“Ascend 910”称谓，两个版本分别归档。端侧覆盖 Unsloth、Ollama、MLX、llama.cpp 和实际计算后端。历史参数保留年代，新算例依据固定版本资料复算。

UB 2.0.1 中文正式规范、UB 操作系统参考设计 2.0 中文版与昇腾 950 NPU 架构白皮书已取得并归档。950 的核内通路用于第 4 章，NDDMA、SIMD／SIMT 与同步的编程比较用于第 5 章，CCU 集合通信卸载用于第 6 章，UBoE 用于第 7 章；操作系统的设备直通与资源交付用于第 12 章。

重点讨论以下关系，并将设备执行的分析延伸到端边云的数据与任务放置：

| 边界 | 它存在的证据 |
| --- | --- |
| 算子与片上存储层次 | Flash Attention |
| 并行策略与互联 | 「TP 不超过 8」这条经验法则 |
| 模型架构与推理系统 | GQA / MLA / MTP |
| 超节点与制程功耗 | NVL72 的 72 |

## 写作原则

**分析方法与案例分开维护。** 正文说明可复用的方法，参数和具体实现记录日期、来源及适用条件。新的证据改变结论时，保留修订原因。

**行文采用正式术语。** 依次交代条件、推导与证据，避免夸张判断、反复排比和对本书自身的评价。

## 假设与证据登记表

蓝图末尾的登记表列出各类输入及其证据状态，包括训练计算量、架构演进、动态形状、图执行、平台调度与计费。910C 的双 die 和 AIC／AIV 数量已有论文依据，逐代指令能力变化与设计因果仍需进一步取证；未披露的训练阶段、开发工作量和完整运行轨迹继续列为待核内容。已完成的条件式计算与未知量分开记录。
