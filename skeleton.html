实验与计算

每章三项核心练习，共 39 项；其余就地标为延伸，完整变体保存在扩写资料。核心标记表示阅读选择，星级表示难度。基础活动从手算、小脚本和已有记录分析开始，少量进阶题需要专用设备或模拟。计算、编程和测量按问题搭配，每题都以一次判断结束。

  • 先预测。确定任务和比较的方案，算出最关键的容量、工作量、字节或依赖；没有必要先搭建复杂系统。
  • 再检验。用小程序、原始记录或设备测量检查预测；结果不符时定位遗漏的工作，修正估算。
  • 改变条件。更换 batch、上下文、带宽、期限或请求分布，说明什么时候应该作出不同选择。

例如，先算 4090 的训练状态与通信下界，再决定是否搭建；先算分块能少读多少字节，再写程序；先手画几个事务的时序，再决定有没有必要做事件模拟。仿真只研究简单计算尚不能判断、又确实影响选择的问题。

计算活动约 20–40 分钟，小程序或记录分析约 45–90 分钟，综合研究按内容增加。扩写时配输入、步骤、环境和参考分析，安装准备另计。普通电脑应能完成基础路径；无法使用特定设备时提供标明出处的记录。

性能实验记录质量、计时范围、冷热状态、重复与样本量，区分教学计算、模拟、公开测量和本书实测。具体要求随实验解释。当前设备计划、未公开参数与待采集记录见编辑笔记。

第 1 章

初识 AI Infra

数据搬移塑造了 AI Infra 的架构。 从芯片、网络、执行框架到模型算法，本书沿同一问题展开：计算需要什么数据，数据放在哪里，为什么需要移动，以及怎样降低搬移的代价。本章先建立全景和一个可跟算的设备选择，再用研究经历说明判断怎样形成、怎样修正。

本章判断： 降低搬移代价可以来自减少字节、提高复用、改变位置或安排执行。它同时受到容量、计算、依赖、质量与实现条件约束。所有改进都回到完整任务，检查省下什么、增加什么及新的限制。

前置与交付： 使用基本代数与单位换算；交付一页资源估算、一张执行与状态图和第一份设计决定。第 2 章用真实模型补齐需求，第 3 章再加入请求分布。

阅读安排： 核心为实验 1-3、1-4、1-8，其余为延伸。历史细节与原有推算保存在本章扩写资料，判断沿跨章记录继续修正。

1.3 一次完整的估算与判断修正

1.3.1 从任务条件到可行范围

固定模型、输入输出、质量、并发和期限，再检查每卡 M_weight + M_state + M_workspace ≤ M_available。对每一资源分别数实际工作：计算为 FLOPs/F_precision，HBM 为读写字节除以带宽，通信先以 nα + V/B 估量级。

共享同一接口的流量合并；必须先后完成的工作沿依赖相加。不同资源能够合法并发时，最大资源服务时间提供下界；可达时间还需检查争用和实现。这个组合规则在全书保持一致。

1.3.2 低并发解码的第一遍判断

教学假设为 70B 权重每参数 1 byte、每 decode 步读取一次、可驻留 H100 SXM。仅权重 70 GB / 3.35 TB/s ≈ 20.9 ms；另算计算下界，讨论增加算力、增加带宽、降低位宽和提高复用各可能改善什么。它是历史教学分支，不冒充 Qwen 的实测或完整 token 时间。

由本例引入 Roofline：算术强度 I=FLOPs/V，资源吞吐上界为 min(F_precision,B×I)。随后加入 KV、转换与非矩阵工作，观察新限制。第 2 章换成 Qwen3-8B 的真实配置重新建表，不能将两模型的数字拼成同一测量。

2.3 共享表示与状态压缩

共享 KV 头与压缩潜变量改变保存和读取；展开或吸收式执行会重新分配计算与中间搬移。

2.3.1 KV cache 与历史复用

从不保存历史的逐步生成计算出重复工作，再得到 KV cache。Qwen3-8B 的 BF16 KV 每个历史 token 占 2×36×8×128×2=147456 bytes，即 144 KiB；8192-token 历史占约 1.125 GiB。一次普通全历史 decode 至少需要逻辑上访问这份历史，并新增 144 KiB 状态；是否全部从 HBM 读取、KV 头间能否有效复用，取决于缓存层次与内核路径。

接着区分“存多少”和“累计读多少”：生成 G 个 token 时，历史读取项按 144 KiB×[G×S+G(G−1)/2] 累加，新 token 当步访问与写入另计。batch 无前缀共享时各序列状态相加，理想权重复用则可能由整个批次分摊；不能把状态大小或每 token 的数字直接当成整项任务流量。

2.3.2 MHA、MQA 与 GQA

在相同隐藏维度与上下文下改变 KV 头数，比较状态容量、读取字节与模型质量。共享 KV 头减少状态宽度，但 Q 头仍要完成各自的序列交互，不能直接用缓存缩减倍数代表全部注意力计算缩减倍数。

2.3.3 潜变量压缩与执行路径：K3 MLA

11.4.3 任务质量与思考预算

用“一个模型思考 100 个 token，另一个需要 1,000 个”引出选择。固定任务和质量门槛，比较实际 reasoning token、可见输出、工具调用次数与成功率；区分配置预算、实际用量和预算截断。少思考却经常失败的模型未必经济，隐藏思考不能用可见摘要长度估算。

先做等单价教学算例：输入 10,000 token、可见输出 200 token，输入／生成价格分别为每百万 2／10 美元。实际思考从 1,000 减为 100 token，单次费用由 0.032 降为 0.023 美元；思考部分缩为十分之一，总费用并没有缩为十分之一。换模型时重新代入各自 tokenizer、计费项与速率；reasoning 若已含在 output usage 中，不再加一次。

11.4.4 前缀缓存的成本与延迟

安排 10 轮代码 Agent 算例，固定公共前缀，再改变新增上下文、命中比例、轮间间隔和 TTL，算缓存费用的交点。结合最低缓存长度、前缀变化与工作区边界解释命中条件。API 缓存 token 是计费和复用证据，不能直接反推出 KV 在哪级存储或读取多少字节；资源模型回到第 2、9 章。

12.1 完整交互的数据与时间

复用已定义的服务和环境，从输入到可用结果计算 RAW、语音和截图循环。

12.1.1 图片精修与语音服务的输入输出

图片精修需要保留更多原始信息用于后期调整，因此输入可能是几十 MB 的 RAW，成片回传又有数 MB。背景在这里一笔带过，随即标出上传、云端处理与下载的字节和时间；具体文件大小由输入记录提供。

ASR 则上传一段音频并等待识别结果，TTS 提交文本后等待首段及后续音频。用 Queqiao 中约 355 KB 的 ASR 请求、约 30 ms 的模型处理与约 200 ms RTT，先判断等的是计算、发送还是反馈；TTS 另算首段积累和持续播放，不能只报模型速度。

12.1.2 图片精修的传输与计算

先用明确标注的教学条件计算：30 MB 输入、5 MB 成片、上行 20 Mbit/s、下行 100 Mbit/s、RTT 100 ms、云端处理 0.3 s。连接已可用且服务收齐原图再处理时，上传与下载的串行发送时间分别约 12 s、0.4 s；单次请求的简化时间预算约 12.8 s，另加排队、协议与未计入的本地处理。上行瓶颈下，把模型处理从 0.3 s 降到 0.03 s，只省下约 0.27 s。

随后改变上行速度、无损压缩的实得比例与编解码开销、分块能力和输出质量，比较减少字节、提前处理与增加算力的收益。先返回预览与完整精修成片分别计时；只有模型依赖允许时，才把上传与分块处理重叠，不能把预览提前等同于成片完成。

第 13 章

架构协同设计

本章让读者完成一次带有未知量的设计评审：提出减少搬移代价的候选，加入遗漏约束，允许结论翻转，再决定是否继续投入。前文的资源模型用于形成可检查的判断；作者案例呈现判断怎样被事实修正。

本章判断： 有吸引力的局部收益需要经过物理可行、完整任务和投入条件三次检验。比较规则、未知量和可变性都属于设计模型；得到修改或放弃方案的结论也能形成有价值的研究。

13.1.1 固定需求与比较自由度

给一项与前文同类但配置未算过的模型服务，固定质量、上下文、到达分布、时限和投入边界。将训练、长期推理与必要工具环境纳入同一生命周期；分别允许改变表示、设备、分工、并行和副本。

13.2 一个方案怎样被遗漏约束推翻

13.2.1 OpenTallas：省去权重读取之后

以作者 OpenTallas 项目解释将不变权重固定到另一种供数结构的动机，再加入仍需读写的 KV、算术与辅助操作。沿同一个分析点比较提高 ROM 带宽、提高 KV 带宽和减少通信，检查哪个改动实际改变时间；不同模型的分析点分别成组。

项目尚无完整目标芯片或系统的硅实测。公开分析中未计价的辅助工作保留为未知量，不能以部分小计推断完整服务速度；模型与脚本一致只能说明内部复算。

13.2.2 从局部 hop 到完整通信跨度

按通信跨度修正记录呈现历史错误：跨区域集合操作曾按一次局部 hop 计价，补入拓扑跨度后可行性判断发生变化。先给修正前输入让读者预测，再揭示被遗漏的路径。

教学输入为 60 层、每层两次不可重叠通信、100 µs token 目标，其中 30% 留给通信。单次仅有 0.25 µs；15 hop、每 hop 100 ns 的传播下界为 1.5 µs，全 token 为 180 µs。需要重新选择拓扑、切分或目标；降低权重读取不能抵消独立的串行路径。

13.2.3 从目标反推实现供给

沿算术供给案例，把 100 µs 反推到单元数、有效效率、面积与供数预算。保留历史版本，不把过去的问题写成当前项目仍未修复的事实。

让读者分别判断功能正确、分析一致、满足性能目标。加入一项此前未估价的算子，检查所有串行工作是否共享同一余量；每项单独通过必要条件，仍需验证总预算。

13.4 技术可行之后的投入选择

13.4.1 固定什么、固定多久
