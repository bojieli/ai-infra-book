# 实验 2-4：V4-Flash 的压缩历史与稀疏访问

对应正文 2.4。按 DeepSeek-V4-Flash 的 43 层配置分别算完整／命中前缀后的 prefill、每步 decode 的 FLOPs、权重读取、窗口／压缩历史读取、索引扫描和状态写入；扫描 8K／128K／1M × batch=1／64。

## 独立运行

```bash
python3 run.py    # 现场调用 calculations/calc.py，产物写入 results/
```

只需 Python 3.8+ 标准库。本实验**不另行实现公式**：所有数字由本书统一计算项目的 CLI（`calc.py state` / `v4-forward` / `v4-prefix-continuation`）用官方 inference config 现场生成，产物与调用参数一并存入 `results/`。

## 层构成

window 2 + CSA 21 + HCA 20 = **43 层**（官方 config，不按 Pro 的参数倍数缩放）。

## 结果

**状态扫描**

| 历史 | batch | 窗口 | 压缩历史 | 索引历史 | 常驻合计 | 每步选中载荷 | 索引扫描 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 8,192 | 1 | 5.4 MiB | 43.3 MiB | 10.5 MiB | 0.069 GiB | 17.1 MiB | 10.5 MiB |
| 131,072 | 1 | 5.4 MiB | 692 MiB | 168 MiB | 0.856 GiB | 35.9 MiB | 168 MiB |
| 1,048,576 | 1 | 5.4 MiB | 5,536 MiB | 1,344 MiB | 6.735 GiB | **175.9 MiB** | **1,344 MiB** |
| 8,192 | 64 | 344 MiB | 2,768 MiB | 672 MiB | 4.42 GiB | 1,096 MiB | 672 MiB |
| 1,048,576 | 64 | 344 MiB | 346 GiB | 84 GiB | 431 GiB | 11.0 GiB | 84 GiB |

三条判断：

1. **稀疏访问确实生效**。1M 历史、batch=1 时常驻 6.735 GiB，每步真正读进注意力的选中载荷只有 175.9 MiB——约 2.6%。历史增长 128 倍（8K→1M），选中载荷只增长 10 倍（17.1→175.9 MiB）。这是压缩＋稀疏选择的直接收益。
2. **但索引扫描不稀疏**。为了选出该读哪些块，索引历史必须整段扫过：1M 时 1,344 MiB，是选中载荷的 **7.6 倍**。长上下文下，主导每步读取的不是被选中的历史，而是**为了选择而做的扫描**。这一项在只看“稀疏率”的分析里最容易漏掉。
3. **窗口是定长的**。无论历史 8K 还是 1M，窗口都是 5.4 MiB（batch=1），每步写入固定 44,032 B。随长度增长的是压缩历史和索引，不是窗口。

**前向工作与权重**

| 场景 | 有效注意力 TFLOPs | 含参考稀疏/专家 tile | 统一 BF16 权重 |
| --- | ---: | ---: | ---: |
| 完整 prefill 8192 | 231.1 | 233.3 | 529.6 GiB |
| decode batch=1，历史 8192 | 0.030 | 0.432 | 529.6 GiB |
| decode batch=64，历史 8192 | 1.891 | 18.789 | 529.6 GiB |
| decode batch=1，历史 131072 | 0.043 | 0.445 | 529.6 GiB |

注意两列 FLOPs 的差距：batch=64 decode 的**有效**注意力只有 1.89 TFLOPs，按参考实现的稀疏／专家 tile 计却是 18.79 TFLOPs——差 10 倍。稀疏在数学上省下的工作，实际内核不一定省得下，因为 tile 必须整块算。这一条决定了第 5 章讨论的稀疏内核实现价值。

完整数值与每次 CLI 调用的原始输出见 [results/](results/)。

## 限制

- `uniform_bf16_parameter_bytes`（529.6 GiB）是**统一 2 字节口径**的对照量，不是 V4 实际混合 FP8/FP4 格式的存储；实际 checkpoint 载荷单列为 `base_checkpoint_payload_bytes`。
- 状态口径是所声明的逻辑驻留与选中载荷，不是实际 HBM 流量；运行时转换、预分配与分配器工作区未计入。
- 压缩块完成时的更新峰值在本组场景（历史为块大小整数倍）下为 0，表示这些采样点不落在块边界上，不表示该项不存在。
- MTP、草稿对齐、接受／回滚不在本实验范围内（第 8 章）。
