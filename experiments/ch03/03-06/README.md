# 实验 3-6：各训练阶段的工作量

对应正文 3.3。从前向、反向与状态计数开始，比较预训练、长上下文中期训练与 SFT 三个阶段，逐项指出 `6ND` 漏掉了什么工作，并给出影响预算的范围。

## 独立运行

```bash
python3 run.py    # 现场调用 calculations/calc.py，产物写入 results/
```

只需 Python 3.8+ 标准库。数字由 `calc.py training-matrix|training-nonmatrix|training-state` 与五个 V4 训练子账现场生成，本实验不另行实现公式。

## 三个阶段（Qwen3-8B）

| 阶段 | 计损失 token | 输出头行数 | 训练矩阵 TFLOPs | 其中注意力 | 6ND TFLOPs | 矩阵/6ND |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 预训练（4K 序列） | 4,096 | 4,096 | 200.84 | 14.85 | 201.30 | **0.998** |
| 长上下文中期训练（32K 序列） | 32,768 | 32,768 | 2,437.96 | **950.01** | 1,610.36 | **1.514** |
| SFT（4K 序列，1/4 计损失、compact 头） | 1,024 | 1,024 | 189.37 | 14.85 | 201.30 | **0.941** |

三条判断：

1. **在 4K 预训练上，6ND 几乎是对的**（比值 0.998）。这解释了它为什么被广泛使用。
2. **在 32K 长上下文上，6ND 低估 51%**。原因全在注意力：950.0 of 2,438.0 TFLOPs（39%）来自注意力，而 `6ND` 里根本没有这一项——它只数参数相关的矩阵工作。序列越长，注意力按 L² 增长，6ND 的误差越大。**中期训练的预算不能用 6ND 估。**
3. **SFT 只有输出头能省**（比值 0.941，省 6%）。前向与反向的主干工作与预训练完全相同——不计损失的 token 仍要参与前向和注意力。“SFT 便宜”指的是数据量小，不是每 token 便宜。

## 6ND 之外还漏掉什么（Qwen3-8B 单步）

| 项目 | 数值 |
| --- | ---: |
| 前向标量 FLOPs | 0.566 GFLOPs |
| 反向标量 FLOPs | 1.095 GFLOPs |
| **优化器标量 FLOPs** | **114.670 GFLOPs** |
| 前向末保存的非线性中间量 | 0.972 GiB |
| 参数状态（未切分，16 B/参数） | 137.308 GiB |

优化器更新的标量工作（114.7 GFLOPs）是前向＋反向标量工作的 69 倍，它与序列长度无关、只与参数量有关——batch 越小、步数越多，它占的比例越高。特殊函数原语单独计数（sqrt 8.19×10⁹、sigmoid 5.66×10⁷、exp 2.90×10⁷ 等），不折算成矩阵吞吐。

参数状态 137.3 GiB 是**未切分**口径：这是训练与推理最大的差别，推理只要 15.3 GiB 权重。

## V4-Flash 的训练子账

V4-Flash 没有统一的训练适配器（会拒绝而不是套 Dense 公式）。本实验改用官方源码派生的五个子账：注意力、MoE、压缩器、mHC 与训练原语。它们**不是完整训练步**，相加也不构成完整 FLOPs——每个子账的覆盖范围在其 `coverage` 字段里声明。
