# RedFuser固定生成源码的实际TileLang复核

本目录直接运行书中归档的两份作者生成源码，**未修改生成核**：quant-generated.txt→generated.py、attention-generated.txt→attention_generated.py。上游固定提交为`56bf0b28c569fe160fd0a53a87a9d7f113852940`；来源、文件哈希及版本见sources.json。这里只执行既有生成结果，不声称运行了RedFuser自动推导pass，也不复现论文A10/H800性能排名。

RTX PRO 6000，Torch2.10.0+cu128、TileLang0.1.8。显式使用现有 CUDA12.8 工具链，environment.json 记录 nvcc12.8.93；cuda128.log 记录成功编译与执行。生成 CUDA 代码、实际 CUDA trace 和全部输出均已保存。

## 前缀FP8量化

保持作者原始4096×4096形状，所有行使用相同输入，W每行只给选定位置权重1，W_scale全部为1。原顺序A第0项1、第128项10，W选择第0项；交换块后两值及对应权重一同交换，数学输入配对不变。

| 输入安排 | 作者生成核FP16输出 | 全行尺度参考 | 不同元素 |
|---|---:|---:|---:|
| 原块顺序 | 1 | 0.98193359375 | 16,777,216 |
| 交换块顺序 | 0.98193359375 | 0.98193359375 | 0 |
| 全零输入 | 全部NaN | 0 | 16,777,216 |

全行参考使用原生CUDA FP8 cast，随后按实际稀疏权重取相应项，未重复实现教学舍入模拟。交换块影响输出是实际后端结果，不能作为保持整行量化语义的等价优化。全零行暴露该固定源码的零尺度边界；未将其改好后覆盖失败。

论文配套测试的atol=.1会容纳本例约.018的差异，因此“通过其宽松误差断言”不能替代逐位或较严格合同。这一说明基于现有归档测试源码，不宣称作者对全零输入做过测试。保存的首次调用墙钟包含初始化且没有充分重复，只作运行记录，不制作速度排名。

## 注意力跨块状态

保持作者原始[128,16,512,64]形状，所有query只在首维取8，以抵消源码1/sqrt(64)缩放；key的首维在位置0、1、64分别取FP16表示的0、ln2、ln4，其他位置取-100，对应value分别1、3、-2，其余0。另一次交换前两个64宽块及其value。

参考使用**实际FP16输入**的FP64稳定softmax，值为-0.14311696936873675；它与理想实数输入的-1/7不同，不混用。

| 块顺序 | 实际FP16输出 | 与FP64参考绝对差 |
|---|---:|---:|
| 原顺序 | -0.14306640625 | 约0.00005056 |
| 交换两块 | -0.1429443359375 | 约0.00017263 |

全部输出有限且通过atol=.001/rtol=.01检查；两种顺序相差一个FP16 ULP，说明数学状态可合并不等于实际浮点归约顺序无关。没有加入原源码不支持的causal/mask接口，未测试所有掩码或数值范围。完整输出经过gzip无损压缩，离线逐字节SHA和全部元素复核；不是只检查抽样位置。

## 复现

本目录独立运行，要求TileLang、Torch及支持目标GPU的CUDA工具链：

```sh
CUDA_HOME=/usr/local/cuda-12.8 PATH=/usr/local/cuda-12.8/bin:$PATH python3 run.py --output results/new-quant
CUDA_HOME=/usr/local/cuda-12.8 PATH=/usr/local/cuda-12.8/bin:$PATH python3 attention_run.py --output results/new-attention
python3 verify.py
```

离线verify读取封存的cuda128/attention，需Torch，不需GPU。量化输出原始PT在远端保留，本地保存其gzip副本；可用Python gzip或gzip -k无损解压，自产可信PT使用weights_only=True加载。manifest.json封存源码、日志、原始报告与全部压缩输出。

这组证据完成了5-4所要求的指定生成源码/真实后端数值复核。严格数值等价在量化原顺序和零输入中不成立，因此没有继续把该前缀方案画成合法优化的速度收益。RedFuser生成器支持域、更多随机输入及同合同的完整量化GEMM性能仍属于扩展待办；全书最终跨session增补复核尚未进行。
