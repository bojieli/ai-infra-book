# 实验 7-10：网络优化的模型级收益

对应正文 7.6 的核心练习。通信快了，训练或推理到底快多少？把集合通信曲线代入本章的训练与跨服务器推理候选，比较分层通信、重叠、慢链路和故障退化，分别报告训练步时与推理延迟。

## 独立运行

```bash
python3 run.py    # 读取 ../07-03/rows.csv 的公开曲线，调用 calc.py forward，写出 results/
```

只需 Python 3.8+ 标准库。集合通信时间取自[实验 7-3](../07-03/README.md) 已解析的**公开 NCCL AllReduce 记录**（80 个可用实测点、294 项校验通过），不是本实验新测的曲线。模型工作量由 `calc.py forward` 现场生成。

本目录另有一份**本地实测**：[rank-readiness/](rank-readiness/README.md)，四个真实 CPU 进程的 Gloo `all_reduce`，195 组、780 个 rank 结果逐元素正确，给出 rank 就绪偏差如何进入集合通信完成时间。

## 三条判断

1. **模型级收益远小于通信项的改善幅度**。分层通信把训练的通信时间砍掉一半（68.67→34.37 ms），训练步时只快 **7.2%**；推理 prefill 更少，只有 **4.7%**。原因是通信在总时间里只占 14%（训练）和 11%（推理 prefill）。**Amdahl 在这里是硬约束**——这也是实验 5-9 在内核层面得到的同一结论（热点只占 1.597%，替换后端到端不变）。
2. **重叠比减少字节更有效**。同样的基线，重叠 80% 让训练快 11.6%、推理快 8.8%，都优于分层通信。因为重叠不改变通信量，只把它藏进计算——**只要计算足够长，藏得下**。这也解释了为什么真实框架把重叠放在优先级最高的位置。
3. **退化的代价大于优化的收益**。慢链路（×3）让训练慢 29.0%，故障退化（×2）慢 14.5%；而最好的优化只快 11.6%。**网络工作的主要价值在于避免退化，而不是在健康状态下再挤出几个百分点**——这正是第 7 章开头那句判断（"网络设计降低的是完整协作的代价"）的量化形式。

decode 一侧的通信占比更低（消息只有 0.5 MiB 级）：基线 30.13 ms 中通信只占 2.53 ms（8.4%），分层通信只快 2.8%、重叠快 6.7%，而慢链路仍让它慢 16.8%——同样是“避免退化 > 追加优化”。完整数值见 [results/model-level.md](results/model-level.md)。

## 限制

- 公开曲线来自两台／四台 HGX H100 的 AllReduce 记录，**不能代表 AllGather、ReduceScatter、专家交换或多 NIC 中继**（实验 7-3 已明确这一边界）。
- 重叠比例（80%）、慢链路倍数（×3）与故障退化倍数（×2）是声明输入，不是实测退化幅度。
- 训练步的前反向按 1:2 计，梯度 all-reduce 载荷按 BF16 参数量；不含优化器状态通信与流水气泡（第 10 章）。
- 计算与访存取资源下界，不含真实 MFU；因此“通信占比”是乐观下界，实际占比更低。
