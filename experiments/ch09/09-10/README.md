# 实验 9-10：异构推理的完整部署

对应正文 9.6 的核心练习。综合 PD 分离、AF 分离与共享 KV 池三项案例，按 Chat、Agentic、Real-time 请求选择硬件、切分和路由；先列可恢复状态与交接条件，再算服务目标与成本，最后说明哪些组合值得进一步实测。

## 本目录的四组记录

- [startup/](startup/README.md)：SGLang ＋ HiCacheFile 的 **8 次实际启动、64 个请求**输出全部核验；就绪、首响应与客户端积压排空分列。完整目录 256 次成功 get，但**首个完成的 cached 为 0**，`wait_complete` 配置核对一致——JIT 未逐组 hash、原因未定位，因此不作为缓存加速证据。三入口 × 1/8 请求两轮共 54 个输出全部精确匹配。另保留 TIME_WAIT 失败批的 8 个请求作为负例。
- [cache-mechanism/](cache-mechanism/README.md)：缓存机制的核对记录。
- [native-storage-observation/](native-storage-observation/README.md)：原生存储路径观察。
- [branch-observation/](branch-observation/README.md)：分支行为观察。

## 综合设计的当前结论

三类请求的选择依据来自本章前面的实验，本目录负责验证"能不能真的起来"：

| 请求类型 | 主要约束 | 依据 | 建议组合 |
| --- | --- | --- | --- |
| Chat（短输入短输出、多轮） | 前缀命中率 | 实验 9-1（省 52.9% prefill）、8-4（命中按精确前缀） | 缓存亲和路由 ＋ 共置；不做 PD |
| Agentic（长输入、工具往返） | 历史读取与重算 | 实验 9-7（共享池对模板稳定性敏感）、9-9（亲和提高命中但不保证延迟） | 共享 KV 池 ＋ 亲和路由，模板必须冻结 |
| Real-time（低延迟、短输出） | 首 token 与逐 token | 实验 9-2（异构 PD 短输出 2.50×）、9-4（输出越长 PD 越有利） | 异构 PD；输出长时退回共置 |

## 哪些组合值得进一步实测

按本目录暴露的缺口排序：

1. **PD connector 的真实系统 trace 与时段尾延迟**（实验 9-2 只有稳态上界）；
2. **跨主机的共享 KV 池**（实验 9-7 只做了同 GPU 双引擎）；
3. **动态并行切换的阈值扫描**（沿用第 6 章四卡输入，记录每步 token 数、补齐、模式与显存峰值）；
4. **图模式与故障范围**下的启动与恢复。

这四项都不是计算能回答的问题，必须在受支持的固定版本上实跑。

## 限制

- 本目录只验证启动、输出一致性与缓存字段核对，**不是端到端性能基准**。
- 首完成 cached 为 0 的原因未定位，因此不能把 HiCacheFile 的存在当作加速证据。
- 综合设计表的依据来自本章其它实验，其各自的限制同样适用。
