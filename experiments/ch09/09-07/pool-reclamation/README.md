# 9-7共享池退出后的实际资源回收

发现此前成功实验的进程已退出，但10个`/dev/shm/lmcache_l1_pool_<pid>`文件仍占用68GiB（73014444032bytes）。创建者PID均能与本任务已封存的监督资源记录对应，创建者已不存在。以root读取全机/proc maps和fd，没有活跃引用，没有无法检查的进程。

最终仅删除这10个确认归属且无引用的池。删除前再次检查创建者不存在、文件不是符号链接、UID1000、单链接，以及device/inode/size/mtime未变化；删除后10路径均不存在。另5个未能由保留证据确认归属的池未动，也未动CUDA小型共享文件或其他CPU/GPU任务。

- 删除前系统MemAvailable：69636161536bytes。
- 删除后系统MemAvailable：142792806400bytes。
- 目标文件实际分配块合计：73014444032bytes；全机可用内存变化还包含同时发生的其他活动，不以两次快照相减推算独占释放量。

`targets.json`保存创建者PID/出生时间/父进程/会话、原监督文件及其SHA；`inspection.json`是独立只读检查，`deleted.json`是执行删除时重新检查及实际结果。原成功实验数据和清单未更改，删除的是已弃用的运行时缓存池，不是原始实验结果。

此前guard的“no leftovers”表示没有残留进程，**不证明持久命名共享内存已释放**。本次未隔离具体退出/析构路径的原因，不把观察扩大为所有LMCache退出都会泄漏。今后同类实验结束后须另核对对应pool文件，不能只检查PID或GPU进程。

维护脚本为本次精确allowlist设计：`sudo python3 -B reclaim.py`只检查，`--delete`才删除。此次文件已不存在，再运行会拒绝，而不是扩大范围或自动搜索删除其他文件。真实检查61978 exit0、回收83008 exit0。所有扫描只输出匹配对象，不记录其他进程命令行。
