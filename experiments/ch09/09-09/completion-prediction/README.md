## 方法与证据

先用[上一轮排队实测](../queue-pressure/README.md)的六组已知记录校准，保留为calibration.jsonl；模型和UTC写入model.json，SHA记录于model.sha256，在新请求前固定。旧结果全部已知，不当作未见测试集。128输出预算也是已知条件的新重复；8/32是新的预算条件。

缓存实例0先预热实际Agent末轮3136-token输入，再运行无关背景文本。实际/get_load确认实例0有请求、实例1空闲后，根据背景已知输出预算8/32/128和已观察提交后时间预测剩余等待，加热目标耗时；与冷实例实测校准时间比较。每个预算两轮，seed910打乱轮内顺序，每组清缓存再预热。决策写入decisions.jsonl后才提交目标请求。共18次实际生成调用，目标均强制1输出token，背景强制预算长度。

线性规则将背景prefill等固定开销一并按长度缩放；这不是精确的调度模型。100ms绝对误差复核阈值在PROTOCOL.md和model.json预定，不根据新结果修改。

## 重现与核验

run.py读取固定绝对模型和专用环境路径，worker-command.json保留完整命令。需要已配置SGLang环境与CUDA13工具链；沿用9-8实际验证的JIT缓存。运行前确认31191/31192空闲，复制本目录到独立工作目录且不含results；使用该专用环境Python执行run.py。脚本拒绝覆盖已有results；仅清理自身新建进程组。正式执行退出0，两worker已结束，gpu-after.txt显示原有四个GPU服务仍在，端口无监听。

离线执行 `python3 analyze.py`：核验实际执行源码哈希、模型SHA、六个预算/轮次组合、事前决策时间、规则重算、背景重叠与输出长度、缓存命中和目标输出，生成summary.json。results保留完整请求响应、负载采样、原生worker日志和执行清理记录，run.log保留启动与完成输出。数据及本目录文件以manifest.json封存。
