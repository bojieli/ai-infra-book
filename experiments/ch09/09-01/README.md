# 实验 9-1：服务分工与缓存的基线

对应正文 9.1。复用第 6、7 章确定的并行方案，给一组 Chat／Agent 请求画完整时序，分别估算共置、阶段分离和缓存复用可能省下的工作与新增流量，选出后续最值得验证的两项。

## 独立运行

```bash
python3 run.py    # 现场调用 calculations/calc.py forward|generate
```

只需 Python 3.8+ 标准库。6 个请求的长度取自实验 2-8 的固定画像量级；链路 25 GB/s 为声明输入。

## 结果

| 请求 | 输入 | 可复用前缀 | 输出 | 完整 prefill | 命中后 prefill | 省下 | KV 快照 | PD 交接 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Chat 轮 3 | 800 | 512 | 32 | 11.30 TF | 4.11 TF | 7.19 TF | 0.110 GiB | 4.72 ms |
| Agent 轮 2 | 3,200 | 2,048 | 128 | 47.48 TF | 17.79 TF | 29.69 TF | 0.439 GiB | 18.87 ms |
| Agent 轮 3 | 4,400 | 3,200 | 128 | 66.84 TF | 19.36 TF | 47.47 TF | 0.604 GiB | 25.95 ms |

**三种组织的收支合计**

| 项目 | 数值 |
| --- | ---: |
| 共置：完整 prefill 工作 | 166.07 TFLOPs |
| 缓存复用：省下的 prefill 工作 | **87.93 TFLOPs（52.9%）** |
| 缓存复用：需要保留／取回的 KV | 0.826 GiB |
| 阶段分离：新增交接字节 | **1.540 GiB** |
| 阶段分离：新增交接时间 | **66.2 ms** |
| 全部 decode 工作 | 8.04 TFLOPs |
| 全部 decode 权重读取 | **6,766.7 GiB** |

三条判断：

1. **缓存复用的收益最大且最直接**。多轮对话里后一轮的输入包含前一轮的全部内容，命中前缀省掉 52.9% 的 prefill 工作，代价只是保留 0.826 GiB 的 KV。**在多轮场景里，缓存是三项中投入产出比最高的一项。**
2. **阶段分离的代价是可见的，收益不在这张表里**。分离新增 1.54 GiB 交接、66.2 ms；它换来的是 prefill 与 decode 可以用不同的设备（实验 9-2 显示异构时能到 2.5×），共置时不需要付这笔钱。**只有确定要异构，分离才值得。**
3. **decode 的权重读取（6,766.7 GiB）比 prefill 的全部矩阵工作（166 TFLOPs）更值得关注**。这一组请求的输出很短（32–128 token），decode 矩阵工作只有 8.04 TFLOPs，却要把权重反复读近 6.8 TB——**这才是这组请求真正的主导成本**，也是第 8 章 batch 与第 9 章池化要解决的问题。

## 后续最值得验证的两项

1. **前缀缓存的实际命中粒度与驻留时间**。本基线把命中当作精确前缀且总是可用；实测（实验 8-4）显示命中按精确 token 前缀判定，首 token 一变就归零，且驻留受容量与淘汰影响。这一项决定 52.9% 的节省能否兑现。
2. **PD 交接在真实链路上的时间与并发影响**。本基线按 25 GB/s 无竞争计；实际链路与在途并发（实验 7-5）以及交接期间两侧的等待（实验 9-4）都会改变这笔账。

完整数值见 [results/baseline.md](results/baseline.md)。

## 限制

- 时序按“每请求独立、无排队”画；真实到达分布与排队见实验 3-2 与 8-9。
- 缓存命中按“前一轮输入全部可复用”假设，是上界。
- 交接按无竞争链路计，未含在途并发限制与两侧等待。
