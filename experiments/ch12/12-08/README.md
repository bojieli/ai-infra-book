# 实验 12-8：跨地域计算与数据费用

对应正文 12.5（进阶）。更便宜的算力值得跨地域搬数据吗？给定多地域任务和数据位置，安排实时与后台工作，扫描传输费用、时限与复用次数。

## 独立运行

```bash
python3 run.py    # 现场调用 calculations/calc.py region-placement，写出 results/region.{json,md}
```

只需 Python 3.8+ 标准库。三种放置**重放同一条固定轨迹**（同一模型 revision、同一 token 序列、同一轮数），质量由构造固定——因此比较的是纯粹的字节与费用，不掺入质量差异。价格、功率上限与交付期是声明输入。

## 硬约束先于价格

|  | far 地域 | near 地域 |
| --- | ---: | ---: |
| 需求 / 上限 kW | 250 / 400 | 250 / 400 |
| 交付期 | 30 周 | 4 周 |

在 4／12／26 周的交付期限下，**far 地域根本不是候选**——不管它的算力多便宜。只有期限放到 30 周及以上，价格比较才开始有意义。**先筛硬约束，再比价格**，这是本实验的第一条。

## 三种放置的等待与盈亏平衡

| 放置 | 往返 199 ms 时的会话等待 | 往返 207 ms 时 |
| --- | ---: | ---: |
| remote_stateless（每次重算） | 5.355 s | 5.451 s |
| remote_warm（保温会话） | 2.992 s | 3.088 s |
| local（本地） | **0.604 s** | 0.604 s |

两个盈亏平衡点：

- **保温时长 121.8 s（0.034 小时）**：低于这个间隔，保温比无状态便宜——它省下的 prefill 值回了占用的内存；超过就不值。
- **出网价格边界 84.17 /GB**，而声明价只有 0.08 /GB。**当前价格离边界差三个数量级**，也就是说在这条轨迹上，出网费用完全不构成把计算搬回本地的理由。

**复用比例扫描**：命中比例只要 ≥0.1，保温放置就更便宜；实测该轨迹的缓存命中比例是 **0.8337**，远在门槛之上。**复用次数是这道题的主导变量**——一次性任务不值得保温，多轮会话几乎总值得。

## 结论

更便宜的算力值不值得跨地域搬数据，取决于三个依次生效的条件：

1. **交付期限**是否容得下远地域的建设周期（本例 30 周 vs 4 周）；
2. **复用比例**是否高到让状态保温划算（门槛 0.1，实测 0.8337）；
3. **出网价格**是否接近边界（本例差三个数量级，不构成约束）。

实时工作受往返时延支配（本地 0.604 s 对远端 2.992–5.451 s），应留在近端；后台工作对时延不敏感，可以搬去便宜的地域——**但前提仍是第 1 条的交付期限**。

## 限制

- 请求与回复字节取自轨迹自身的消息体，不是 token 数乘估计值；会话状态按官方配置的 K/V 几何计。
- 等待中的计算项是矩阵工作量除以声明速率，是**服务时间下界而非时延**；同一轨迹的实测模型时间为 13.156 s、实测总耗时 13.803 s，两者不可互相替代。
- 价格、功率上限与交付期是声明输入，不是任何供应商的报价。
- 三种放置都没有各自单独评测质量；质量由“重放同一轨迹”这一构造保证。
