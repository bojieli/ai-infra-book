# 实验 10-9：Routing Replay 与训练一致性

对应正文 10.5。沿固定 NeMo RL 的 Qwen3-30B-A3B R3 配方或其配套 trace，关闭／开启 replay 比较专家集合不一致率、同权重 logprob 差异、记录容量与阶段时间，再比较相同任务下的训练曲线。

## 本目录的记录

[source-readiness/](source-readiness/README.md)：取得并分析 NVIDIA 官方 R3 验证报告的**四对真实训练 history**，交付 logprob 不一致、训练 reward 和阶段时间图。数据由原作者在其集群运行，本机只做下载、逐步对齐、源码核对与离线分析；**没有在本机重新训练 Qwen3-30B-A3B**，也没有把论文图片数字化。

## 结果

八个已完成 run 各有 step 0…100，共 **808 个原始 history 行**；step 0 只记录 setup、训练指标为 null，因此实际可比较的训练记录是 **800 行、每 run 100 步**。四种配置共用 seed 42，是四种设置的一对一对照，**不能当八个独立随机种子**。

三条观察：

1. **四种设置的日志级 logprob 误差中位数均降低**——replay 确实减少了训练侧与生成侧的数值分歧。
2. **reward 无一致改善**——数值一致性提高没有直接换来任务指标提高。
3. **R3-on 的总步时中位数均略长**——一致性是有成本的。

这三条合起来正是本题要问的：Routing Replay 买到的是"训练与生成看到同一组专家"，代价是步时；它是否值得，取决于不一致本身是否正在损害训练，而这需要更长的曲线来判断。
