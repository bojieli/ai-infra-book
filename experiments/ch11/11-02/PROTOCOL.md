# 四路径及文件系统恢复对照的测量定义

执行前锁定SDK版本、模板ID/build/envd版本、vCPU/内存、区域和日期，保留对应服务返回版本；envd至少0.5.0是当前快照文档前提，不代表本机已有该部署。每路径相同配置、相同程序和工作集，随机重复顺序。

环境内先写唯一文件标记，启动常驻进程：仅内存保留随机nonce及计数器，同时维护一个活动命令流或WebSocket；环境外另有独立事件计数作为“快照不能撤销外部操作”的验证。分别记录：
1. 从模板创建：API返回与首个文件读写/工具完成分开；不能把API返回当全部页就绪。
2. 默认暂停恢复：核对sandbox ID、文件哈希、内存nonce、进程状态与连接是否需要重连；分开暂停、恢复API、重连和首工具完成。
3. 快照派生：原实例继续运行；至少两个新实例核对同初态及派生后的互不影响，sandbox ID必须分别保存。PID相同不证明同一实例，须考虑命名空间。
4. 干净重建：从固定模板重新建，不导入运行时文件/内存；旧marker不应被意外带入。
5. 文件系统仅保存控制组：恢复后文件在、内存进程不应被当作续接，检查重启身份。

对快照后活动连接中断，必须重连后验证首工具；不能仅看进程内状态。故障/拒绝/重试、实际持久化模式都保存；区域灰度行为不当全平台保证。所有缺失测量保留null。没有配置凭据时只做资料核验，不冒充云端运行，也不要求购买服务。容量/成本推算归calculations；本目录不重复实现。
