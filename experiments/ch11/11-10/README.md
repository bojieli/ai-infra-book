## 下一轮 matched-workload 实验设计（未执行）

本节是后续新实验的可执行协议设计；本 worker 不运行任何一步，也不预先批准 GPU/SSH 作业或使用现有服务。先在获授权的新实验空间建立独立配置和记录器；不要在封存旧目录改参数或覆盖结果。

1. **冻结配对输入。** 从锁定的 11-01 静态定义提取初始代码、SPEC、六例 checker 和 system/user 文本，核对上表 SHA。固定模型快照、tokenizer/模板、vLLM/Torch/驱动、解码参数、APC 设置、12 轮终止条件、工具版本及限额，记录主机、CPU 配额、内存、GPU 实际型号及服务配置。每次完整 Agent 运行重建相同初始工作目录；不携带上一次输出。原任务只有一个，不将重复次数说成独立任务数。后续任务集另行预登记并按任务配对。
2. **登记目标和计时。** 在看新结果前填 L、P、δ、B，保存配置 SHA。L 从外部提交计至正确结果可见且所属工具进程回收；另报首次正确结果和全部清理时间。外部提交、准入、引擎 queued/scheduled/first/last、工具排队/launch/ready/call/reply/reap 分别打点，明确每个时钟域，禁止 epoch 和 monotonic 混减。失败、截断、超时和拒绝也保留 terminal 状态、用量、重试祖先及清理结果。
3. **先做可行性预检。** 做 3 对相同配置重复，先验证记录完整性及原六例能否全部通过。所有预检记录保留，单列且不与正式性能样本混合。若仍零合格完成，只报告失败尝试延迟，不进入“成功任务扩容收益”判定。质量改进需另一个明确版本的实验，先冻结新基线，再保持各资源条件下相同的模型/提示/工具策略，不把质量修订当资源干预。
4. **执行单因素配对。** 各候选先登记独立基线/干预：基线 C 核与 C+1 核（固定并发、内存和 GPU）；同 checkpoint 的一个与两个独立 GPU 服务副本（固定单请求解码配置）；基线 M 与增量 ΔM 的内存限制（固定核数和其他池）；API 基线额度与提高额度（只在同一真实 API 服务部署存在时）；按需工具与小预热池（先一类一个就绪 worker，固定预测及 50 ms 提前，显式记录每个 worker 驻留）。C、M、ΔM、额度必须在新环境测量配置后写入协议，不能从本页缺失数据猜值。GPU 副本容量比较需要相同外部请求到达；单任务串行下不要预期额外副本自动加速。资源余量/权限不足时将该臂记为未实施。
5. **控制负载和暖态。** 先分开“单 Agent 延迟”和“固定到达轨迹下吞吐/排队”两个区组。到达轨迹使用同一预保存时间序列、任务顺序和输入哈希；现无生产到达记录时先只做单 Agent 区组，不能将自造突发称真实生产轨迹。正式每臂每区组至少 30 对，固定 seed=1110 随机 AB/BA 次序，按时段配对；这是起始采样计划，不是尾分位精度保证。冷启动和稳定暖态分开测：冷态清理自建环境/模型服务，暖态按同一预登记请求序列预热并记录完成；APC 清理/预填策略两臂一致。收集独占或可量化的背景负载，不能把不同暖态或共享 GPU 争用藏进资源变量。
6. **按瓶颈证据启用相应臂。** 模型请求路径优先补 GPU 服务/争用观测；只有存在相同负载下服务/排队压力时测试服务副本。CPU 臂要求工具排队与 CPU 忙核/节流同窗记录；内存臂要求压力、缺页/换页或内存准入等待；API 臂要求相同服务的 quota/429/准入记录；预热臂要求冷启动处于关键路径并同时记录误预测驻留。无该条件仍可做受控否证，但结论必须限定负载，不据此宣布普遍资源无效。
7. **接受或拒绝。** 每个宣称完成的任务必须原六例全部通过；独立扩展检查另列，失败不得从分母排除。先比较按时且合格比例，再比较到合格完成的时间与资源账；不以“成功样本条件平均”藏失败。接受需同时满足：达到预登记 P/L，基线与干预质量无退化，配对主要效应（单任务延迟或固定到达下合格吞吐，二选一预登记）的 95% 置信区间达到预登记 δ，失败/清理/驻留不违反预登记约束，并由 C65 owner 接入真实计费后验证 B。可用按时间块/任务配对 bootstrap；一次 30 对不足以稳定估尾部时报告不确定并预登记追加批次，不能挑最佳轮或看到显著即停。零成功分母、缺成本或缺资源计量均拒绝采购结论，记录为待验证。

精确重放历史动作可另外隔离工具/启动开销，但不能替代上述完整真实 Agent 对照。若真实 Agent 输出轨迹在两臂变化，仍保留在按提交任务配对的主结果中；阶段差异不能再当“同动作执行”因果效果。只对相同实际工具调用哈希的配对子集做补充机制分析，并说明选择偏差。


只需要 Python 标准库。`analyze.py`不 import 相邻脚本，不使用 subprocess、网络、GPU、SSH 或计算项目入口；只读取锁定原始结果与静态来源，再写本目录的 `records.json`、`summary.json`、`decision.json`、`checks.json`、`manifest.json`。它可独立启动，但不是自带原始数据的单文件包：从脚本目录定位仓库根，缺失相邻证据或 SHA 漂移时失败且不刷新已有结果，不自动更新锁。

检查包括源 SHA 与旧 manifest 交集一致、主会话/工具文件链、模型事件与 token 计数、时钟内顺序、非负 CPU、保存的逐例质量一致性、双槽占用与相同批次工作、预热来源 SHA/144 次结果/进程回收、Collector 事件身份与提交时序。它们检查真实数据约束，不是复刻实现的 tests。CPU 微负载摘要只与已存参考或同载荷保存输出核对，不再做 SHA256 计算任务；本次没有重跑模型生成代码、独立 oracle 或旧分析器。SHA 证明封存字节一致，不能证明原采样器没有系统误差。

`checks.json`记录本机实测 CPU/墙钟/峰 RSS。程序为单线程、零子进程，锁定输入小于 16 MiB、新增总量小于 30 MiB，实测峰 RSS 远低于 2 GiB。Darwin 拒绝 2 GiB 的 RLIMIT_AS，程序明确不声称硬地址空间限额已生效；通过小输入、顺序读取和结束时 RSS 检查控制本次离线分析。Linux 会设置该限额。时间/CPU 的本次工具运行开销是分析开销，不加入原实验轨迹。

共享 `calculations/README.md` 在初次读取后被其他工作更新，本批未修改它；它只作定位背景，旧观察 SHA 和排除理由记于 sources.lock 的 `consulted_unpinned_context`。作为固定计算引用的 retry-paths-book.md/json 仍严格校验，不受该背景 README 的更新替代。

仅交付证据表；不同轨迹及单次失败不足以支持采购收益科学图，不新增图像或相应视觉 QA 声明。`manifest.json`封存本目录全部交付文件（自身除外，避免自引用），并记录 status 文件 SHA；其 sources.lock SHA 锚定全部外部只读依赖。重跑离线分析会更新运行开销及 manifest。没有改正文、inventory、PROGRESS、research、references、旧实验或 calculations；没有联系 owner、派生 worker、git 提交、论文追补或最终跨 session 审计。
