## 干预实际内容

[PROTOCOL.md](PROTOCOL.md)在模型作业前冻结，运行时验证 [run.lock.json](run.lock.json) 的源码/协议哈希；只读来源见 [sources.lock.json](sources.lock.json)。原初始文件、SPEC、六例检查、system/user 和四种工具 schema 均来自封存 11-01。四次第一请求 token IDs 相同。

baseline 原样返回 `returncode/stdout/stderr`。feedback 在六例失败时保留这三个字段，增加独立受限子进程的 `diagnostics_process` 和解析后的 `diagnostics`。诊断只重执行原六例，返回失败例的输入前后、期望、实际值和返回对象/内层对象与入参的身份关系，不提供修复实现。原 stdout 与新增诊断 stdout 都保留，因而有重复文本；更长的上下文也是本干预的一部分，不外推为其他精简诊断格式的结果。

两次 feedback 各提供五轮诊断。初始失败明确显示 `[[3,5],[1,2]]` 调用后变为 `[[1,2],[3,5]]`；嵌套例期望 `[[1,10]]` 而实际 `[[1,3]]`。模型写入后，诊断继续显示输入改变与内层对象别名，但最终文件未进一步修好。完整反例来自实际执行，不是预写答案。新增诊断在单独子进程重执行同一代码，保留其原始 stdout；审计核对与原六例对应的输入、实际值和布尔结果。

两次 feedback 最后一条 `finish` 回答相同，表示仍有测试失败、需要进一步检查。控制器保留原 finish 终止行为，质量门槛独立拒绝此输出。因此“少一轮”来自失败终止分支，不能报告为成功加速。
