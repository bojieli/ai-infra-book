# 实验 4-4：片上缓冲与数据复用

对应正文 4.4 的核心练习。增加一块片上缓冲值不值得？沿同一 Qwen3-8B 上投影矩阵与注意力工作，扫描分块和缓冲，算省下的中转字节与等待，再提高矩阵吞吐观察旧缓冲为何可能不够。

## 独立运行

```bash
python3 run.py    # 现场调用 calculations/calc.py gemm-tiles|attention-tiles，产物写入 results/
```

只需 Python 3.8+ 标准库。全部由统一计算项目按官方 Qwen3-8B 形状现场生成。

## 矩阵侧：同步加载 vs 异步双缓冲

上投影 `[1024,4096]×[4096,12288]`，只读写一次的最低载荷 **128 MiB**：

| 片上容量 | 缓冲策略 | 可行候选 | 最佳块 (m,k,n) | 下一层访问 | 算术强度 |
| ---: | --- | ---: | --- | ---: | ---: |
| 64 KiB | 同步 | 2／4 | 64×32×64 | 3,096 MiB | 31.8 |
| 64 KiB | 异步双缓冲 | 2／4 | 64×32×64 | 3,096 MiB | 31.8 |
| **80 KiB** | **同步** | 3／4 | **128×32×128** | **1,560 MiB** | **63.0** |
| **80 KiB** | **异步双缓冲** | 2／4 | **64×32×64** | **3,096 MiB** | **31.8** |
| 128 KiB | 同步 | 3／4 | 128×32×128 | 1,560 MiB | 63.0 |
| 128 KiB | 异步双缓冲 | 3／4 | 128×32×128 | 1,560 MiB | 63.0 |
| 256 KiB | 两者相同 | 3／4 | 128×32×128 | 1,560 MiB | 63.0 |

**80 KiB 那两行是本实验的答案。** 在固定的片上容量下，异步双缓冲要为“下一块正在搬”额外留一份输入空间，于是最大可行块从 128×128 退到 64×64，下一层访问从 1,560 MiB 涨到 3,096 MiB——**多出来的 1,536 MiB 中转字节，就是异步搬运在这个容量点上的价格**。它买到的是搬运与计算的重叠；值不值得取决于这次重叠能省下的等待是否超过多读一倍的代价。

64 KiB 时两者相同（都只能用 64×64，双缓冲连这个块都放不下更大的），256 KiB 时也相同（容量足够，双缓冲不再挤占）。**代价只出现在容量刚好卡在两档之间的位置**，这正是实际芯片最常处于的位置。

**提高矩阵吞吐后旧缓冲为什么不够**：把矩阵能力翻倍，同一个 128×128 块的计算时间减半，但它仍要从下一层取 1,560 MiB。要让搬运跟上，就得要么把块开得更大（需要更多片上容量），要么增加缓冲级数（又要更多容量）。**收益开始变小的位置就在 80→128 KiB 这一段**：128 KiB 之后，无论同步还是异步，最佳块与中转字节都不再改善（1,560 MiB 一直到 256 KiB 都没变），继续加缓冲买不到复用。

## 注意力侧：同一问题的另一种形状

8192 token、因果、单头：

| 片上容量 | KV 块 | Q 块 | 接口字节 | 行状态更新 |
| ---: | ---: | ---: | ---: | ---: |
| 64 KiB | 1 | 83 | 204.6 MiB | 3.36e7 |
| 64 KiB | 64 | 47 | 360.1 MiB | 5.28e5 |
| 64 KiB | 128 | 25 | 672.8 MiB | 2.66e5 |
| 64 KiB | 256 | — | **放不下** | — |
| 256 KiB | 1 | 334 | **56.9 MiB** | 3.36e7 |
| 256 KiB | 256 | 108 | 162.9 MiB | 1.35e5 |

这里出现了**方向相反的两项**：KV 块越小，接口字节越少（因为 Q 块可以开得更大、Q 重读更少），但行状态更新（在线 Softmax 的缩放与合并）多两个数量级；KV 块越大则反过来。**没有单一最优块**，取决于向量／特殊函数单元与访存哪一项更紧——这与实验 4-1 单 SM 那张表是同一件事的两个视角。

容量的收益在这里很直接：64→256 KiB 使同一 KV 块的接口字节降到 1/3.6（204.6→56.9 MiB），并让 KV 块 256 从放不下变成可行。

完整数值见 [results/buffer.md](results/buffer.md)。

## 限制

- 下一层访问字节是所枚举方案的计数，不是实测 HBM 流量；L2 能服务的重读不应全部记成显存流量（实测对照见实验 5-1 的 GPU 分块补测）。
- 缓冲策略只区分输入缓冲份数（1／2），不含具体的 TMA／异步拷贝指令开销与同步代价。
- 注意力行按单头计；跨头与跨层的并发、寄存器压力和调度不在内。
- 提高矩阵吞吐的影响以“同一块的计算时间减半”推理，没有代入具体设备的实测重叠效率。
