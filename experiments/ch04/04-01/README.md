# 实验 4-1：注意力计算与单元配比

对应正文 4.1 的核心练习。把 Qwen3-8B 的同一注意力计算映射到 NVIDIA、昇腾和 Apple，固定访存条件后**分别只提高矩阵或向量能力**；算完成时间而不是峰值总和，再增大上下文重做。

## 独立运行

```bash
python3 run.py    # 现场调用 calculations/calc.py，产物写入 results/
```

只需 Python 3.8+ 标准库。所有数字由 `calc.py fa4-resource-balance|forward|roofline` 用官方规格与官方 config 现场生成。

## A. 单 SM 内的三项资源（head_dim=128）

| tile | 矩阵周期 | SMEM 周期 | 指数周期 | 下界 | 限制资源 |
| --- | ---: | ---: | ---: | ---: | --- |
| 128×128 基线 | 1,024 | 768 | 1,024 | 1,024 | matrix、exp |
| 128×128 只把矩阵翻倍 | 512 | 768 | 1,024 | **1,024** | **exp** |
| 128×128 矩阵与指数都翻倍 | 512 | 768 | 512 | **768** | **smem** |
| 128×128 三项都翻倍 | 512 | 384 | 512 | 512 | matrix、exp |

**这是本实验最重要的一张表：只把矩阵能力翻倍，下界一点没动**（1,024 周期不变），因为指数（softmax 的向量／特殊函数）立刻接替成为限制。矩阵与指数一起翻倍后，共享内存又接替上来。三项一起翻倍才真正减半。

在 256×128、128×256、256×256 三种 tile 上，这个顺序完全相同——**限制资源的转移不是某个 tile 尺寸的巧合**。第 4 章“增加计算单元的收益取决于供数和非矩阵工作”这句判断，就来自这四行。

## B. 同一注意力工作在各设备上的完成时间

固定访存条件（写一次 KV ＋ 读回一次），只比较完成时间：

| 上下文 | 设备 | 峰值口径 | 计算下界 | 访存下界 | 主导 |
| ---: | --- | --- | ---: | ---: | --- |
| 8,192 | A100 80GB SXM | BF16/FP32 tensor 312 T | 63.44 ms | 1.19 ms | 计算 |
| 8,192 | H100 SXM | BF16/FP32 tensor 989 T | 20.01 ms | 0.72 ms | 计算 |
| 8,192 | B200 SXM | BF16/FP32 tensor 2,250 T | 8.80 ms | 0.30 ms | 计算 |
| 8,192 | RTX PRO 6000 Blackwell WS | BF16/FP32 tensor 504 T | 39.29 ms | 1.35 ms | 计算 |
| 8,192 | 昇腾 950DT（规格上限） | 见下 | — | 0.60 ms | 只能给访存下界 |
| 8,192 | Apple M2 Max | 见下 | — | 6.04 ms | 只能给访存下界 |
| 32,768 | H100 SXM | — | 320.06 ms | 2.89 ms | 计算 |
| 32,768 | B200 SXM | — | 140.74 ms | 1.21 ms | 计算 |
| 32,768 | RTX PRO 6000 | — | 628.56 ms | 5.39 ms | 计算 |

**上下文从 8K 增到 32K，注意力工作涨 16 倍（19.8→316.7 TFLOPs），访存只涨 4 倍。** 注意力按 L² 增长而 KV 按 L 增长，所以长上下文让注意力越来越偏计算。答案因此很明确：**在这条路径上更值得增加的是矩阵吞吐（以及与之配套的向量／特殊函数能力），不是显存带宽**。这与 decode 阶段的结论相反——第 4 章后面的实验会给出那一侧。

两处“只能给访存下界”不是遗漏：

- **Apple M2 Max**：官方未公布该 SoC 的 GPU 矩阵峰值，因此不能算计算下界。
- **昇腾 950PR/950DT**：官方 cube 峰值（BF16 432／486 TFLOPs）的**累加精度标注为 unspecified**，统一计算项目拒绝把它用于精度特定的 Roofline，避免把不同累加格式的数字混在一起比较。

这两条限制本身就是结论的一部分：跨厂商比较受限于公开规格的完整程度，而不只是受限于算法。

完整数值见 [results/attention-units.md](results/attention-units.md)。

## 限制

- 单 SM 部分的周期是三项稳态资源下界，不是完整 kernel 时延；exp 只是 softmax 的一部分，归约、缩放、TMEM 流量、校正与同步都没有被赋零成本。
- 设备部分是 Roofline 下界，假设理想重叠，不是实测。实测的 Mac 与 RTX 对照见实验 4-6。
- 访存条件固定为“写一次 KV ＋ 读回一次”，不含分数张量的物化（8K 时那一项本身就有 1,152 GiB，见结果表最后一节）——那正是 FlashAttention 要消除的部分，在第 5 章处理。
- 矩阵倍数是假设的供给变化，不是其他型号的规格。
