# 实验 4-5：batch 与架构性能

对应正文 4.5 的核心练习。把 batch 变大，会改变芯片比较的结果吗？用 Qwen3-8B 与 DeepSeek-V4-Flash 的真实形状，在四种架构上生成 Roofline，再分别只改变矩阵吞吐、存储带宽和非矩阵能力。

## 独立运行

```bash
python3 run.py    # 现场调用 calculations/calc.py，写出 results/roofline.{json,md,svg}
```

只需 Python 3.8+ 标准库；SVG 自绘，不需要 matplotlib。工作量与设备规格全部由统一计算项目按官方 config 与官方规格现场生成。

## 真实组合下的算术强度与主导资源

| 模型 | 阶段 | batch | 算术强度 | A100 | H100 | B200 | RTX PRO 6000 |
| --- | --- | ---: | ---: | --- | --- | --- | --- |
| Qwen3-8B | prefill | 1 | **7,582** | 计算 428 ms | 计算 135 ms | 计算 59 ms | 计算 265 ms |
| Qwen3-8B | decode | 1 | **1.2** | 访存 8.0 ms | 访存 4.9 ms | 访存 2.0 ms | 访存 9.1 ms |
| Qwen3-8B | decode | 8 | 6.4 | 访存 12.2 ms | 访存 7.4 ms | 访存 3.1 ms | 访存 13.8 ms |
| Qwen3-8B | decode | 64 | 13.8 | 访存 45.4 ms | 访存 27.6 ms | 访存 11.6 ms | 访存 51.6 ms |
| Qwen3-8B | decode | 256 | **15.8** | 访存 159 ms | 访存 96.9 ms | 访存 40.6 ms | 访存 181 ms |
| V4-Flash | prefill | 1 | 406 | 计算 741 ms | 计算 234 ms | 计算 103 ms | 计算 459 ms |
| V4-Flash | decode | 64 | 3.3 | 访存 279 ms | 访存 170 ms | 访存 71 ms | 访存 317 ms |

H100 的脊点是 **295 FLOPs/byte**。prefill 的算术强度 7,582 远在脊点右侧（计算受限），decode 即使 batch 到 256 也只有 15.8，仍在脊点左侧 19 倍处（访存受限）。

**答案：把 batch 变大不会改变芯片比较的结果——至少在这个范围内不会。** batch 从 1 到 256，算术强度只从 1.2 涨到 15.8（13 倍），远不足以跨过脊点。原因是 Qwen3-8B 的 KV 也随 batch 线性增长，权重复用带来的强度提升被历史读取抵消了大半（1→8 时涨 5.3 倍，64→256 时只涨 1.15 倍，**边际收益迅速衰减**）。四种架构在所有 decode 场景下的排序完全一致，且都由带宽决定。

## 单因子改动（H100）

| 模型 | 阶段 | batch | 真实组合 | 矩阵吞吐减半 | 存储带宽减半 |
| --- | --- | ---: | ---: | ---: | ---: |
| Qwen3-8B | prefill | 1 | 135.0 ms | **270.1 ms** | 135.0 ms |
| Qwen3-8B | decode | 64 | 27.6 ms | 27.6 ms | **55.2 ms** |
| V4-Flash | prefill | 1 | 233.6 ms | **467.2 ms** | 339.6 ms |
| V4-Flash | decode | 64 | 171.2 ms | 171.2 ms | **342.3 ms** |

干净的二分：**prefill 只对矩阵吞吐敏感，decode 只对存储带宽敏感**，两者在本组条件下互不影响。V4-Flash 的 prefill 是唯一的例外——把带宽减半也让它从 233.6 涨到 339.6 ms，因为它的算术强度 406 只略高于脊点 295，离边界很近。

**哪项演进解决了当前瓶颈**：A100→H100→B200 的矩阵吞吐是 312→989→2,250 TFLOPs（7.2×），带宽是 2,039→3,350→8,000 GB/s（3.9×）。矩阵吞吐涨得更多，因此这几代主要改善的是 **prefill**；decode 的改善幅度只有带宽那一份。这与第 8、9 章 PD 分离的动机直接相连——两个阶段要的不是同一种资源，各代硬件对它们的改善速度也不同。

## 非矩阵工作

| 模型 | 阶段 | batch | 标量 GFLOPs | 特殊函数原语次数 |
| --- | --- | ---: | ---: | ---: |
| Qwen3-8B | prefill | 1 | 191.9 | 1.63e11 |
| V4-Flash | prefill | 1 | **5,410.7** | **7.22e10** |
| Qwen3-8B | decode | 256 | 10.8 | 7.50e9 |

V4-Flash 的 prefill 标量工作是 Qwen3-8B 的 **28 倍**——压缩、量化编解码、索引 top-k 与门控都在这一栏。Roofline 的两条边（矩阵与带宽）都解释不了这一项：它需要第三种能力。这也是实验 4-1 里“只把矩阵能力翻倍，指数立刻接替成为限制”在模型级的对应现象。**标量与特殊函数原语单列，不折算成矩阵吞吐。**

## 限制

- Roofline 是资源下界，假设理想重叠；不是实测吞吐，也不含 kernel 启动、调度与并发争用。
- 统一计算项目把 `compute-efficiency`／`bandwidth-efficiency` 定义为**效率**（不得超过 1），因此单因子改动用“减半”表达；与“另一项翻倍”在比值上等价。
- V4-Flash 的访存口径为统一 BF16 权重载荷 ＋ 该场景的状态驻留，不是实际混合量化格式下的 HBM 流量。
- 昇腾与 Apple 未列入：前者官方 cube 峰值的累加精度为 unspecified，后者未公布 GPU 矩阵峰值（见实验 4-1）。
