# 13-1：用真实质量记录审阅三份半成品设计

这是事后证据评审，使用第8章已有原始记录，没有新跑模型，也不伪装成事前预测。三份候选由本书构造，遗漏陈述是教学材料，不是原实验作者的结论。容量、通信、关键路径与费用复算继续由C72负责，本目录只补设计评审与真实质量证据。

## 一页决定

**需求。** 固定Qwen3-8B同一revision、BF16权重和Triton attention，回答给定文档中的三个键值；必须自然结束、严格JSON且三个值全部正确。保留八个不同任务以及串行／四并发、两轮重复的全部32条正式自然生成记录。质量门槛是这些指定请求全部通过，不将重复当32个独立任务。最短有效完成时间应包含发现错误与修正；原记录没有修正运行，所以这一时间和费用均未知。这里不添加假定生产SLO或宣称容量已经合格。

|半成品候选|遗漏的约束或路径|原始记录重新评分|评审决定|
|---|---|---|---|
|A：BF16 KV，本地常规执行；“基线即正确参考”|基线仍会答错，完成响应不等于完成有效任务|28/32；长文档r0在两种并发、两轮均错|保留，作为后续错误定位与修正的基线|
|B：FP8 KV；“块数翻倍，所以同质量容量翻倍”|精度路径与质量未闭合；分配块数不等于可接纳有效并发|26/32；长文档四并发两任务均错|暂停容量扩张建议，先检查失败机制|
|C：FP8 KV、Q恢复BF16；“回到28分即与A等价”|同分掩盖失败身份变化，额外观察也改变计时路径|28/32；失败集中于r1，与A的失败集合不同|保留为区分Q路径影响的机制对照|

**选择。** 继续验证A和C，三项均不批准部署。选择C不是证明它优于B，而是它只改变Q路径，适合检验质量变化是否由该路径参与造成；A提供原生BF16参照。两者同为28/32，逐请求失败集合却不相同，因此不能把质量视为匹配，更不能按其原始响应耗时计算同质量加速比。

**状态与遗漏。** 三路径均是输入→同模型→attention的Q/K/V处理→KV池→逐步生成→JSON验收。B/C中的FP8 KV校准与读取、C的Q恢复必须进入路径；“校验失败→纠正→重新验收”在所有候选中尚未测量。实测三者KV底层存储都为12,884,115,456 bytes，格式改变的是同预算可分配的块数；这不能证明整个进程内存减半，也没有证明真实吞吐或并发翻倍。没有跨设备状态共享或专用硬件实测。

**最强反例。** 若新的冻结任务上C相对A增加错误或错误身份继续漂移，即使总分接近，也应撤回同质量候选的判断。反过来，若B在独立任务、匹配质量和实际容量压力下通过，当前暂停B不应成为永久排除。

**最小补测。** 先冻结不用于校准的新任务及逐任务门槛；对A/C交错运行，控制输入、采样、引擎、负载与观察开销，记录失败身份及正常结束。再运行同一有界纠正策略，将验证、反馈和重试计入有效完成时间；只有通过质量门槛后才测容量压力与排队，B可按相同门槛重入。这个提案尚未执行，不能借用旧记录填入新结果。

## 独立复核

运行 `python3 review.py`。仅使用标准库，在本目录从15个复制原始文件重建结果，不依赖其他实验代码或模型。`source-bindings.json`保存来源、大小与SHA；`source/`保留完整输入、响应、批次、环境与KV快照。脚本逐文档重新解析期待值，拒绝重复JSON键，区分自然生成与强制长度／预热，按原批次重新选择32条记录。

`review-results.json`保留逐请求评分、耗时和错误身份，未观测的费用、有效纠正时间和生产容量为null。它是当前教学决定的可检查证据，不替代原8-8的完整数值分析或C72模型。本题更广的三种系统架构及全生命周期比较仍需各自证据；这里完成的是三种表示路径的审阅变体。
