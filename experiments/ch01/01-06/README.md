# 实验 1-6：网络处理的 CPU 预算（配套延伸）

对应正文 1.4.2。按作者博士论文的简单转发基线复算 CPU 核数，再加入封装、包长分布和负载率，给出主机与网卡的分工建议。

## 独立运行

只需 Python 3.8+ 标准库：

```bash
python3 run.py    # 写出 results/nic-budget.json 与 .md
```

## 基线

作者博士论文 §4.2.1：**40 Gbps 链路约 60 Mpps；简单转发的单核处理能力约 10–20 Mpps**。原件见 [bojieli-phd-thesis.pdf](../../../references/files/papers/bojieli-phd-thesis.pdf)。

线上占用按以太网帧（含 FCS）＋ 8 字节前导/SFD ＋ 12 字节帧间隙计。包长分布按**包数**加权，不是按字节加权。

## 结果

| 场景 | 平均线上占用 | 包率 | 10 Mpps/核 | 20 Mpps/核 |
| --- | ---: | ---: | ---: | ---: |
| 论文基线：全 64 B 最小帧，满线速 | 84.0 B | 59.52 Mpps | 6 核 | 3 核 |
| 加 VXLAN 封装（+50 B 线上） | 134.0 B | 37.31 Mpps | 4 核 | 2 核 |
| IMIX 包长分布（按包数 7:4:1） | 380.5 B | 13.14 Mpps | 2 核 | 1 核 |
| IMIX + 链路负载率 50% | 380.5 B | 6.57 Mpps | 1 核 | 1 核 |
| 全 64 B + 链路负载率 50% | 84.0 B | 29.76 Mpps | 3 核 | 2 核 |
| 全 64 B，每包工作量 ×2（封装+隔离） | 84.0 B | 59.52 Mpps | 12 核 | 6 核 |
| 全 64 B，CPU 目标利用率 70% | 84.0 B | 59.52 Mpps | 9 核 | 5 核 |
| 卸载后主机只留 10% 包处理 | 84.0 B | 59.52 Mpps | 1 核 | 1 核 |

复算基线：40 Gb/s ÷ 8 ÷ 84 B = **59.52 Mpps**，与论文记的“约 60 Mpps”一致。

四点判断：

1. **满线速最小帧是最坏情况**，只做简单转发就要 3–6 核。这还没算封装、隔离和策略。
2. **封装先降包率再升每包工作量**。加 50 B 线上字节后包率降到 37.3 Mpps，但每包多做封装/解封装，核数不会同比下降——两个方向要分开算。
3. **真实包长分布把包率降一个量级**。IMIX 下只有 13.1 Mpps，1–2 核即可。按最小帧配核会大幅过配；按 IMIX 配核则在遭遇小包攻击或特定负载时不够。**这两个数字都要留着。**
4. **留余量本身就是容量**。CPU 目标利用率从 100% 降到 70%，最小帧场景的核数从 6/3 涨到 9/5。

## 分工建议

把**与包数成正比、逻辑固定**的工作放到网卡：校验、封装/解封装、转发查表、限速。把**与连接状态、策略和应用语义相关**的工作留在主机。主机只保留 10% 包处理时，最小帧场景从 6 核降到 1 核以内。

但卸载不改变总线约束：即使主机包处理归零，每包仍要过 PCIe，在途事务数仍受限。这一项在第 7 章单独核算（实验 7-5），本实验不含。

完整数值见 [results/nic-budget.md](results/nic-budget.md)。

## 限制

- 10–20 Mpps/核是历史论文里“简单转发”的服务能力，不是现代 CPU 基准，也不是完整虚拟化的实测。
- 每包工作量倍数、目标利用率与主机保留比例都是声明的对照输入，不是测量值。
- 多核线性扩展是假设。忙碌核秒与分配的整核数不是同一个量，结果文件里两者分列。
- 本实验只算主机包处理的核预算。网卡自身处理能力、PCIe 带宽与在途事务、成本和 SLO 都不在内。
