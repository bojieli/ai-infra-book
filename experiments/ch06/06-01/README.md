# 实验 6-1：模型与硬件的资源收支

对应正文 6.1。对三个模型在同一组八卡资源上，固定一组 prefill／decode 输入，逐候选给出逐卡容量、每 token 的计算与权重／KV 读取、每层通信，再判断该候选**首先**受哪一项限制。

## 独立运行

```bash
python3 run.py    # 现场调用 calculations/calc.py forward|v4-forward|ring-collective
```

只需 Python 3.8+ 标准库。逐卡 80 GB／3.35 TB/s／989.4 TFLOPs；scale-up 单向 450 GB/s、启动 3 μs 为声明输入。

## 结果（节选）

| 场景 | 方案 | 逐卡驻留 | 容量 | 算力 | 内存带宽 | 互联 | 首先受限于 |
| --- | --- | ---: | :---: | ---: | ---: | ---: | --- |
| Qwen3-8B prefill 8192 | TP=1 副本×8 | 17.6 GB | 通过 | 135.03 ms | 4.90 ms | — | **算力** |
| Qwen3-8B prefill 8192 | TP=8 | 2.2 GB | 通过 | 16.88 ms | 0.61 ms | 21.81 ms | **互联** |
| Qwen3-8B decode b64 h8192 | TP=1 副本×8 | 93.7 GB | **不通过** | 1.29 ms | 27.60 ms | — | **容量** |
| Qwen3-8B decode b64 h8192 | TP=8 | 11.7 GB | 通过 | 0.16 ms | 3.45 ms | 3.17 ms | **内存带宽** |
| Qwen3-235B prefill 8192 | TP=4 | 117.9 GB | **不通过** | 112.83 ms | 35.12 ms | 17.40 ms | **容量** |
| Qwen3-235B prefill 8192 | TP=8 | 59.0 GB | 通过 | 56.41 ms | 17.56 ms | 21.81 ms | **算力** |
| V4-Flash decode b64 h8192 | TP=8 | 71.7 GB | 通过 | 0.24 ms | 21.40 ms | 3.17 ms | **内存带宽** |

四条判断：

1. **同一个模型在两个阶段受限于不同资源**。Qwen3-8B 的 prefill 一直是算力受限，decode 在单卡上先受容量限制、切开后转为内存带宽限制。**任何"这个模型受限于 X"的说法都必须指明阶段。**
2. **大模型在低 TP 下全部卡在容量上**。Qwen3-235B 与 V4-Flash 在 TP≤4 时逐卡驻留都超过 80 GB，根本进不了时间比较；只有 TP=8 才进入"算力还是带宽"的讨论。容量是准入条件。
3. **切得越细，交接越贵**。Qwen3-8B prefill 的互联时间随 TP 单调上升（TP=2 时 11.17 ms，TP=8 时 21.81 ms），在 TP=8 处超过算力的 16.88 ms 成为首要限制——**并行度不是越高越好，它有一个由通信决定的上界**。
4. **decode 的互联代价小得多**（0.52–3.17 ms），因为每次交接的载荷只有几十 KB。这与实验 6-4、6-8 的结论一致：小消息由启动时间决定。

完整 24 行数值见 [results/budget.md](results/budget.md)。

## 限制

- 逐卡驻留按权重与 KV 均分记账，不是可行的切法；真实 TP／PP 的切分粒度与复制份数在实验 6-2、6-3 处理。
- 通信按每层一次环形 all-reduce 的声明模型计，不含拥塞、重叠与集合通信库的算法切换（实验 6-4）。
- V4-Flash 的权重按统一 BF16 口径，不是实际混合量化格式的存储。
- 三项时间取资源下界，假设理想重叠；不是实测。
